# 2026-11-13 · 不再给每个点贴标签：Object-centric Mapping 与 3D Scene Graph 怎样让地图记住“谁是谁”

> 阶段 M · 开放词汇三维语义、场景图与空间智能 ｜ 标签：object-centric mapping, 3D scene graph, instance association, data association, object identity, graph relation, uncertainty, multi-view fusion, open vocabulary, embodied planning
> 主线：逐点 semantic feature 能回答“这里像什么”，却不能稳定回答“这是第几个物体、它和谁有什么关系”；Object-centric Mapping 必须把每帧 observation 与跨帧 persistent identity 分开，经几何—外观—语义联合关联形成 object node，再把带方向、坐标系、置信度和来源的 relation 写成 graph edge，最后用 identity、relation、geometry 与 task 四张成绩单独立验收。

---

## ⏮ 上篇回顾（30 秒）

M1 把二维 image feature 反投影到三维，并用 reliability-weighted fusion 形成可被 text query 的 3D feature。它解决的是：一个空间位置与哪些语言概念相似。

但一个机器人听到“把桌边第二把椅子移到门旁”时，只有逐点 feature 仍不够。它还需要知道：

- 哪些点属于同一个物体；
- 不同视角里的 mask 是否是同一把椅子；
- 椅子与桌、门、房间之间有什么关系；
- 关系来自真实几何、视觉模型，还是语言模型推断；
- 新观测到来后，旧 identity 是延续、分裂、合并，还是已经失效。

今天就把 dense semantic map 升级为 object-centric 3D scene graph。

## 开篇：地图里明明有两把椅子，为什么系统只记住了一个“chair 区域”

设一张开放词汇三维地图中，每个点都有 feature。用文本 `chair` 查询时，两把相邻椅子都亮了；这说明 category retrieval 成功，却没有给出两个 persistent object identity。

若每帧 instance segmentation 稍有变化，系统还可能出现两种相反错误：

- **over-merge**：两把椅子被合成一个 node；
- **over-split**：同一把椅子的正面、靠背和侧面变成三个 node。

一旦 identity 错了，后续关系也会跟着错：`chair-2 left of table` 可能被写到 `chair-1`，物体计数会错，机器人再次看到目标时也无法更新原 node。

所以 object-centric mapping 的第一原则是：

> `observation` 是某一帧看到的局部证据；`object identity` 是系统根据多帧证据维护的假设。两者不能用同一个 ID 偷偷等同。

## 第一层：从 Dense Field 到 Object Node，究竟压缩了什么

逐点地图可写成

$$
\mathcal M_{\text{dense}}
=\{(\mathbf x_p,\mathbf f_p,w_p)\}_{p=1}^{P},
$$

其中：

- $\mathbf x_p\in\mathbb R^3$ 是第 $p$ 个三维点；
- $\mathbf f_p\in\mathbb R^d$ 是语言或视觉 feature；
- $w_p$ 是该 feature 的可靠度；
- $P$ 是地图点数。

Object-centric map 则写成一组 node：

$$
\mathcal V=\{v_j\}_{j=1}^{N},
$$

第 $j$ 个 node 不只存一个 label，而应包含

$$
v_j=(I_j,\mathcal P_j,\mathbf b_j,\mathbf f_j,
p_j(c),\mathbf a_j,t_j,\mathcal S_j).
$$

逐项解释：

- $I_j$：persistent identity；
- $\mathcal P_j$：属于该物体的三维点或 surface support；
- $\mathbf b_j$：3D bounding box / oriented box；
- $\mathbf f_j$：融合后的 appearance / language embedding；
- $p_j(c)$：类别 $c$ 的概率或开放词汇 query 分数；
- $\mathbf a_j$：颜色、材质、大小、状态等 attribute；
- $t_j$：最后观测时间；
- $\mathcal S_j$：支持这个 node 的 frame、mask、pose 与模型来源。

这一步不是免费压缩。它用一个 object hypothesis 取代大量 point feature，因此必须承担三项责任：

1. **partition**：哪些点属于这个 object；
2. **identity**：跨帧是否还是同一个 object；
3. **provenance**：结论由哪些 observation 支持。

若只存最后一个 caption，原始几何与来源全丢掉，图看起来更“聪明”，却更难纠错。

## 第二层：Observation 不是 Identity——先写清在线更新的两个集合

第 $t$ 帧产生 $K_t$ 个 observation instance：

$$
\mathcal O_t=\{o_i^t\}_{i=1}^{K_t}.
$$

每个 observation 可写成

$$
o_i^t=(m_i^t,\mathcal Q_i^t,\mathbf z_i^t,
\mathbf g_i^t,r_i^t),
$$

其中：

- $m_i^t$：二维 mask；
- $\mathcal Q_i^t$：mask 经 depth 与 pose 反投影得到的三维点；
- $\mathbf z_i^t$：appearance / language feature；
- $\mathbf g_i^t$：centroid、box、shape descriptor 等几何量；
- $r_i^t$：该 observation 的可靠度。

地图中已有 $N_{t-1}$ 个 persistent node：

$$
\mathcal V_{t-1}=\{v_j\}_{j=1}^{N_{t-1}}.
$$

在线更新要估计 association matrix

$$
A_{ij}^t\in\{0,1\},
$$

其中 $A_{ij}^t=1$ 表示 observation $o_i^t$ 被分配给 map node $v_j$。还要允许：

- observation 没有匹配，创建新 node；
- map node 本帧不可见，不应删除；
- 一个 mask 可能需要 split；
- 两个旧 node 可能经更多证据确认应 merge；
- 动态物体移动后，位置不再是唯一 identity cue。

这就是 data association，而不是普通分类。

## 第三层：Association Cost 怎样从几何、外观与语义一步步组成

对 observation $i$ 与 node $j$，先定义几种距离。

### 1. 几何重叠距离

若二者有 3D box，可计算

$$
\operatorname{IoU}_{ij}^{3D}
=\frac{|B_i\cap B_j|}{|B_i\cup B_j|}.
$$

把“越大越相似”变成 cost：

$$
d_{ij}^{\text{iou}}=1-\operatorname{IoU}_{ij}^{3D}.
$$

但遮挡只露出椅背时，当前 box 很小，IoU 可能偏低；所以 IoU 不能独自裁决 identity。

### 2. 位置距离

设 observation centroid 为 $\mathbf c_i$，node 预测 centroid 为 $\hat{\mathbf c}_j$，则

$$
d_{ij}^{\text{pos}}
=\frac{\|\mathbf c_i-\hat{\mathbf c}_j\|_2}{\sigma_{ij}}.
$$

$\sigma_{ij}$ 表示 pose、depth 与 object motion 带来的位置 uncertainty。相同的 10 cm 偏差，在高精度静态扫描中可能可疑，在移动机器人远距离观测中却可能正常。

### 3. Feature 距离

将 feature 归一化后，用 cosine distance：

$$
d_{ij}^{\text{feat}}
=1-\frac{(\mathbf z_i)^\top\mathbf f_j}
{\|\mathbf z_i\|_2\|\mathbf f_j\|_2}.
$$

它能帮助被短暂遮挡的物体重新关联，但两把同款椅子的 embedding 可能几乎相同，因此 feature similarity 也不是 identity proof。

### 4. 类别兼容与时间先验

若 node 的类别 posterior 为 $p_j(c)$，observation 的类别分布为 $q_i(c)$，可用

$$
d_{ij}^{\text{sem}}
=-\log\left(\sum_c q_i(c)p_j(c)+\epsilon\right),
$$

其中 $\epsilon>0$ 防止对数零值。再加入 time / motion model cost $d_{ij}^{\text{time}}$。

### 5. 联合 cost 与 gating

完整 cost 可写成

$$
C_{ij}
=\lambda_g d_{ij}^{\text{iou}}
+\lambda_p d_{ij}^{\text{pos}}
+\lambda_f d_{ij}^{\text{feat}}
+\lambda_s d_{ij}^{\text{sem}}
+\lambda_t d_{ij}^{\text{time}}.
$$

权重 $\lambda_*$ 不能只凭感觉设定。若把各项看成条件独立 likelihood 的 negative log，权重就对应不同证据的 noise / calibration；可靠度低的模态应少说话。

还要先做 gating：若几何距离远超 uncertainty、时间上不可能到达，或类别明确冲突，就令 $C_{ij}=+\infty$，不让外观相似把不可能的 pair 拉回来。

## 第四层：为什么逐个 Greedy Match 会制造 Identity Switch

若同一帧有多个 observation，关联不是“每个 observation 各找最近 node”，而是带一对一约束的全局分配：

$$
\min_{A}
\sum_{i=1}^{K_t}\sum_{j=1}^{N_{t-1}}A_{ij}C_{ij},
$$

满足

$$
\sum_j A_{ij}\le 1,
\qquad
\sum_i A_{ij}\le 1.
$$

第一条表示一个 observation 最多匹配一个旧 node；第二条表示同一帧中一个旧 node 最多接收一个 observation。实际系统还会加入 dummy node，表示“新物体”或“未匹配”。

局部最小不保证全局最小：第一个 observation 抢走“稍微更像”的 node，可能迫使第二个 observation 接受极差匹配，最终发生 identity switch。

## 最小可运行代码：Greedy 为什么会抢错 Node

下面用三对 observation / map node 演示。为避免依赖额外优化库，小规模全局解直接枚举 permutation；真实系统可用 Hungarian algorithm 或 min-cost flow。

```python
from itertools import permutations

# 行：当前帧 observation；列：旧 map node；越小越匹配
cost = [
    [0.10, 0.20, 0.90],
    [0.11, 0.80, 0.90],
    [0.90, 0.30, 0.10],
]

def sequential_greedy(matrix):
    available = set(range(len(matrix[0])))
    assignment = []
    total = 0.0
    for row in matrix:
        j = min(available, key=lambda col: row[col])
        assignment.append(j)
        total += row[j]
        available.remove(j)
    return assignment, total

def global_assignment(matrix):
    n = len(matrix)
    best_perm = min(
        permutations(range(n)),
        key=lambda perm: sum(matrix[i][perm[i]] for i in range(n)),
    )
    total = sum(matrix[i][best_perm[i]] for i in range(n))
    return list(best_perm), total

greedy_ids, greedy_cost = sequential_greedy(cost)
global_ids, global_cost = global_assignment(cost)

print("greedy:", greedy_ids, "cost=", round(greedy_cost, 2))
print("global:", global_ids, "cost=", round(global_cost, 2))
```

预期输出：

~~~text
greedy: [0, 1, 2] cost= 1.0
global: [1, 0, 2] cost= 0.41
~~~

第 0 个 observation 若先拿 node 0，只省下 $0.10$；第 1 个 observation 却被迫付出 $0.80$。全局分配让第 0 个 observation 退到 node 1，把真正依赖 node 0 的第 1 个 observation 留给它，总 cost 更小。

但请注意：全局最优只是在**给定 cost model** 下最优。若 pose、mask 或 feature 已错，Hungarian algorithm 不会把错误证据变成真相。

## 第五层：匹配之后，Node 应怎样更新而不丢掉不确定性

假设 observation $i$ 匹配 node $j$。最简单的 feature update 是加权平均：

$$
\mathbf f_j^{\text{new}}
=\frac{W_j\mathbf f_j+r_i\mathbf z_i}{W_j+r_i},
\qquad
W_j^{\text{new}}=W_j+r_i.
$$

几何 support 可以做 union、voxel fusion 或 surface update；类别分布可以用 log-likelihood 累积。但有三条边界：

1. **错误不会因平均自动消失**：同一视角重复十次的偏差不是十份独立证据；
2. **旧证据不能无限压死新状态**：动态环境需要 time decay 或 state change；
3. **保留 provenance**：至少能追到哪些 frame / mask 改变了 node，才有机会撤销错误 merge。

因此 node 最好同时维护：累计量、有效 observation 数、最后更新时间、viewpoint diversity、冲突计数和原始证据索引，而不是只留一个最终向量。

## 第六层：Scene Graph 的 Edge 不只是“两个 Node 连起来”

三维场景图写成

$$
\mathcal G=(\mathcal V,\mathcal E).
$$

一条边可写成

$$
e_{jk}=(I_j,r,I_k,p_{jk}^{(r)},F,\mathcal S_{jk}),
$$

其中：

- $I_j$ 是 subject node；
- $I_k$ 是 object node；
- $r$ 是关系，如 `left_of`、`inside`、`supported_by`；
- $p_{jk}^{(r)}$ 是关系概率；
- $F$ 是判断关系所用坐标系；
- $\mathcal S_{jk}$ 是几何、图像或模型来源。

### 1. 关系有方向

`cup on table` 不等于 `table on cup`。若 $r$ 是 `inside`、`supported_by` 或 `left_of`，subject / object 交换后语义会变。

### 2. 关系依赖坐标系

`left_of` 到底是世界坐标的左、相机画面的左，还是人的朝向左？不写 frame，关系就可能随相机转身而反转。

### 3. 关系不是一律二值

设两个 box 的水平间隔为 $\Delta x$，测量 uncertainty 为 $\sigma$，可用 logistic model 表示

$$
p(\text{left\_of}_{jk})
=\sigma_{\text{logistic}}
\left(-\frac{\Delta x}{\tau}\right),
$$

其中 $\tau$ 控制边界模糊程度。两个物体几乎对齐时，应允许 uncertainty，而不是因为数值差 $1$ mm 就写死一条关系。

### 4. 几何关系与语义关系来源不同

- `above`、`inside` 可主要由 3D geometry 计算；
- `supports` 还需要接触、重力方向和稳定性；
- `used_for`、`belongs_to` 常包含常识推断；
- `dangerous_near` 甚至依赖任务与人的状态。

把 LLM 推断边伪装成直接测量边，会让 graph reasoning 失去证据边界。

## 第七层：Graph Consistency 能抓错，但不能凭空造真

关系之间有结构约束。例如：

- 若 $A$ `left_of` $B$，通常不应同时高置信地写 $B$ `left_of` $A$；
- 若杯子 `inside` 柜子，杯子的几何 support 应与柜子体积兼容；
- 若物体 `supported_by` 桌面，接触位置与重力方向应合理；
- object–room–building hierarchy 不应形成循环包含。

可以把 graph refinement 写成

$$
\hat{\mathcal G}
=\arg\min_{\mathcal G}
\left[
\sum_{e\in\mathcal E}\phi_e(e)
+\lambda\sum_{q\in\mathcal C}\psi_q(\mathcal G)
\right],
$$

其中：

- $\phi_e$ 是单条边与 observation 的不一致代价；
- $\psi_q$ 是违反第 $q$ 条 graph constraint 的代价；
- $\mathcal C$ 是约束集合；
- $\lambda$ 控制 observation evidence 与结构 prior 的权衡。

但 consistency 只会在候选解释之间重新分配可信度。若系统漏看了第三把椅子，或两把椅子从第一步就被错误 merge，漂亮的 graph constraint 也不能恢复未进入图的实体。

## 第八层：怎样评价 Object-centric Map，不让“能问答”替代 Identity 正确

至少要拆成四张成绩单。

### 1. Node / Instance

- 3D instance precision、recall、Panoptic Quality；
- over-split / over-merge rate；
- duplicate node 数；
- small / thin / occluded object subgroup；
- open-vocabulary head / body / tail 分组。

### 2. Identity / Association

- association precision / recall；
- identity switch；
- track fragmentation；
- re-identification after occlusion；
- viewpoint、distance、pose-error subgroup。

### 3. Edge / Relation

- predicate precision、recall、mR@K；
- subject–predicate–object triplet accuracy；
- directional relation 与 symmetric relation 分开；
- relation calibration；
- geometric edge、learned edge、LLM-inferred edge 分来源报告。

### 4. Geometry / Task

- node support 的 surface accuracy / completeness；
- object retrieval 是否找到正确 physical instance；
- navigation / manipulation success；
- absent-object query 是否能说“不知道 / 不存在”；
- task success 是否依赖 oracle pose、oracle object mask 或人工 graph correction。

一句语言问答答对，可能来自语言先验，而不是地图正确；一张 graph 可视化很整齐，也可能漏掉一半物体。必须用 held-out scene、真实 identity 与独立 geometry / task endpoint 把这些路径拆开。

## 🔗 与我 CVPR / 偏振三维工作的连接

### 1. 更好的几何边界可以帮助 Instance Association

偏振若真实改善 normal、surface boundary 或反光区域 geometry，可能减少 feature bleeding，让相邻同类物体更容易分开。但要证明的是：在冻结 detector、pose、association rule 与 observation budget 后，instance / identity 指标是否改善。

### 2. Polarization Feature 不是天然的 Object Identity

DoLP / AoLP 会随 view、material、illumination 和 reflection mode 变化。同一物体跨视角可能差异大，同材质不同物体又可能相似。它更适合作为带 validity 的辅助 cue，而不是硬 identity key。

### 3. Physical Attribute 要保留 Measurement Provenance

若 node 写有 `rough`、`metallic`、`high-DoLP` 等 attribute，应标明来自哪种观测、在哪些 view / illumination 下有效，并与 language-model caption 分开。否则物理测量会被语义猜测污染。

### 4. 公平 Control 应把收益拆开

至少比较：

- RGB geometry + RGB association；
- RGB geometry + RGB/polarization association；
- RGB/polarization geometry + RGB association；
- RGB/polarization geometry + RGB/polarization association。

这样才能判断偏振收益来自 geometry support 更准、association cue 更强，还是两者耦合。

## 🔧 配菜 · 面试考点

### Q1：Semantic mapping 与 object-centric mapping 的区别是什么？

Semantic mapping 主要回答空间位置属于什么概念；object-centric mapping 还必须维护实例边界、persistent identity、跨帧 association、属性和关系，并允许对象更新、消失与重现。

### Q2：为什么 cosine similarity 高不能证明两个 observation 是同一物体？

同类、同款甚至相邻物体可能 feature 极相似；identity 需要几何位置、运动可达性、时间连续性、shape 与 appearance 等联合证据，并报告不确定性。

### Q3：Hungarian assignment 解决了什么，又没解决什么？

它在给定 pairwise cost 和一对一约束下找全局最小分配，避免 greedy 抢占；它不保证 cost model、mask、pose 或 feature 本身正确，也不能直接处理所有 split / merge / birth / death 情况。

### Q4：为什么 scene graph edge 必须带 frame 和 provenance？

`left_of` 等关系依赖参考坐标，`supports` 等关系依赖几何和物理假设；记录 frame 与来源才能判断关系是否可复现、可迁移和可纠错。

### Q5：怎样证明 3D scene graph 对机器人有用？

先验证 node、identity、edge 与 geometry，再在冻结 perception budget、planner 和执行条件下测 object retrieval、navigation 或 manipulation；不能只用 LLM 对 graph 的文本问答作为唯一证据。

## 一张可复用的“Object-centric Mapping 十八问卡”

1. **Observation**：每帧输出的是 mask、point set、box 还是 feature？
2. **Identity**：observation ID 与 persistent object ID 是否明确分开？
3. **Frame**：所有 geometry 在哪个坐标系与 gauge？
4. **Pose**：pose uncertainty 是否进入 association？
5. **Geometry**：IoU、centroid、shape 各自在哪些遮挡下可靠？
6. **Feature**：appearance / language feature 是否 view-sensitive？
7. **Semantics**：category compatibility 是硬门槛还是概率证据？
8. **Time**：静态、可移动与动态 object 是否用不同 motion prior？
9. **Gate**：哪些 pair 在物理上不可能，应提前排除？
10. **Assignment**：是否有一对一、birth、death、split、merge？
11. **Update**：新证据怎样改变 node，旧证据是否会无限累积？
12. **Provenance**：能否追到支持 node / edge 的 frame 与模型？
13. **Relation**：edge 是否有方向、frame、confidence 与来源？
14. **Consistency**：graph constraint 能检查哪些冲突，不能恢复哪些漏检？
15. **Instance**：over-split、over-merge、duplicate 是否单独统计？
16. **Identity**：遮挡后 re-identification 与 identity switch 是否评价？
17. **Task**：graph 是否改善真实 retrieval / navigation / manipulation？
18. **Evidence**：语言问答、几何正确和任务成功是否分开验收？

- [ConceptGraphs: Open-Vocabulary 3D Scene Graphs for Perception and Planning](https://arxiv.org/abs/2309.16650)：用 class-agnostic 2D instance、multi-view association、3D fusion、caption 与 relation inference 构建开放词汇 object graph，并展示 perception / planning 用途。

- [SGAligner — ICCV 2023](https://openaccess.thecvf.com/content/ICCV2023/html/Sarkar_SGAligner_3D_Scene_Alignment_with_Scene_Graphs_ICCV_2023_paper.html)：展示 object、attribute 与 relation 的多模态 graph 怎样用于部分重叠、环境变化下的三维对齐。

## 一句话总结

Object-centric Mapping 不是把 dense point feature 做一次 clustering，而是维护一套可更新、可追溯的实体假设：把每帧 observation 经带 uncertainty 的几何—外观—语义 cost 与全局 data association 接到 persistent node，再把有方向、坐标系、置信度和 provenance 的 relation 写成 scene graph；只有 node、identity、edge、geometry 与 task endpoint 分层通过，地图才真正从“哪里像 chair”升级为“哪一把椅子与谁有什么关系”。
