# 2026-11-16 · 让机器人真正听懂“红椅子旁边的桌子”：Language Grounding 怎样从文本走到三维行动

> 阶段 M · 开放词汇三维语义、场景图与空间智能 ｜ 标签：language grounding, embodied instruction, referring expression, 3D scene graph, spatial relation, affordance, reachability, POMDP, uncertainty, task success
> 主线：Language Grounding 不是把整句文本与整张地图做一次 cosine similarity，而是把 noun、attribute、relation、reference frame、action 与 constraint 分别绑定到可追溯的三维实体和区域；Embodied Instruction 还要把“指的是谁”继续变成 collision-free、reachable、可执行且可验证的 action，并在歧义会改变动作时主动澄清。

---

## ⏮ 上篇回顾（30 秒）

M2 把逐帧 observation 经 data association 接到 persistent object node，再用带方向、坐标系、置信度和 provenance 的 edge 形成 3D scene graph。它解决了“地图里谁是谁、谁和谁有什么关系”。

但 scene graph 还不会自动听懂指令。用户说“把杯子放到红椅子旁边的桌子上”，系统至少要回答：

- “桌子”对应哪个 object node；
- “红椅子”是 anchor，不是最终 target；
- “旁边”在什么 frame、什么距离阈值下成立；
- “桌子上”是一个可放置 surface，不是桌子中心点；
- 机器人能否无碰撞到达、抓取并放下；
- 如果有两张都合理的桌子，应该赌一个，还是先问一句。

今天把这条链从 language 一直接到 physical execution。

## 开篇：相似度最高的桌子，为什么可能恰好是错误目标

假设房间里有三张桌子：

1. 远处一张大木桌，视觉—语言 feature 与 `table` 最像；
2. 红椅子旁边一张小桌，`table` feature 稍弱；
3. 红椅子另一侧还有一张桌，但被隔断挡住，机器人到不了。

若只计算

$$
s_j^{\text{sem}}
=\cos(\mathbf f_j,\mathbf e_{\text{table}}),
$$

其中 $\mathbf f_j$ 是第 $j$ 个 object node 的 feature，$\mathbf e_{\text{table}}$ 是文本 `table` 的 embedding，那么系统会选第 1 张桌。

可原句不是“找最像桌子的东西”，而是“找与某把红椅子满足空间关系、并且支持后续放置动作的桌子”。语义相似度只是一个 unary evidence；relation、frame、reachability 与 affordance 都不能被它替代。

## 第一层：先写清 Grounding 的输出，不要把“理解了”当接口

设自然语言指令为 $u$，三维地图为

$$
\mathcal M=(\mathcal V,\mathcal E,\mathcal F),
$$

其中：

- $\mathcal V=\{v_j\}$ 是 object node 集合；
- $\mathcal E$ 是 object relation；
- $\mathcal F$ 是 free space、surface、obstacle 等连续几何场。

一个可执行 grounding 不应只输出一句改写文本，而应至少输出

$$
g=(z_t,z_a,r,F,G,A,C),
$$

逐项解释：

- $z_t$：target object，例如“桌子”；
- $z_a$：anchor object，例如“红椅子”；
- $r$：二者关系，例如 `near`；
- $F$：关系所在参考坐标系；
- $G\subset\mathbb R^3$：允许机器人或物体到达的 goal region；
- $A=(a_1,\ldots,a_T)$：动作序列；
- $C$：碰撞、可达性、抓取、放置、顺序与安全约束。

这组变量把三种经常被混用的成功拆开：

1. **Referential success**：找对了物体；
2. **Spatial success**：找对了满足关系的区域；
3. **Embodied success**：真实执行后任务成立。

文本回答正确不等于机器人走得到；机器人偶然成功也不证明每个 noun 和 relation 都 ground 对了。

## 第二层：把一句话拆成可绑定的变量

以“把杯子放到红椅子旁边的桌子上”为例，可得到近似结构：

```text
action: place
theme: cup
target: table
anchor: chair
anchor_attribute: red
relation(target, anchor): near
placement_relation(theme, target): on
```

这里最重要的不是某一种 parser，而是 **role**：

- `cup` 是被操作的 theme；
- `table` 是 placement target；
- `chair` 是帮助消歧的 anchor；
- `red` 修饰 chair，而不是 table；
- `near` 约束 table–chair；
- `on` 约束 cup–table surface。

若把 bag-of-words 直接平均成一句 embedding，模型可能知道句子“与桌椅有关”，却丢掉谁修饰谁、谁是 target、谁只是参照物。

因此 compositional grounding 的基本单位不是整句相似度，而是带 role 的 factor。

## 第三层：从 Unary Similarity 到 Joint Grounding Posterior

设候选 target 为 $v_j$，候选 anchor 为 $v_k$。我们希望估计

$$
p(z_t=j,z_a=k\mid u,\mathcal M).
$$

利用 Bayes rule，它正比于 likelihood 与 prior 的乘积：

$$
p(j,k\mid u,\mathcal M)
\propto
p(u\mid j,k,\mathcal M)p(j,k\mid\mathcal M).
$$

为便于解释，把证据拆成四个 factor：

$$
p(j,k\mid u,\mathcal M)
\propto
\phi_t(j)\,\phi_a(k)\,\phi_r(j,k;F)\,\phi_c(j,k).
$$

其中：

- $\phi_t(j)$：候选 $j$ 与 target phrase `table` 的兼容度；
- $\phi_a(k)$：候选 $k$ 与 `red chair` 的类别—属性兼容度；
- $\phi_r(j,k;F)$：在 frame $F$ 下，二者满足 `near` 的概率；
- $\phi_c(j,k)$：可见性、地图时效、可达性等 context evidence。

取对数后，乘法变成加法：

$$
S_{jk}
=\log\phi_t(j)
+\log\phi_a(k)
+\log\phi_r(j,k;F)
+\log\phi_c(j,k).
$$

再用 softmax 得到归一化 posterior：

$$
p_{jk}
=\frac{\exp(S_{jk}/\tau)}
{\sum_{m,n}\exp(S_{mn}/\tau)},
$$

其中 $\tau>0$ 是 temperature。$\tau$ 小时分布更尖，$\tau$ 大时更平；它能做 calibration，却不能把错误地图变正确。

这一步的直觉是：**候选必须同时解释名词、属性、关系和任务上下文**。任何一项接近零，joint posterior 都应下降。

### 一个可解释的 `near` likelihood

设两个 object support 之间的最短三维距离为

$$
d_{jk}=\min_{\mathbf x\in\mathcal P_j,\mathbf y\in\mathcal P_k}
\|\mathbf x-\mathbf y\|_2.
$$

若当前场景中 `near` 的期望距离为 $\mu_r$、容许尺度为 $\sigma_r>0$，可写

$$
\phi_r(j,k)
=\exp\left[-\frac{(d_{jk}-\mu_r)^2}{2\sigma_r^2}\right].
$$

这不是说“near”天然服从 Gaussian，而是把模糊语言显式变成一个可校准、可替换的 relation model。室内导航的“旁边”可能是 0.5 m，仓库叉车语境则可能是数米；$\mu_r,\sigma_r$ 必须由任务和尺度决定。

## 第四层：Reference Frame 错了，`left` 和 `front` 会整句翻转

`near` 大体对旋转不敏感，但 `left_of`、`in_front_of`、`behind` 强烈依赖 frame。常见 frame 有：

- **egocentric frame**：以说话者或机器人朝向为准；
- **object-centric frame**：以物体正面为准；
- **world frame**：以房间或地图轴为准；
- **intrinsic functional frame**：如桌子的“前面”由使用方向决定。

若在 frame $F$ 中，target 与 anchor 中心差为

$$
\Delta\mathbf c_{jk}^{F}
=\mathbf R_{WF}^{\top}(\mathbf c_j^W-\mathbf c_k^W),
$$

其中 $\mathbf c^W$ 是 world-frame 中心，$\mathbf R_{WF}$ 把 frame $F$ 的坐标轴表示到 world frame，那么 `left_of` 可以要求

$$
\Delta c_{x,jk}^{F}< -\delta,
$$

$\delta>0$ 是避免边界抖动的 margin。

如果系统不知道“左边”是按用户视角还是机器人视角，应把 $F$ 也作为 latent variable，而不是悄悄选一个默认值：

$$
p(j,k,F\mid u,\mathcal M)
\propto \phi_t\phi_a\phi_r(j,k;F)\phi_F(F).
$$

当不同 frame 导致不同动作目标时，最安全的输出不是高置信幻觉，而是：“你说的是你视角的左边，还是我的左边？”

## 第五层：Object Grounding 之后，还要生成 Goal Region

即使找对了桌子，机器人也不能把导航 goal 设成桌子中心——那里通常在障碍物内部。

设 target object 占据区域为 $O_t$，机器人 footprint 为 $B$。为了把机器人身体尺寸计入碰撞，可对障碍物做 Minkowski expansion：

$$
O^{+}=O\oplus(-B).
$$

于是 collision-free configuration space 为

$$
\mathcal C_{\text{free}}
=\mathcal C\setminus O^{+}.
$$

若任务要求机器人停在桌边距离区间 $[d_{\min},d_{\max}]$，候选 goal region 可写成

$$
G_0=
\left\{
\mathbf q\in\mathcal C_{
text{free}}:
d_{\min}\le d(\mathbf q,O_t)\le d_{\max}
\right\}.
$$

还要叠加观察与操作约束：

$$
G=G_0
\cap G_{\text{visible}}
\cap G_{\text{reachable}}
\cap G_{\text{safe}}.
$$

- $G_{\text{visible}}$：从该 pose 能看到操作区域；
- $G_{\text{reachable}}$：机械臂 inverse kinematics 有解；
- $G_{\text{safe}}$：满足 clearance、稳定性和人机安全距离。

对 `place cup on table`，还需从桌子 surface support $\mathcal S_t$ 中找 placement region：

$$
P=\{\mathbf x\in\mathcal S_t:
\text{stable}(\mathbf x)\land
\text{clear}(\mathbf x)\land
\text{reachable}(\mathbf x)\}.
$$

语言 ground 到 object 只是中间接口；最终执行需要的是 pose / region 与约束。

## 第六层：Embodied Instruction 是部分可观测的闭环，不是一次性生成动作串

现实机器人不知道所有真实状态。设 $s_t$ 是时刻 $t$ 的真实世界状态，$o_t$ 是传感器观测，$b_t(s)$ 是 belief：

$$
b_t(s)=p(s_t=s\mid o_{1:t},a_{1:t-1},u).
$$

执行动作 $a_t$ 并收到新观测 $o_{t+1}$ 后，belief update 为

$$
b_{t+1}(s')
\propto
p(o_{t+1}\mid s')
\sum_s p(s'\mid s,a_t)b_t(s).
$$

这正是 POMDP 的核心：

- transition $p(s'\mid s,a)$ 描述动作怎样改变世界；
- observation model $p(o\mid s)$ 描述传感器怎样看见状态；
- reward / cost 描述任务收益、路径代价与风险。

策略不是固定字符串，而是

$$
a_t=\pi(b_t,u).
$$

例如抓杯前发现杯子不在原处，正确系统应重新定位或询问，而不是继续执行旧坐标。执行中还应验证 precondition / effect：

```text
navigate(table_region)
  precondition: path exists
  effect: robot near table

place(cup, table_surface)
  precondition: holding(cup), reachable(surface), surface_clear
  effect: supported_by(cup, table)
```

只有新观测确认 `supported_by(cup, table)`，任务才闭环；planner 声称“已放置”不是 physical evidence。

## 最小可运行代码：为什么 Joint Grounding 能纠正 Semantic-only

下面的例子保留三个证据：`table` 语义、与红椅子的距离关系、可达性。被阻挡的候选先由 hard constraint 排除，再对剩余候选计算 posterior。

```python
import math

candidates = [
    # name, table semantic score, distance to red chair, reachability
    ("table_far", 0.96, 1.80, 0.99),
    ("table_near", 0.88, 0.40, 0.92),
    ("table_blocked", 0.91, 0.32, 0.00),
]

mu_near = 0.35
sigma_near = 0.25

semantic_only = max(candidates, key=lambda x: x[1])[0]
print("semantic-only:", semantic_only)

feasible = []
for name, semantic, distance, reachability in candidates:
    if reachability <= 0.0:  # hard constraint: no path / no valid goal region
        continue
    relation = math.exp(
        -((distance - mu_near) ** 2) / (2.0 * sigma_near ** 2)
    )
    log_score = (
        math.log(semantic)
        + math.log(relation + 1e-12)
        + math.log(reachability)
    )
    feasible.append((name, log_score))

max_score = max(score for _, score in feasible)
weights = [math.exp(score - max_score) for _, score in feasible]
normalizer = sum(weights)

ranked = sorted(
    [
        (name, score, weight / normalizer)
        for (name, score), weight in zip(feasible, weights)
    ],
    key=lambda x: x[2],
    reverse=True,
)

for name, score, posterior in ranked:
    print(name, "log-score=", round(score, 2),
          "posterior=", round(posterior, 3))
```

预期输出：

~~~text
semantic-only: table_far
table_near log-score= -0.23 posterior= 1.0
table_far log-score= -16.87 posterior= 0.0
~~~

`table_far` 的类别证据最好，却几乎不满足 `near red chair`；`table_blocked` 虽符合语言关系，但没有可行 goal region，因此不能直接成为执行目标。

代码里的 posterior 只是 toy calibration。真实系统还要验证不同 factor 是否过度相关：同一个视觉 backbone 同时产生颜色、类别和 relation 时，不能把它们误当三份独立证据而重复计票。

## 第七层：什么时候应该 Clarify，而不是硬选 Top-1

设最优与次优 grounding posterior 分别为 $p_{(1)}$、$p_{(2)}$。简单的 ambiguity signal 是 margin：

$$
\Delta=p_{(1)}-p_{(2)}.
$$

但是否询问不能只看 $\Delta$，还要看错误代价。定义：

- $L_{\text{wrong}}$：选错对象造成的 expected loss；
- $C_{\text{ask}}$：询问一次的时间与交互成本；
- $V_{\text{ask}}$：回答预计减少的风险。

只有当

$$
V_{\text{ask}}>C_{\text{ask}}
$$

时，澄清才值得。递送毛巾时可以容忍较低阈值；操作药品、热源或易碎物时应更保守。

好问题应最大化候选区分度，例如“你指的是靠门的桌子，还是靠窗的桌子？”比“请再说一遍”更有效。系统还必须允许 `none-of-the-above`：地图中没有目标、目标已移动、描述使用了地图未建模的属性时，强制 top-1 会把 unknown 伪装成 certainty。

## 第八层：Evaluation 要把四张成绩单分开

### 1. Language / Reference

- object grounding accuracy、Acc@IoU；
- relation / attribute accuracy；
- unique / ambiguous expression 分组；
- seen / unseen category、same-class distractor；
- none / absent-object rejection 与 calibration。

### 2. Spatial / Map

- grounding 到正确 physical instance，而不只是同类 box；
- target / anchor geometry accuracy；
- frame-dependent relation 单独统计；
- goal-region validity、free-space precision；
- pose error、occlusion、scene change subgroup。

### 3. Planning / Execution

- path validity、collision rate、SPL；
- grasp / place success；
- subgoal completion 与最终 task success；
- irreversible failure、human intervention、time / energy cost；
- simulation、real robot 与 oracle perception 分开。

### 4. Interaction / Safety

- clarification rate 与 clarification efficiency；
- risk-coverage：自动执行多少时，错误率多高；
- calibrated confidence；
- unsafe action、worst-group 与 recovery success。

必须做 error attribution：失败来自 parser、object map、relation、frame、planner、controller，还是 world change？单个 task-success 数字无法告诉你该修哪一层。

## 🔗 与我 CVPR / 偏振三维工作的连接

### 1. 偏振若改善几何，应先改善 Spatial Grounding，而不是直接宣称“语言理解更好”

更准的 normal、边界或透明 / 高光表面 support，可能让 `on`、`inside`、`near edge` 与 free-space 判断更可靠。但要冻结 text encoder、parser、planner 和 action budget，先看 target support、relation 与 goal-region endpoint。

### 2. 物理属性可以成为语言中的额外 Discriminative Cue

“高 DoLP 的杯子”“镜面柜门”可能帮助区分同类对象，但 DoLP / AoLP 受 view、illumination、material 与 reflection mode 共同影响。它们必须带 measurement condition 和 validity，不能被写成永恒 attribute。

### 3. matched control 要拆开 Geometry 与 Grounding 的收益

至少比较：

- RGB map + RGB grounding；
- RGB/polarization map + 同一 RGB grounding；
- RGB map + RGB/polarization grounding cue；
- RGB/polarization map + RGB/polarization grounding。

再分别报告 referential、goal-region、execution 与 safety，才能知道收益在哪个接口出现。

### 4. Language Prior 不能替代 Independent Physical Evidence

LLM 很容易猜“杯子通常在桌上”，但偏振三维工作若声称物理恢复改善，必须用真实 geometry / material measurement 与执行结果验证；把常识补全写回 map 时还要标注 `inferred`，不能伪装成 `observed`。

## 🔧 配菜 · 面试考点

### Q1：3D visual grounding 与 open-vocabulary retrieval 有什么区别？

Open-vocabulary retrieval 常按文本—feature 相似度找类别相关区域；3D grounding 还要解析 target、anchor、attribute、relation 与 frame，在多个同类 instance 中绑定正确实体，并报告歧义和不存在情况。

### Q2：为什么 grounding 正确仍可能 task failure？

目标 object 正确不代表存在 collision-free goal、机械臂可达 surface、满足 precondition 的动作序列或可靠 controller。Grounding、planning 与 execution 是串联但不同的接口。

### Q3：为什么 spatial relation 不能只存一个 label？

`left_of` 依赖 frame，`near` 依赖场景尺度，`on` 依赖 surface 与 support geometry。Relation 应带参数、置信度、frame、有效时间和 provenance。

### Q4：何时应该让机器人询问？

当多个 grounding 会导向不同动作，且错误 expected loss 高于询问成本时；问题应针对最能区分候选的属性或关系，而非泛泛重问。

### Q5：怎样证明 language-grounded robot 真正依赖地图？

用 same-class distractor、relation swap、anchor removal、shuffled graph、incorrect pose、absent target 与 unseen scene controls；再看 grounding、goal region 与 physical execution 是否按预期改变，而不是只评文本输出。

## 一张可复用的“Grounding-to-Action 二十问卡”

1. **Utterance**：原始指令是什么，是否保留上下文？
2. **Role**：theme、target、anchor、action 分别是谁？
3. **Attribute**：颜色、材质、大小修饰哪个实体？
4. **Candidate**：候选来自 detector、scene graph 还是 dense field？
5. **Identity**：找到的是类别还是 persistent physical instance？
6. **Relation**：关系是 unary、binary 还是 higher-order？
7. **Frame**：left / front 以谁为参考？
8. **Scale**：near / far 的阈值如何随场景变化？
9. **Factor**：semantic、attribute、relation、context 怎样组合？
10. **Dependence**：多个 factor 是否来自同一模型而重复计票？
11. **Unknown**：目标不存在时能否拒答？
12. **Ambiguity**：top-1 / top-2 gap 与 calibration 如何？
13. **Question**：什么澄清问题最能区分候选？
14. **Region**：object 怎样变成可导航 / 可操作区域？
15. **Constraint**：collision、reachability、visibility、safety 是否满足？
16. **Plan**：动作 precondition 与 effect 是否显式？
17. **Update**：新观测怎样更新 belief 与重规划？
18. **Verify**：完成状态由传感器证据还是 planner 自报？
19. **Attribution**：失败发生在 parser、map、grounding、plan 还是 control？
20. **Evidence**：语言、空间、执行与安全是否分开验收？

- [Visual Language Maps for Robot Navigation — ICRA 2023](https://vlmaps.github.io/)：把 pixel-level visual-language feature 放进地图，并将开放词汇和空间语言目标转成 navigation goal；其能力边界也提示 map localization 与真实 obstacle-aware execution 必须分开评价。

## 一句话总结

Language Grounding 是把带 role 的 noun、attribute、relation 与 reference frame 联合绑定到三维 target / anchor posterior；Embodied Instruction 则继续把 object 变成 collision-free、visible、reachable、safe 的 goal region，在 belief update 中规划、执行和验证。只有 reference、space、plan、physical execution 与 safety 五层分别通过，系统才从“文本上知道桌椅”升级为“能可靠地按这句话行动”。
