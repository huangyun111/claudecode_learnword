## ⏮ 上篇回顾（30 秒）

G1 把问题写成 $Q=(P,T,C,O,\Pi)$：总体、干预、对照、结果和协议。G2 要补上其中最容易漏掉的 $\Pi$：数据到底怎样分给 train/validation/test，以及一堆结果怎样汇总成一个可信结论。

## 🧭 开篇：把同一把椅子的相邻帧放进 train 和 test，为什么危险

假设数据集拍摄了 100 个物体，每个物体有 20 个相邻视角。若随机按“图像”切分，训练集很可能看过某把椅子的 19 个角度，测试时只需认出剩下的一个角度。分数会很高，却不回答“遇到新物体是否有效”。

关键不是文件数是否均衡，而是 **split unit 是否与想声称的泛化单位一致**：

```text
想声称“新图像”有效        → image split 可能足够
想声称“新物体/新场景”有效  → object/scene split
想声称“新相机/新实验室”有效 → sensor/site split 或独立数据集
```

同一个模型可以在 image split 上很好、在 scene split 上失效；这不是统计细节，而是两个不同问题。

## 第一层：数据切分先定义独立性

### 🪜 台阶 1：一个样本不等于一个独立证据

令 $g(i)$ 表示第 $i$ 张图像所属的 group，例如物体、场景、序列或采集批次。若相邻图像共享背景、光照、材质、标注流程，通常有

$$
\operatorname{Cov}(Y_i,Y_j\mid g(i)=g(j))>0.
$$

也就是说，同一 group 内的误差会一起变好或变坏。把它们随机打散，模型便能利用共享线索；把所有像素当独立样本，更会把有效样本量严重夸大。

### 🪜 台阶 2：leakage 不只是在 test 上训练

最明显的泄漏是把 test 标签放进 loss。更常见的泄漏还包括：

- 同一视频或同一物体的相邻帧跨 split；
- 用全数据均值、归一化统计量或 PCA 拟合 preprocessing；
- 根据 test error 删除“坏样本”、选择 epoch 或阈值；
- 同一对象的文件名、背景、水印或采集顺序成为捷径；
- 生成输入与下游 evaluator 共享 GT 派生信息，却被写成 RGB-only 结果。

规则很朴素：**任何由 test 参与决定的规则，都不能再把该 test 叫 held-out。**

### 🪜 台阶 3：train / validation / test 的职责不能互换

```text
train       拟合参数
validation  选模型、超参数、阈值与 checkpoint
test        在方案冻结后估计一次最终风险
```

若尝试 $K$ 个配置并挑 validation 最好者，$\min_k \hat R_{\mathrm{val},k}$ 已带有“挑出来的幸运成分”。这不意味着不能调参；它意味着要把选择过程限制在 validation，并把 test 留给冻结后的方法。

## 第二层：平均数前先决定比较单位

### 🪜 台阶 4：per-image metric 与 pooled-pixel metric 回答不同问题

对第 $i$ 张图，设有效像素集合为 $\Omega_i$，像素误差为 $e_{ip}$。

**先图像、后平均**：

$$
m_i=\frac{1}{|\Omega_i|}\sum_{p\in\Omega_i}e_{ip},\qquad
\bar m=\frac1N\sum_{i=1}^N m_i.
$$

每张图权重相同，回答“随机一张图的典型误差”。

**直接汇总像素**：

$$
m_{\mathrm{pixel}}=\frac{\sum_i\sum_{p\in\Omega_i}e_{ip}}{\sum_i|\Omega_i|}.
$$

大 mask 图权重更大，回答“随机有效像素的典型误差”。两者都可以合理，但必须预先说明；不能只挑对自己有利的一种。

### 🪜 台阶 5：matched comparison 应保留配对

对同一个 evaluation unit $i$，记录 Control 与 Proposed 的误差 $c_i,p_i$，定义

$$
d_i=p_i-c_i.
$$

$d_i<0$ 表示 Proposed 改善。平均效果为

$$
\bar d=\frac1N\sum_{i=1}^N d_i.
$$

它比“分别报告两列均值再相减”更有信息：你还能画 $d_i$ 的分布、找出受损场景，并在 bootstrap 中保持同一图像的配对。若模型 A 在一批容易图、模型 B 在另一批难图上测，两个均值的差混入了 composition difference，不再是模块效应。

## 第三层：bootstrap 不会凭空制造独立样本

### 🪜 台阶 6：它在重复什么

给定 $N$ 个独立 unit 的 paired differences $d_1,\ldots,d_N$，一次 bootstrap 是从这些 unit 中**有放回**抽取 $N$ 个，计算新的 $\bar d^{(b)}$。重复 $B$ 次：

$$
\{\bar d^{(1)},\ldots,\bar d^{(B)}\}.
$$

取 2.5% 与 97.5% 分位数，可得到 percentile interval。它近似“若从同一总体重新采一批 unit，均值差会怎样波动”。

但若 object 才是独立单位，就应 resample object，再带上其全部帧；逐像素 bootstrap 会把相关像素误当独立，区间虚假地变窄。

### 🪜 台阶 7：seed variation 与 sample variation 是两条轴

- **sample bootstrap**：固定训练结果，问换一批测试样本时结论多稳；
- **multiple seeds**：固定协议下，问随机初始化、data order 等训练随机性多稳；
- **dataset / sensor repetition**：问跨采集条件是否仍成立。

它们不互相替代。一个方法可能在同一 test 集上 bootstrap 很稳定，却对 seed 极敏感；也可能多 seed 稳定，但换相机立即退化。

## 🧪 最小可运行代码：配对 bootstrap 与 subgroup 检查

```python
import numpy as np

rng = np.random.default_rng(7)
# 同一 12 张图的 proposed - control，负数表示改善
d = np.array([-1.2, -0.8, -0.9, -0.5, -1.1, -0.7,
              -0.6, -0.4, -0.9,  0.3,  0.6, -0.2])
group = np.array(["easy"] * 6 + ["hard"] * 6)

B = 5000
boot = np.empty(B)
for b in range(B):
    ids = rng.integers(0, len(d), size=len(d))
    boot[b] = d[ids].mean()

print(f"paired mean delta = {d.mean():.3f} deg")
print("95% bootstrap interval =", np.quantile(boot, [0.025, 0.975]))
for name in ["easy", "hard"]:
    x = d[group == name]
    print(name, "mean=", round(x.mean(), 3),
          "harm_rate=", round((x > 0).mean(), 3))
```

这段代码不检验“是否显著”就替你宣布普适真理；它做的是把平均效果、区间、困难子组和 harm rate 放在同一张证据卡上。

## 第四层：subgroup 与 worst-case 不是装饰性附录

若只报 $\bar d=-0.53^\circ$，可能掩盖 easy 组大幅改善、hard 组系统性受损。对预先定义的子组 $G_k$，可报告：

$$
\bar d_k=\frac{1}{|G_k|}\sum_{i\in G_k}d_i,qquad
h_k=\frac{1}{|G_k|}\sum_{i\in G_k}\mathbb{1}(d_i>0).
$$

$\bar d_k$ 是平均变化，$h_k$ 是受损比例。worst-group 并不意味着总要把最小组的随机极值当结论；应预先规定分组、报告样本量，并把它视为 failure analysis 的入口。

对偏振/法向任务，合理的预注册式分组可包括：低 DoLP、高反光、遮挡边界、材质类别、scene 或传感器。事后扫几十个分组再只展示最好结果，本身又是 selection bias。

## 第五层：哪些统计说法不能说得太满

- “95% interval 不跨 0”不等于模型在所有未来数据上必胜；它只针对既定 unit、数据分布和重复机制。
- “三个 seed 都更好”是有价值的稳定性证据，但不是跨域泛化证明。
- “平均数更低”不等于没有伤害；应同时看 $d_i>0$ 的比例与严重失败。
- 多指标、多 checkpoint、多数据筛选后再报告单个最优 p-value，会放大假阳性；应说明选择空间，或保留 confirmatory test。

## 🔗 与你的 CVPR / 偏振工作有什么连接

1. corrected HAMMER 的真实 test 与 GT-derived simulation 是不同 population；不要把它们合成一个平均分。  
2. 比较 PA/R/fusion 时，固定 evaluator、mask、split 和 checkpoint-selection rule，并按同一 image 配对差分。  
3. 下游 fixed-SfP 的 normal metric 说明 downstream utility；生成 fidelity 需另行报告，二者不能互相替代。  
4. 若低 DoLP 或边界组恶化，即便总均值下降，也应把它写成设计限制，而不是藏在总表后面。

## 🎤 面试角度

**Q：为什么不能对一百万个像素做 t-test？**  
像素在同一图像、物体和采集流程中高度相关；把它们当一百万独立样本会低估不确定性。应按 claim 对应的 image、object、scene 或 dataset 层级聚合/重采样。

**Q：bootstrap 与多 seed 各回答什么？**  
前者估计测试样本构成变化带来的不确定性，后者估计训练随机性；两者都不足以替代独立数据集验证。

## 一句话总结

可信汇总从来不是“算一个 mean ± std”：先按真正独立的 unit 切分数据，冻结 train/validation/test 的职责；再用同一 unit 的 paired difference 表示比较；bootstrap 只在正确层级重复采样；最后把 seed、子组、harm 与 worst-case 摆在总均值旁边。这样得到的结论范围更窄，却更经得住复查。
