# 2026-10-09 · Claim–Evidence Mapping：论文里的每一句主张，究竟需要什么证据

> 阶段 H · 第 1 篇 ｜ 标签：claim–evidence mapping, claim taxonomy, scope, matched evidence, traceability, limitations, artifact
> 读法：先把论文句子拆成可检验的 claim，再为不同强度的 claim 配置恰好足够的实验、图表、限制与 artifact；目标不是“实验越多越好”，而是“证据类型与主张类型对得上”。

## ⏮ 上篇回顾（30 秒）

阶段 G 已经把单次实验组织成证据链：定义 estimand，锁定 matched control、split unit 与 evaluator，再报告 paired effect、uncertainty、harm 和 provenance。今天再向论文前端走一步：一篇论文往往有十几句显性或隐性的主张，怎样确保每一句都能向下找到证据，又不会把局部结果写成普遍结论？

## 🧠 开篇：同一个结果，为什么能写出四种强度完全不同的话

假设实验显示：在 corrected HAMMER 的固定 test split 上，新模块比 matched baseline 的 normal MAngE 低 $0.4^\circ$。下面四句话看起来相近，证据要求却逐级上升：

1. “我们设计了一个 polarization-aware fusion module。”——**构成性主张**；
2. “该模块在此协议下把 MAngE 降低了 $0.4^\circ$。”——**比较性主张**；
3. “该模块因为利用 AoLP / DoLP 几何线索而改善法向。”——**机制性主张**；
4. “该模块能稳定提升真实场景中的几何重建。”——**泛化与应用主张**。

同一张主结果表最多直接支持第 2 句。若没有 cue shuffle、component swap、真实数据、独立几何 GT 与下游重建评估，第 3、4 句就是把证据沿着“听起来合理”的方向外推。

Claim–Evidence Mapping 的核心动作因此是：

```text
论文句子
  → 把句子正规化为可检验 claim
  → 判断 claim 类型与强度
  → 列出最低必要证据
  → 绑定具体 table / figure / appendix / artifact
  → 写清证据没有覆盖的边界
```

## 第一层：先把一句自然语言 claim 写成“六槽位”

把第 $j$ 个经验性主张表示为

$$
C_j=(P_j,T_j,K_j,O_j,\Pi_j,S_j).
$$

六个符号分别表示：

- $P_j$（population）：结论针对谁，例如“HAMMER 中未见过的 scene”；
- $T_j$（treatment）：被研究的方法、模块或信息；
- $K_j$（comparator）：与谁比较；
- $O_j$（outcome）：用什么结果衡量，例如 MAngE、harm rate 或 latency；
- $\Pi_j$（protocol）：split、mask、evaluator、selection 与 aggregation；
- $S_j$（scope）：结论允许延伸到哪里，例如 simulated input、real RGB、normal estimation 或 reconstruction。

例如“我们的方法显著提高几何精度”不是一个合格的 claim：$P,K,O,\Pi,S$ 几乎都缺失。把它收紧后可以写成：

> 在 corrected HAMMER 的 held-out scene split、固定 valid-GT mask 与同一 evaluator 下，Ours 相对 matched baseline 降低 scene-level normal MAngE；95% cluster-bootstrap interval 与 effect 一并报告。

这句话变长了，却第一次变得可核验。所谓“写得严谨”，不是多加几个学术形容词，而是把读者需要补猜的槽位显式化。

## 第二层：不同 claim 类型，需要不同形状的证据

### 🪜 台阶 1：构成性与实现主张

典型句式是“we introduce / our model contains / we optimize”。最低证据包括：

- 清楚的 architecture、公式、输入输出与训练目标；
- 足以排除歧义的 implementation detail；
- 代码、配置或伪代码能够对应论文描述。

它能证明“东西是什么、怎样实现”，却不能证明“为什么有效”或“优于谁”。

### 🪜 台阶 2：比较性主张

典型句式是“outperforms / improves / is more efficient”。最低证据包括：

- 同一 population、split、input、mask 与 evaluator；
- 明确的 baseline 和 matched control；
- per-unit paired effect、uncertainty 与预定义 aggregation；
- 若声称效率更高，还要在同一硬件和计时协议下报告 latency、memory 或 FLOPs。

只给 best-run point estimate，不能支撑“稳定提升”；只在不同协议的表格里排名，不能支撑公平优越性。

### 🪜 台阶 3：机制性主张

典型句式是“because / by exploiting / the gain comes from”。这类 claim 不只问“有没有提升”，还问“提升来自哪里”。通常需要：

- component ablation：去掉目标部件；
- matched-capacity control：排除参数量或算力增加；
- cue shuffle / corruption：破坏被声称使用的信息；
- diagnostic：目标中间量随输入变化呈现预期响应；
- alternative-explanation test：主动检验竞争解释。

若完整系统优于 baseline，只能说明“这个系统在该比较中更好”；不能自动推出某个物理 cue 被正确利用。

### 🪜 台阶 4：泛化、稳健与因果主张

“works in the wild”“robust to noise”“causes improvement”都比单数据集均值更强。它们分别需要：

- 泛化：与目标 scope 匹配的 external dataset、unseen group 或 deployment sample；
- 稳健：预先定义的扰动轴、强度范围、worst-group 与 failure boundary；
- 因果：明确 intervention、可比 control、排除主要 confounder，并避免把相关诊断写成机制证明。

一个有用原则是：**claim 每多跨一步 scope，证据也必须多跨一步 domain。** simulated polarization 上的 fidelity 结果不能越级成为 real-RGB 成像证据；depth-derived normal 不能被改名为独立几何 GT。

## 第三层：“证据足够”不是数量问题，而是覆盖问题

设 claim $C_j$ 有一组必要证据要求

$$
R(C_j)=\{r_{j1},r_{j2},\ldots,r_{jm}\},
$$

论文实际提供的证据集合为

$$
E=\{e_1,e_2,\ldots,e_n\}.
$$

定义覆盖矩阵

$$
A_{jk}=
\begin{cases}
1,& e_k\text{ 直接覆盖 }r_{j\ell}\text{ 中的某一项},\\
0,& \text{否则}.
\end{cases}
$$

但“有一篇实验提到过”仍不等于充分。每条映射还要同时通过四个匹配条件：

$$
M(C_j,e_k)=
I_P\,I_{\Pi}\,I_O\,I_S,
$$

其中四个指示量分别检查 population、protocol、outcome 与 scope 是否一致；任一项为 0，乘积就是 0。比如：

- 同样是 normal MAngE，但 mask 不同，$I_{\Pi}=0$；
- 同样是 HAMMER，但一个评 simulated、一个声称 real RGB，$I_S=0$；
- 图像视觉更自然，却声称 geometry 更准，$I_O=0$；
- frame-level 随机划分，却声称泛化到 unseen object，$I_P=0$。

因此，十个错位实验不能替代一个对位实验。Claim–Evidence Map 关心的是 coverage 与 match，不是附件页数。

## 第四层：把整篇论文画成“主张—证据二部图”

最实用的工作表可以只有五列：

| Claim ID | 论文中的主张 | 最低必要证据 | 实际落点 | 边界 / 状态 |
|---|---|---|---|---|
| C1 | 方法包含 physics-guided fusion | 公式、结构、实现 | Sec. 3, Fig. 2, config | supported |
| C2 | 固定协议下优于 baseline | matched table、paired interval | Table 1, result JSON | supported |
| C3 | gain 来自 polarization cue | shuffle、swap、capacity control | Table 2 | partial：缺 real cue corruption |
| C4 | 改善真实几何 | real input、独立 GT、mesh metric | none | unsupported：删去或降级 |

这里最重要的不是把所有格子填成绿色，而是允许三种诚实动作：

1. **补证据**：claim 重要且实验可行；
2. **降级措辞**：把“demonstrates”改成“is consistent with”；
3. **缩小 scope**：把“real-world geometry”改成“the evaluated simulated benchmark”。

限制（limitations）也应绑定 claim，而不是在末尾泛泛写“未来将测试更多数据”。好的限制会指出：哪一个槽位没有被覆盖，因此哪一种外推暂时不成立。

## 🧪 最小可运行代码：自动审计 claim 是否缺证据

下面只用 Python 标准库。它不替你判断科学真伪，而是把“比较性、机制性、泛化性主张需要哪些证据”写成可执行检查。

```python
claims = [
    {
        "id": "C1",
        "type": "comparative",
        "text": "Ours lowers normal MAngE on corrected HAMMER",
        "scope": "simulated_hammer",
        "evidence": {"matched_protocol", "paired_effect", "uncertainty"},
    },
    {
        "id": "C2",
        "type": "mechanistic",
        "text": "The gain comes from polarization cues",
        "scope": "simulated_hammer",
        "evidence": {"component_ablation", "matched_capacity"},
    },
    {
        "id": "C3",
        "type": "generalization",
        "text": "The method improves real-world geometry",
        "scope": "real_rgb_geometry",
        "evidence": {"external_data", "independent_geometry_gt"},
    },
]

required = {
    "comparative": {"matched_protocol", "paired_effect", "uncertainty"},
    "mechanistic": {
        "component_ablation", "matched_capacity", "cue_intervention"
    },
    "generalization": {
        "external_data", "independent_geometry_gt", "scope_matched_protocol"
    },
}

for claim in claims:
    missing = required[claim["type"]] - claim["evidence"]
    status = "SUPPORTED" if not missing else "GAP"
    print(f'{claim["id"]}: {status}')
    if missing:
        print("  missing:", ", ".join(sorted(missing)))
```

预期输出中，C1 通过；C2 缺少直接 cue intervention；C3 即使已有 external data 与某种 GT，也仍缺 scope-matched protocol。你可以把这段检查扩展为论文仓库中的 `claims.json`，让每个 claim 继续指向 table cell、运行记录与 artifact hash。

## 🔗 与你的 CVPR / 偏振工作怎样连起来

对偏振生成与下游任务，建议至少拆成四条互不替代的 claim 链：

1. **生成链**：输出在固定 reference / mask 下更接近目标偏振图；
2. **读出链**：从输出恢复的 AoLP / DoLP 或 Stokes 更一致；
3. **下游链**：相同 downstream model 与 evaluator 下 normal / depth 更准；
4. **真实几何链**：真实采集上，相对独立几何 GT 的误差下降。

这四条链可以相关，但不能用箭头直接省略中间证据。视觉质量不能替代物理 readout，readout consistency 不能替代 downstream gain，downstream normal 也不能自动证明 metric 3D reconstruction。论文写作时，先给每条摘要和 introduction claim 编号，再检查它能否落到对应协议的 table、figure、per-sample result 与 artifact。

## 🎤 面试角度

**Q：Claim–Evidence Map 与普通实验清单有什么区别？** 实验清单从“我做了什么”出发；Claim–Evidence Map 从“我说了什么”出发，检查每句主张是否有类型匹配、scope 匹配且可追溯的证据。

**Q：ablation 为什么不一定支持机制 claim？** 因为移除模块可能同时改变 capacity、optimization 或信息流。要把“模块有用”推进到“因为使用某个 cue 而有用”，还要增加 matched-capacity 与 cue intervention 等排除性证据。

**Q：发现 claim 没有足够证据时怎么办？** 只有三种合规选择：补实验、缩小适用范围、降低措辞强度。不能用更多形容词或更多 qualitative examples 填补证据类型缺口。

**Q：limitations 为什么也是证据结构的一部分？** 因为它标出 claim 的外边界，防止读者把局部支持误读为更大 population、protocol 或 outcome 上的支持。

## 📚 进一步阅读

- [NeurIPS Paper Checklist](https://neurips.cc/Conferences/2021/PaperInformation/PaperChecklist)：要求主张与理论、实验和可泛化范围匹配，并明确 assumptions 与 limitations。
- [ACM Artifact Review and Badging](https://www.acm.org/publications/policies/artifact-review-and-badging-current)：区分 artifact available、evaluated、results reproduced 等不同强度，不把“上传了文件”等同于“结论已复得”。
- [ML Reproducibility Checklist](https://www.cs.mcgill.ca/~jpineau/ReproducibilityChecklist.pdf)：把模型、数据、代码、超参数与结果报告落实为可审计项目。

## 一句话总结

Claim–Evidence Mapping 不是给论文多做一张表，而是把每个主张正规化、分级，并要求它只从 population、protocol、outcome 与 scope 都匹配的证据中取得支持；证据不够时，补实验、降措辞或缩边界，而不是越级外推。
