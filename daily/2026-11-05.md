# 2026-11-05 · 一段视频“看起来连续”，为什么还不能证明四维场景正确：动态重建的观测与证据合同

> 阶段 K · 第 4 篇 ｜ 标签：dynamic reconstruction, synchronized multi-view, scene flow, 3D tracks, per-time geometry, held-out view-time, visibility, subgroup evaluation, matched controls
> 主线：动态重建不是把每帧渲染好就结束。要把“恢复了真实 4D 场景”拆成五份可核验合同：观测何时、从哪里采到；同一物理点如何跨时刻保持身份；每个时刻的几何怎样独立评估；未见过的 view-time 组合怎样留出；快速运动、遮挡、拓扑变化等困难 subgroup 是否被平均数掩盖。

---

## ⏮ 上一篇回顾（30 秒）

K3 比较了 Dynamic NeRF 与 4D Gaussian Splatting：前者通常把时间写入 spacetime field 或 canonical deformation，后者让显式 Gaussian 随时间移动、旋转或改变属性。两类方法都能得到漂亮的动态 novel view，但也都可能用 appearance、deformation、visibility 或 support change 互相补偿。

所以今天不再问“表示能力够不够”，而问更严格的问题：**你到底观察了什么，又用什么独立证据证明恢复的是正确的 geometry、motion 与 identity？**

## 🎯 主菜：先把“4D 正确”拆成不同 estimand

动态场景可写成随时间变化的状态

$$
\mathcal S(t)=\{\mathcal G(t),\mathcal A(t),\mathcal V(t),\mathcal I(t)\},
$$

其中：

- $t$ 是物理时间；
- $\mathcal G(t)$ 是该时刻的三维几何；
- $\mathcal A(t)$ 是材质、辐射或 appearance；
- $\mathcal V(t)$ 是相机相关的 visibility；
- $\mathcal I(t)$ 是跨时间的物理身份或 correspondence。

相机 $v$ 在时刻 $t$ 只给出二维观测

$$
\mathbf y_{v,t}=\mathcal R\!\left(\mathcal S(t),\mathbf K_v,\mathbf T_{v,t},\boldsymbol\ell_{v,t}\right)+\boldsymbol\epsilon_{v,t},
$$

其中 $\mathcal R$ 是成像 / rendering 过程，$\mathbf K_v$ 是内参，$\mathbf T_{v,t}$ 是相机位姿，$\boldsymbol\ell_{v,t}$ 表示曝光、光照等采集条件，$\boldsymbol\epsilon_{v,t}$ 是噪声。

这条式子立刻揭示四个不同目标：

1. **Image reconstruction**：已观察的 $\mathbf y_{v,t}$ 能否被重建；
2. **Novel-view synthesis**：同一 $t$、新相机 $v'$ 的图像能否预测；
3. **Temporal interpolation / extrapolation**：新时刻 $t'$ 的状态能否预测；
4. **Physical 4D recovery**：$\mathcal G(t)$、motion 与 identity 是否接近真实世界。

前 3 个目标可以为第 4 个提供证据，却不能自动等价于第 4 个。

## 第一份合同：Observation Contract——“同时拍到”必须是可量化条件

### 1. 同步多视图为什么比“多段视频”更强

若多个相机在同一物理时刻 $t$ 观察动态点 $\mathbf X(t)$，则它们满足

$$
\tilde{\mathbf u}_{v,t}\sim\mathbf K_v\mathbf T_{v,t}\tilde{\mathbf X}(t).
$$

多条射线约束的是**同一个三维状态**，因此可以三角化或做 multi-view consistency。

若相机 $a$ 与 $b$ 实际存在时间偏移 $\Delta t$，它们约束的分别是 $\mathbf X(t)$ 与 $\mathbf X(t+\Delta t)$。一阶 Taylor 展开为

$$
\mathbf X(t+\Delta t)\approx\mathbf X(t)+\dot{\mathbf X}(t)\Delta t.
$$

因此由不同步引入的三维偏差近似为

$$
\|\Delta \mathbf X\|\approx\|\dot{\mathbf X}(t)\|\,|\Delta t|.
$$

物体速度越快，同样 10 ms 的同步误差就越危险。动态重建论文若只写“multi-view video”，却不报告 hardware trigger、timestamp 精度、残余 offset 或 rolling-shutter readout，就没有把输入难度说清楚。

### 2. 相机与时间都要校准

完整观测合同至少记录：

- camera intrinsics、distortion model 与分辨率；
- world-to-camera / camera-to-world convention；
- 相机位姿来自外部标定、静态 SfM，还是与动态场联合优化；
- global shutter / rolling shutter；
- frame timestamp、帧率、曝光时间与丢帧；
- 多相机同步方式及可接受的最大 $|\Delta t|$；
- 光照、自动曝光、white balance 是否跨相机一致。

若 candidate 联合优化 time offset 和 pose，而 baseline 使用冻结的输入标定，比较就不再是单一方法因素。要么所有方法共享同一 calibration，要么明确把 calibration quality 作为独立变量报告。

## 第二份合同：Identity / Motion Contract——同一个点去了哪里

### 3. Scene flow 不只是相邻帧 optical flow

设物理点 $i$ 在时刻 $t$ 的世界坐标为 $\mathbf X_i^t$。三维 scene flow 定义为

$$
\mathbf s_i^t=\mathbf X_i^{t+1}-\mathbf X_i^t.
$$

若预测为 $\hat{\mathbf s}_i^t$，常见 endpoint error 为

$$
\operatorname{EPE3D}_i=\|\hat{\mathbf s}_i^t-\mathbf s_i^t\|_2.
$$

二维 optical flow 只检查投影后的移动；正确的 2D flow 仍可能来自错误 depth 与错误 3D motion 的补偿。反过来，正确 scene flow 必须同时说明：起点是哪一个物理点、终点是否仍可见、坐标系是否一致。

### 4. Long-range tracks 检查 identity，而不只检查相邻平滑

一个跨 $L$ 帧的 3D track 是

$$
\mathcal T_i=\{(t,\mathbf X_i^t,z_i^t)\}_{t=1}^{L},
$$

其中 $z_i^t\in\{0,1\}$ 表示点在目标视图 / 传感器中是否可观测。

相邻 scene flow 都很小，并不保证长程 identity 正确：模型可能在遮挡后把点接到外观相似的另一个表面。于是至少要分别检查：

- visible 时的 2D / 3D track location error；
- occlusion classification；
- track survival length；
- 遮挡前后 re-identification；
- 大运动、薄结构、非刚体、拓扑变化 subgroup。

如果 Gaussian 会 densify / prune，primitive ID 不必等于物理点 ID。此时不能直接把“同一个 Gaussian index”当作 ground-truth correspondence；需要独立 track annotation、已知 marker、synthetic GT 或带 correspondence 的扫描数据。

## 第三份合同：Per-time Geometry Contract——每一帧的表面都要单独交卷

### 5. 一张时间平均 mesh 会掩盖什么

动态结果若只导出一个 canonical mesh，可能完全漏掉：

- 某些时刻局部表面塌陷；
- 快速运动阶段的 lag；
- 遮挡区被错误填平；
- topology change 被 canonical warp 强行拉伸；
- appearance 很好但 geometry 在深度方向漂移。

因此应在冻结的世界坐标、尺度、alignment 与 valid support 下，对多个时刻的表面 $\hat{\mathcal G}(t)$ 分别评估。

若 $P_t$ 是预测表面采样点，$Q_t$ 是 GT 点，可写双向 Chamfer distance：

$$
\operatorname{CD}(P_t,Q_t)=
\frac{1}{|P_t|}\sum_{\mathbf p\in P_t}\min_{\mathbf q\in Q_t}\|\mathbf p-\mathbf q\|_2^2
+\frac{1}{|Q_t|}\sum_{\mathbf q\in Q_t}\min_{\mathbf p\in P_t}\|\mathbf q-\mathbf p\|_2^2.
$$

第一项更接近 accuracy，第二项更接近 completeness。只报单向距离会让“只重建容易区域”的稀疏预测看起来很好。还应报告 normal error、coverage，以及静态背景 / 动态前景、可见 / 遮挡、慢 / 快运动等分组。

### 6. Alignment 必须被冻结

若每个时刻都允许独立 Sim(3) 对齐，某些整体漂移和尺度抖动会被评估脚本消掉。更严格的选择是：

1. 用训练外的校准物或首帧确定一次 global alignment；
2. 冻结该变换；
3. 对所有后续时刻使用同一变换。

这才能让 temporal drift 留在指标里，而不是被 per-frame registration 悄悄修复。

## 第四份合同：Held-out View-Time——不要只沿一个轴留出

设训练观测集合为

$$
\Omega_{\text{train}}\subseteq \mathcal V\times\mathcal T.
$$

动态方法需要在 view 与 time 的笛卡尔积上定义留出方式。

### 7. 四种测试回答四个不同问题

1. **Held-out view, seen time**：同一时刻的新视角，主要测空间泛化；
2. **Seen view, held-out time**：同一相机的帧间插值，主要测时间模型；
3. **Held-out view-time pair**：相机与时刻组合都未见，检查时空因素能否组合；
4. **Future time**：训练时间窗之外的外推，难度与 interpolation 完全不同。

如果所有 test frame 的同一时刻仍有其他相机训练图像，模型可能是在“跨视角搬运当时外观”，而不是学会真正的 temporal prediction。反之，单目相邻帧留出又可能被时间平滑轻易插值。协议必须明确 test cell 在 $\mathcal V\times\mathcal T$ 网格中的位置。

### 8. 图像指标与物理指标分层

建议至少分成五层报告：

| 层级 | 代表问题 | 典型指标 |
|---|---|---|
| image | 新视图像不像 | PSNR / SSIM / LPIPS |
| temporal | 视频是否闪烁 | temporal perceptual error、warp residual |
| track / motion | 点是否去了正确位置 | 2D track error、occlusion accuracy、EPE3D |
| geometry | 每时刻表面是否正确 | Accuracy / Completeness / CD / Normal MAE |
| system | 能否在目标资源运行 | FPS、latency、memory、training cost |

这些数字不能互相替代。尤其 FPS 证明的是系统吞吐，PSNR 证明的是 held-out rendering，它们都不是 geometry 或 motion 的直接证书。

## 第五份合同：Subgroup 与 Matched Controls——平均数最容易藏住困难运动

### 9. 先冻结 subgroup，再看结果

动态数据应在看 test 结果前定义 subgroup，例如：

- motion magnitude：slow / medium / fast；
- visibility：always visible / temporarily occluded / reappearing；
- object type：rigid / articulated / non-rigid；
- geometry：large surface / thin structure / specular region；
- topology：stable / contact / split / merge；
- camera condition：static / moving / rolling shutter。

同时报告 micro average、scene-level macro average、worst-group 与 coverage。大量静态背景像素可能让总体均值很好，却掩盖真正关心的动态前景失败。

### 10. Matched controls 要只改变一个主因素

比较 Dynamic NeRF、4DGS 或新 motion module 时，至少冻结：

- 相同 train / VAL / TEST view-time cells；
- 相同输入帧、分辨率、相机与同步信息；
- 相同 initialization 与外部 tracker / depth prior 权限；
- 相同训练时长、显存预算或明确的 compute-matched 版本；
- 相同 alignment、mask、support 与 metric implementation；
- 相同 checkpoint selection，只用 VAL 选，不看 TEST；
- 相同随机种子集合与失败运行处理规则。

还需要能证伪机制的 negative controls：打乱时间、打乱 track、移除同步、冻结 deformation、用 matched-capacity MLP 替代专用 module。若真实 track 与 shuffled track 表现一样，“模型利用了 correspondence”的故事就站不住。

## 🧪 最小可运行代码：训练时刻完全一致，帧间运动仍可不同

下面两个轨迹在观测时刻 $t\in\{0,0.5,1\}$ 完全相同，但在 held-out time 上明显不同。代码还展示 micro average 怎样被大量静态点稀释。

```python
from math import sin, pi


def model_a(t):
    return t


def model_b(t):
    # 在 t = 0, 0.5, 1 时附加项都为 0
    return t + 0.35 * sin(2.0 * pi * t)


observed = [0.0, 0.5, 1.0]
held_out = [0.25, 0.75]

train_gap = max(abs(model_a(t) - model_b(t)) for t in observed)
test_gap = sum(abs(model_a(t) - model_b(t)) for t in held_out) / len(held_out)

# 1000 个静态背景点误差很小，20 个快速前景点误差很大
background = [0.01] * 1000
fast_foreground = [0.50] * 20
micro = sum(background + fast_foreground) / len(background + fast_foreground)
macro = ((sum(background) / len(background))
         + (sum(fast_foreground) / len(fast_foreground))) / 2.0
worst_group = max(sum(background) / len(background),
                  sum(fast_foreground) / len(fast_foreground))

print(f"observed-time max gap = {train_gap:.3f}")
print(f"held-out-time mean gap = {test_gap:.3f}")
print(f"micro average error = {micro:.4f}")
print(f"macro subgroup error = {macro:.4f}")
print(f"worst-group error = {worst_group:.4f}")
```

预期输出：

```text
observed-time max gap = 0.000
held-out-time mean gap = 0.350
micro average error = 0.0196
macro subgroup error = 0.2550
worst-group error = 0.5000
```

第一组数字说明：训练帧相同不代表中间轨迹唯一。第二组数字说明：总体平均误差 $0.0196$ 看似很小，但快速动态前景的误差是 $0.5$。

## 🔬 CVPR / 研究连接：一张可信的动态重建主表应该怎样设计

### 1. 主表不是把所有指标塞成一行

建议按 claim 分块：

- rendering block：held-out view、held-out time、held-out view-time；
- motion block：2D tracks、occlusion、3D scene flow；
- geometry block：per-time accuracy / completeness / normal；
- robustness block：fast motion、reappearance、thin structure、topology change；
- efficiency block：训练成本、memory、FPS / latency。

### 2. 数据集能力必须和 claim 对齐

只有 RGB novel-view GT 的数据集，最多直接支持 rendering claim；没有 3D geometry / scene flow / track GT，就不能把 PSNR 包装成 4D geometry accuracy。可以用多个 benchmark 拼出证据链，但要说明各自支持哪条主张，不能把不同数据集上的数字拼成一个联合结论。

### 3. 最有价值的 failure case 是“图像好、物理错”

例如：

- held-out PSNR 高，但遮挡后 track 跳到邻近表面；
- 单帧 mesh 好，但 global alignment 下随时间漂移；
- 慢运动正常，fast subgroup 出现 lag；
- novel view 好看，但薄结构 completeness 很差。

这些反例能直接划出方法边界，也能防止评审把 image quality 与 physical recovery 混为一谈。

## 🎤 面试角度

### Q1：同步误差为什么会随运动速度放大？

因为不同相机实际观察的是 $\mathbf X(t)$ 与 $\mathbf X(t+\Delta t)$；一阶近似误差为 $\dot{\mathbf X}(t)\Delta t$，所以速度和时间偏移共同决定伪几何偏差。

### Q2：Held-out view 与 held-out time 有什么区别？

前者主要测试同一物理状态下的空间视角泛化；后者测试未观察时刻的动态插值或外推。两者都好，仍不必然证明三维 geometry / motion 正确。

### Q3：为什么 per-frame alignment 可能不公平？

它会逐帧消除整体漂移、尺度变化或 pose error。若目标是评估 4D consistency，应冻结一次 global alignment 并沿时间复用。

### Q4：为什么 primitive ID 不一定是物理 identity？

因为 4DGS 的 densification、pruning、split 与 merge 会改变 primitive support；同一 index 只是实现对象，除非方法和独立证据保证其持续对应同一物理区域。

### Q5：为什么一定要报 worst-group？

动态前景通常只占少量像素，micro average 会被静态背景主导。Worst-group 能暴露快速运动、遮挡、薄结构等真正决定方法可用性的失败。

## ✅ 今日闭环：五份合同

1. **Observation**：相机、时间、同步、曝光与 calibration 明确吗？
2. **Identity / Motion**：scene flow、tracks、visibility 与 reappearance 有独立证据吗？
3. **Per-time Geometry**：每时刻的 accuracy、completeness、normal 与 global drift 测了吗？
4. **Held-out View-Time**：空间、时间、组合与外推分别留出了吗？
5. **Subgroup / Controls**：困难运动、遮挡和 topology 的最坏组，以及 matched / shuffled controls 都报告了吗？

只有这五份合同互相接上，“动态视频拟合”才有资格升级为“可核验的四维重建”。

## 可靠来源

- [Dynamic 3D Gaussians: Tracking by Persistent Dynamic View Synthesis](https://arxiv.org/abs/2308.09713)：通过 persistent Gaussian、local rigidity 与动态 novel-view synthesis 联合讨论 tracking 和 reconstruction，也说明 representation identity 需要额外约束。
- [TAP-Vid: A Benchmark for Tracking Any Point in a Video](https://tapvid.github.io/)：把任意表面点的长程 tracking 与 occlusion 明确成独立 benchmark。
- [KITTI Scene Flow Evaluation](https://www.cvlibs.net/datasets/kitti/eval_scene_flow.php)：展示 scene flow 需要同时处理 disparity 与 optical flow，并区分 foreground / background。
- [General Dynamic Scene Reconstruction from Multiple View Video](https://openaccess.thecvf.com/content_iccv_2015/papers/Mustafa_General_Dynamic_Scene_ICCV_2015_paper.pdf)：给出 wide-baseline multi-view dynamic reconstruction 的经典问题设置与几何重建视角。
- [Humans as a Calibration Pattern: Dynamic 3D Scene Reconstruction from Unsynchronized and Uncalibrated Videos](https://openaccess.thecvf.com/content/ICCV2025/papers/Choi_Humans_as_a_Calibration_Pattern_Dynamic_3D_Scene_Reconstruction_from_ICCV_2025_paper.pdf)：直接讨论同步与相机 calibration 不满足时，动态 neural field 需要联合估计 time offset 和 pose 的困难。
