# 2026-10-16 · Review / Rebuttal / 答辩：不要“赢过质疑”，要让争议变成可核验的判断

> 阶段 H · 第 4 篇 ｜ 标签：peer review, rebuttal, defense, concern taxonomy, evidence gap, scope control, response matrix, decision relevance
> 读法：把每条质疑先还原成“它在担心哪条 claim、缺什么证据、会怎样影响结论”，再选择澄清、纠错、补充小检查、收缩边界或承认限制。目标不是逐句反驳，而是帮助 reviewer / AC / 答辩委员作出可复核的决定。

## ⏮ 上篇回顾（30 秒）

H3 把 Results 组织成可扫描的证据路径：

~~~text
main comparison
  → matched ablation
  → mechanism / subgroup
  → qualitative + failure
  → efficiency / limitations
~~~

但论文提交后，读者不会严格沿着作者设计的路径走。他们会在某个 protocol、公式、对照或措辞处停下来，提出一个可能改变结论的疑问。

今天讨论的不是“怎样写得强硬”，而是怎样把质疑接回证据链。

## 🧠 开篇：review 不是攻击列表，而是一组尚未闭合的判断

假设 reviewer 写道：

> The gain may come from additional capacity rather than the proposed polarization-aware fusion.

情绪化阅读会把它理解为“审稿人没看懂创新”。证据化阅读则会把它翻译成：

~~~text
目标 claim：polarization-aware fusion 带来增益
替代解释：更多参数或不同优化路径带来增益
当前缺口：没有 matched-capacity replacement
决策后果：机制 claim 不成立，但 overall empirical gain 可能仍成立
可核验回应：指出已有对照，或补一个小型 matched check，或收缩机制措辞
~~~

一旦这样翻译，回应就不再是口才比赛，而成为一个有限的 inference problem：**哪条主张受影响？哪一块证据能区分原解释与替代解释？**

## 第一层：先把质疑正规化成五槽对象

把第 $j$ 条 concern 写成

$$
q_j=(c_j,g_j,h_j,r_j,b_j),
$$

其中：

- $c_j$（claim）：它针对哪条具体主张；
- $g_j$（gap）：它认为缺少哪项事实、协议或证据；
- $h_j$（harm）：若 concern 成立，结论会受到多大影响；
- $r_j$（resolution）：什么观察能真正化解争议；
- $b_j$（boundary）：当前 rebuttal 的页数、匿名、时间和实验政策允许做到什么。

例如“泛化不足”太宽，不能直接行动。要继续展开：

$$
c_j=\text{“方法对真实偏振场景普遍有效”},
$$

$$
g_j=\text{“只在单一相机与材质分布上评估”},
$$

$$
h_j=\text{“总体有效可以保留，但跨传感器 claim 不能保留”}.
$$

于是 resolution 可能不是临时跑十个新数据集，而是：补充已有 cross-sensor result、报告预定义 subgroup，或把结论收缩为“在当前相机与数据协议下有效”。

这就是第一条原则：

> **回应的最小单位不是 reviewer 的一句话，而是受到影响的一条 claim。**

## 第二层：五类质疑，需要五种不同证据

### 1. 事实 / 阅读定位（Fact）

典型形式：公式符号似乎不一致、某个 baseline 被误读、实验已在 supplement 却未被看到。

最优回应不是“Please read Section 4”，而是给出可定位事实：

~~~text
Concern → exact location → exact fact → why it resolves the concern
~~~

若读者普遍找不到，说明表达本身也有问题。即便 reviewer 确实漏看，也应在 camera-ready 中提高可见性。

### 2. 协议（Protocol）

典型形式：split 是否泄漏、mask 是否一致、checkpoint 是否由 TEST 选择、alignment 是否公平。

这类问题不能靠解释动机解决，必须恢复 evaluation contract：

$$
\Pi=(D,S,M,A,G,C),
$$

其中 $D$ 是数据版本，$S$ 是 split，$M$ 是 mask，$A$ 是 alignment，$G$ 是 aggregation，$C$ 是 checkpoint-selection rule。

只要其中一项不同，“同表比较”就可能不再估计同一个 quantity。协议质疑优先级通常很高，因为它可能使整张结果表失去可比性。

### 3. 机制（Mechanism）

典型形式：提升也许来自参数量、训练预算、预训练数据或 generic fusion，而不是论文声称的物理机制。

这类问题需要能排除替代解释的 control：

- matched-capacity replacement；
- shuffled / corrupted cue；
- 按 cue quality 分层；
- 拆除目标模块但保留训练预算；
- 检验 Method 预先推导出的 observable prediction。

普通 ablation 只能说明“去掉后变差”；机制证据还要说明“当声称依赖的信息被破坏时，行为按预测改变”。

### 4. 泛化（Generalization）

典型形式：只在一个 dataset、相机、材质或场景分布验证。

泛化质疑有三种诚实处理：

1. 已有覆盖范围内的数据被漏读 → 澄清；
2. 可以做小而匹配的 subgroup / cross-domain check → 补充；
3. 证据确实没有覆盖 → 收缩 scope，并写明未来需要怎样的独立验证。

“未来会测更多数据”不是当前证据。promise 不应被写成 result。

### 5. 表达（Expression）

典型形式：符号未定义、图注无法独立阅读、claim 太强、Method 与 Results 对不上。

表达问题也可能是实质问题的信号。如果三位 reviewer 都误解同一处，最便宜的解释未必是“三个人都不认真”，更可能是论文没有让推理链显式可见。

## 第三层：怎样决定先回哪条——看“决策相关性”，不是看语气强弱

设每条 concern 有三个分数：

- $I_j\in[0,1]$：impact，若成立会多大程度改变接收判断；
- $G_j\in[0,1]$：evidence gap，当前证据缺口有多大；
- $T_j\in[0,1]$：tractability，在 rebuttal 约束内可解决程度。

定义优先级

$$
p_j=I_j\bigl[\lambda G_j+(1-\lambda)T_j\bigr],
$$

其中 $\lambda\in[0,1]$ 控制对“缺口严重”与“能够解决”的权衡。

这个式子不是会议评分规则，只是写作前的资源分配工具。展开理解：

1. $I_j$ 很小：即使解决，也不改变核心判断，不应占据大量篇幅；
2. $I_j$ 很大且 $G_j$ 很大：属于核心证据风险，必须回应；
3. $I_j$ 很大但 $T_j$ 很低：不能假装一页 rebuttal 能补完，应收缩 claim 或承认限制；
4. $T_j$ 很高但 $I_j$ 很小：容易回答不代表值得优先回答。

语气最尖锐的 comment 不一定最重要。真正优先的是会改变 soundness、novelty、protocol validity 或 main claim 的问题。

## 第四层：一个回应块只做四件事

推荐把每个高优先级回应写成

~~~text
Concern → Answer → Evidence → Consequence
~~~

### Concern

用一句中性话复述你理解的问题，避免稻草人式改写。

### Answer

先给结论：同意、部分同意，还是现有证据已回答。

### Evidence

给出精确位置、数字、协议或新增的小检查。不要先铺三段背景才出现答案。

### Consequence

说明它怎样改变论文：保持 claim、降低措辞、增加 limitation、修正图表，还是承认尚未解决。

例如：

> **R2—capacity alternative.** We agree that Base→Ours alone does not isolate the fusion mechanism. The submitted Table S4 already compares a parameter-matched generic fusion block under the same data, optimizer, steps, and checkpoint rule; Ours lowers scene-level angular error by 0.42° relative to that control. We will move this comparison into the main ablation table and narrow the mechanism wording from “proves” to “supports.”

这段有效，不是因为它显得自信，而是因为它同时处理了 alternative explanation、matched protocol、effect 和 claim strength。

## 第五层：澄清、补证据、缩边界，三者不是输赢等级

对 concern $q_j$，可选择动作集合

$$
\mathcal A_j=\{a_{\text{clarify}},a_{\text{correct}},a_{\text{check}},a_{\text{scope}},a_{\text{concede}}\}.
$$

每个动作执行后，都有一个 residual gap $R_j(a)\in[0,1]$。理想目标不是“全部做实验”，而是找一个在政策和成本允许范围内、能把 residual gap 降到可接受阈值 $\tau$ 的最小动作：

$$
a_j^*=\arg\min_{a\in\mathcal A_j}K_j(a)
\quad\text{s.t.}\quad
R_j(a)\le\tau,
$$

其中 $K_j(a)$ 是页数、时间、算力和引入新混淆的综合成本。

推导含义如下：

- 若 evidence 已存在，只是位置不清，`clarify` 的成本最低；
- 若数字或描述确实错了，必须 `correct`，不能用语气掩盖；
- 若一个小型 matched check 能区分两个解释，用 `check`；
- 若现有研究设计根本没有覆盖更大总体，用 `scope`；
- 若核心假设失败，应 `concede`，而不是堆无关实验。

收缩边界不是失败。把“普遍有效”改成“在冻结的 real-input VAL protocol 下平均改善”，往往比用不足证据维持强 claim 更可信。

## 第六层：新增实验必须回答一个“会改变决定”的问题

在 rebuttal 期最容易犯的错，是焦虑驱动地启动许多实验。开始之前先写：

~~~text
If result A, what claim changes?
If result B, what claim changes?
If neither result changes the decision, why run it now?
~~~

一个值得做的小检查应满足：

1. reviewer 的 concern 可被具体 outcome 区分；
2. protocol 可冻结，且不会因看结果再改设置；
3. 不使用 TEST 做 model selection；
4. 不需要偷偷改变方法形成新 contribution；
5. 结果无论正负都能诚实报告；
6. 能在 rebuttal 政策、页数与时间内被正确解释。

CVPR 2026 的 rebuttal 限一页、需保持匿名、不得用外部链接绕过内容限制；官方政策也明确不应要求 substantial additional experiments，作者尤其不应在 rebuttal 中塞入未被具体请求的新 contribution 或大量新结果。因此 rebuttal 的核心仍是消除误读、定位证据和处理决定相关的 concern，而不是临时重做一篇论文。

## 第七层：当 reviewers 互相矛盾时，不要“选对自己有利的人”

常见冲突包括：

- R1 认为方法过于复杂，R2 认为机制不足；
- R1 要更多 baseline，R3 认为实验已经过多但主线不清；
- 一人认为贡献是物理先验，一人认为贡献只是工程集成。

这类矛盾提供了诊断信息。先找共同的 latent concern：

~~~text
表面矛盾：太复杂 vs 机制不足
共同根因：模块—约束—证据对应关系没有写清
统一动作：删去无关结构描述，补上必要性链和 matched control
~~~

回应时可分别编号，但修改论文要解决共同根因。不要写“Reviewer 2 agrees with us, so Reviewer 1 is wrong”；AC 需要的是对争议的综合判断，不是站队证词。

## 第八层：答辩比 rebuttal 多一层——现场检查你的推理是否可迁移

书面 rebuttal 面对一组已知 comments；答辩委员可能沿你的回答继续追问。一个稳健口头回答可以采用五步：

1. **先确认问题边界**：“您问的是跨相机泛化，还是当前相机内的材质泛化？”
2. **直接给结论**：“当前证据只支持后者。”
3. **给最小理由**：指出数据、protocol 与关键结果；
4. **说明边界**：哪些没有测，为什么不能外推；
5. **给可检验下一步**：需要何种独立数据或 intervention，而不是泛泛说“以后继续研究”。

不知道时可以说不知道，但要把未知结构化：

> 当前实验没有独立操纵该因素，因此无法区分 A 与 B。若要判断，需要固定训练数据和容量，只改变 cue correspondence，再看预定义 subgroup 的 paired effect。

这种回答比即兴猜一个机制更像研究者。

## 第九层：一张可直接使用的 response matrix

收到 reviews 后，先不要写 prose。先建表：

| ID | Concern | Claim | Type | Decision impact | Existing evidence | Action | New boundary |
|---|---|---|---|---:|---|---|---|
| R1.1 | split 可能泄漏 | overall gain | protocol | high | split manifest | clarify + exact counts | unchanged |
| R1.2 | 提升来自容量 | mechanism | mechanism | high | matched block | move evidence | “supports” not “proves” |
| R2.1 | 未测跨相机 | generalization | scope | high | none | narrow scope | current sensor only |
| R3.2 | 图 4 色标不清 | visual claim | expression | medium | raw figure config | clarify + revise caption | unchanged |

写作时按 impact 合并重复 concern，而不是按 reviewer 顺序机械复制。这样一页里可以用一次证据回答多人共同问题，也能避免对小修饰写半页、对协议风险只写一句。

## 🧪 最小可运行代码：给 concerns 排优先级，并审计回应是否闭环

下面只使用 Python 标准库。分数不是替代人的判断，而是防止篇幅被“容易回答但不影响决定”的问题占满。

~~~python
concerns = [
    {
        "id": "R1.1",
        "type": "protocol",
        "impact": 1.0,
        "gap": 0.8,
        "tractability": 0.9,
        "claim": "matched overall gain",
        "evidence": "split manifest + evaluator config",
        "action": "clarify",
        "boundary": "VAL, fixed mask and checkpoint rule",
    },
    {
        "id": "R2.2",
        "type": "mechanism",
        "impact": 0.9,
        "gap": 0.7,
        "tractability": 0.8,
        "claim": "gain comes from reliability fusion",
        "evidence": "matched-capacity control",
        "action": "move evidence + weaken wording",
        "boundary": "supports, not proves, the mechanism",
    },
    {
        "id": "R3.1",
        "type": "generalization",
        "impact": 0.8,
        "gap": 1.0,
        "tractability": 0.2,
        "claim": "cross-sensor generalization",
        "evidence": "",  # 当前没有独立证据
        "action": "narrow scope",
        "boundary": "current sensor and dataset only",
    },
]

lam = 0.6
for item in concerns:
    item["priority"] = item["impact"] * (
        lam * item["gap"] + (1 - lam) * item["tractability"]
    )

required = {"claim", "action", "boundary"}
for item in sorted(concerns, key=lambda x: x["priority"], reverse=True):
    missing = sorted(k for k in required if not item.get(k))
    # 若选择 clarify / move evidence，必须真的给出 evidence；scope 则可以没有新证据
    if item["action"] != "narrow scope" and not item.get("evidence"):
        missing.append("evidence")
    status = "READY" if not missing else f"MISSING {missing}"
    print(item["id"], round(item["priority"], 3), status)
~~~

注意第三条：没有 cross-sensor evidence 时，审计器不会强迫你伪造证据；它允许通过 `narrow scope` 闭环。回应质量不等于“每条都证明自己原来完全正确”，而等于 claim、evidence 与 boundary 再次一致。

## 🔗 与你的 CVPR / 偏振工作怎样连起来

对 polarization generation、PA estimation、SfP 与下游 geometry，review 阶段最应预先准备的是：

1. **Protocol card**：real / simulated 输入、split、mask、checkpoint selection、alignment、aggregation、evaluator 一页锁定。
2. **Claim ledger**：每条 abstract / conclusion claim 指向 table、figure、artifact 与 limitation。
3. **Control map**：generic-capacity、shuffled cue、matched budget、base-correct subset 和 worst scene 分别排除什么替代解释。
4. **Boundary card**：PSNR 不等于 geometry，normal 不等于 metric depth，VAL 选择不等于 TEST 证据；每条边界一句话说清。
5. **Negative-result folder**：失败 gate、无收益 subgroup 和旧路线保留 provenance；答辩时“试过但失败”只有在协议和结果可追溯时才是证据。
6. **No-splice rule**：不能从多个 checkpoint 分别挑 AoLP、DoLP、PSNR 的最好数字拼成一个不存在的模型。

当 reviewer 问“为什么不直接用 GT polarization？”时，先判断这是事实、协议还是 scope concern：若 normal RGB-only inference 根本没有 GT polarization 输入，就应恢复输入契约；若某项 ablation 使用 GT-derived cue，只能把它标为 oracle / diagnostic evidence，不能和正常 forward result 混表。

## 🎤 面试 / 答辩角度

**Q：reviewer 明显误读了论文，应该怎么回？** 先给精确位置和事实，再承认可见性问题并说明修改。证明对方“没读”不会自动帮助 AC 判断论文。

**Q：什么时候应该补实验，什么时候应该降 claim？** 能在冻结协议下用小检查区分决定相关的替代解释时补实验；若总体、传感器或任务根本不在当前设计覆盖内，就降 scope。

**Q：为什么 promise 不算回应？** 因为决策应基于当前可检查的 paper、rebuttal 与 evidence。camera-ready 承诺没有当前结果，不能降低 residual gap。

**Q：多个 reviewer 意见冲突怎么办？** 找共同的 latent concern，例如贡献定位或证据路径不清；分别回应事实，统一修复根因。

**Q：答辩遇到不知道的问题怎么办？** 明确当前证据不能区分什么，再给出最小可检验设计。边界清楚比即兴猜测更可信。

## 一句话总结

高质量 rebuttal 与答辩不是把每条质疑“顶回去”，而是把 concern 还原到 claim、evidence gap、decision impact 与 scope：已有证据就精确定位，事实错误就修正，可区分的替代解释就做最小 matched check，超出设计覆盖就收缩边界，最终让 paper、evidence 与结论重新一致。
