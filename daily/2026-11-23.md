# 2026-11-23 · 一张图、一句指令，怎样变成机器人动作：VLA 架构与 Action Tokenization

> 阶段 N · Robot Learning、VLA 与具身策略 ｜ 标签：Vision-Language-Action, VLA, multimodal Transformer, action tokenization, quantization, autoregressive policy, action chunk, proprioception, closed-loop control
> 主线：Vision-Language-Action（VLA）不是“让大语言模型顺便吐几个数字”，而是先定义严格的 observation / instruction / robot state / action contract，再把视觉、语言和可选的 proprioception 编码成 Transformer 可处理的表示，把连续控制量映射为 token 或连续 action head，最后在固定坐标系、控制频率和执行策略下闭环运行。Action token likelihood 只说明模型拟合了训练标签；真正的机器人能力还要由 rollout success、recovery、latency、safety 与跨场景泛化独立证明。

---

## 开篇：模型输出 `128 204 17 255`，机器人就会抓杯子了吗

给机器人一张相机图像和一句指令：

> “把桌上的蓝色杯子放进水槽。”

模型输出一串 token：

~~~text
128, 204, 17, 126, 131, 250, 255
~~~

它们可能分别代表末端执行器的 $x,y,z$ 位移、三个旋转增量和夹爪开合。但仅看 token，至少还有这些问题没有答案：

- 位移是在 world frame、camera frame 还是 end-effector frame 中定义？
- 数值表示 absolute pose、delta pose、velocity 还是 joint target？
- 一次输出执行 $20\ \mathrm{ms}$、$100\ \mathrm{ms}$，还是一整段轨迹？
- `255` 是动作量化后的最大值，还是特殊的 terminate token？
- 图像拍摄与 proprioception 是否同步？
- 模型下一步会重新看图，还是把整段动作 open-loop 执行到底？

所以 VLA 的真正数据流不是一句含混的“图文输入，动作输出”，而是：

~~~text
camera / depth / history + language instruction + robot state
→ modality encoder 与 token / feature projection
→ multimodal Transformer
→ action representation（discrete tokens 或 continuous head）
→ de-tokenize / de-normalize
→ controller 与 safety layer
→ robot/environment 产生新 observation
→ 再次决策
~~~

今天要逐层拆开的，就是这条链。

## 第一层：先把 VLA 的输入输出合同写完整

在时刻 $t$，把策略输入写成 context：

$$
\mathbf c_t
=
\left(
\mathbf I_{t-L+1:t},
\mathbf u,
\mathbf s_{t-L+1:t},
\mathbf m
\right).
$$

每个符号的含义是：

- $\mathbf I_{t-L+1:t}$：最近 $L$ 帧视觉观测，可以来自单目、多相机、RGB-D 等；
- $\mathbf u$：自然语言 instruction；
- $\mathbf s_{t-L+1:t}$：可选的 proprioceptive state，例如 joint angle、end-effector pose、gripper state；
- $\mathbf m$：embodiment / action metadata，例如机器人类型、控制模式、坐标系与频率。

策略输出可以是单步动作：

$$
\mathbf a_t
=
(\Delta x_t,\Delta y_t,\Delta z_t,
\Delta r_t,\Delta p_t,\Delta y^{\text{yaw}}_t,g_t),
$$

也可以是长度为 $H$ 的 action chunk：

$$
\mathbf A_t
=
(\mathbf a_t,\mathbf a_{t+1},\ldots,\mathbf a_{t+H-1}).
$$

这里 $g_t$ 是 gripper command；$H$ 是一次预测覆盖的未来步数。注意 $y$ 既常被用作空间坐标，也可能表示 yaw，因此论文和代码中最好写成明确的 $\Delta y$ 与 $\Delta\psi$，不要靠上下文猜。

仅有向量长度还不够。一个可复现的 action contract 至少要记录：

| 接口 | 必须固定的内容 |
|---|---|
| 语义 | absolute / delta / velocity / torque / joint target |
| 坐标 | world / base / camera / end-effector frame |
| 单位 | meter、radian、normalized value、binary gripper |
| 时间 | control frequency、prediction horizon、execution horizon |
| 边界 | per-dimension range、clipping、dead zone |
| 同步 | image、language、state、action timestamp 对齐 |
| 安全 | workspace、collision、force、speed、termination rule |

如果不同数据集的第一个维度一个表示 base-frame $\Delta x$，另一个表示 joint-1 angle，直接拼接训练不会产生“跨 embodiment 泛化”，只会制造 label collision。

## 第二层：图像、语言和 Proprioception 怎样进入 Transformer

Transformer 接收的是一列向量，不会天然理解“这部分是图像，那部分是关节角”。各模态必须先被变成共同维度的 token。

### 1. Vision tokens

图像 $\mathbf I_t\in\mathbb R^{H_I\times W_I\times 3}$ 可以被切成 patch，经 ViT 类 encoder 得到：

$$
\mathbf V_t
=
(\mathbf v_{t,1},\ldots,\mathbf v_{t,N_v}),
\qquad
\mathbf v_{t,i}\in\mathbb R^d.
$$

$N_v$ 是视觉 token 数，$d$ 是 Transformer hidden dimension。若有多个相机或多帧历史，还要加入 camera ID、time ID 或位置编码，否则模型难以区分“左腕相机当前帧”和“头部相机上一帧”。

视觉 encoder 的职责是提取 object、texture、spatial layout 等信息，但 image embedding 本身并不保证 metric 3D、遮挡关系或可达性正确。VLA 可以利用 pretrained visual semantics，却仍可能把“识别出杯子”与“末端能安全到达杯子”混为一谈。

### 2. Language tokens

tokenizer 把 instruction $\mathbf u$ 分成离散 token：

$$
(w_1,w_2,\ldots,w_{N_l}),
$$

再查 embedding table 得到 $\mathbf l_j\in\mathbb R^d$。语言提供 task、target、relation 和约束，例如：

~~~text
pick [target: blue cup]
place [relation: inside]
[anchor: sink]
[constraint: keep upright]
~~~

但语言相似度只解决“指令在说什么”的一部分。它不能单独决定目标 instance、当前 robot frame 下的位置、可抓区域或 collision-free trajectory。

### 3. Proprioceptive tokens

若策略使用 robot state，可先归一化，再通过 MLP 投影：

$$
\mathbf p_t
=
\mathrm{MLP}\!\left(
\frac{\mathbf s_t-\boldsymbol\mu_s}{\boldsymbol\sigma_s+\epsilon}
\right)
\in\mathbb R^d.
$$

为什么 image 里已经看见机械臂，还需要 proprioception？因为遮挡、视角和图像分辨率可能无法精确给出 joint state、gripper force 或 controller 内部状态。相反，只有 proprioception 又看不到外部物体和接触后果。

不是所有 VLA 都使用完全相同的输入。正确说法是：VLA 架构提供把 vision、language 以及按任务需要加入的 state / history 组合起来的接口；不能把某个模型的输入配置说成整个类别的定义。

### 4. 序列拼接与 Attention

一种抽象写法是：

$$
\mathbf Z_t^{(0)}
=
[\mathbf L;\mathbf V_{t-L+1:t};\mathbf P_{t-L+1:t};\mathbf Q],
$$

其中 $\mathbf L$、$\mathbf V$、$\mathbf P$ 分别是语言、视觉与 proprioception token，$\mathbf Q$ 是用于读取动作的 query / action placeholder。第 $\ell$ 层 self-attention 为：

$$
\mathrm{Attention}(\mathbf Q,\mathbf K,\mathbf V)
=
\mathrm{softmax}\!\left(
\frac{\mathbf Q\mathbf K^\top}{\sqrt{d_k}}+\mathbf M
\right)\mathbf V.
$$

$\mathbf M$ 是 attention mask。它决定哪些 token 可以看见哪些 token：

- context token 通常可以彼此融合；
- 自回归 action token 只能看见之前的 action token；
- 若预测整个 chunk，mask 还决定未来动作之间怎样建立依赖。

所以“同一个 Transformer”不等于“所有信息自动融合正确”。token ordering、modality embedding、mask、history window 与 readout 位置都是架构合同的一部分。

## 第三层：连续动作为什么要变成 Token

大部分机器人控制量是连续数。若复用语言模型的 next-token prediction 接口，一个常见办法是把每个 action dimension 量化成离散 bin。

设某一维连续动作 $a$ 的有效范围为 $[l,h]$，共有 $K$ 个 bin。先裁剪并归一化：

$$
z
=
\mathrm{clip}\!\left(
\frac{a-l}{h-l},0,1
\right).
$$

再得到 bin index：

$$
k
=
\min(K-1,\lfloor Kz\rfloor),
\qquad k\in\{0,\ldots,K-1\}.
$$

解码时使用 bin center：

$$
\hat a
=
l+\frac{k+\tfrac12}{K}(h-l).
$$

对没有被 clipping 的 $a$，bin width 为：

$$
\Delta=\frac{h-l}{K},
$$

最大量化误差满足：

$$
|a-\hat a|\le \frac{\Delta}{2}
=\frac{h-l}{2K}.
$$

这解释了三个工程事实：

1. **range 太宽，分辨率就粗。** 同样 256 个 bin，$[-1,1]$ 比 $[-0.05,0.05]$ 的绝对步长大 20 倍。
2. **range 太窄，会产生 clipping。** 超出训练分位范围的动作全部压到边缘 token，误差不再受半个 bin 控制。
3. **各维要分别归一化。** 平移、旋转和夹爪不应共享一个物理范围；binary gripper 也未必适合假装成 256 级连续量。

RT-1 将各动作维离散为 256 个 bin。RT-2 进一步把动作表示成可由 vision-language model 生成的 token。OpenVLA 采用类似的离散动作接口，并以训练数据中各维的低、高分位范围降低极端 outlier 对分辨率的破坏。这里的“256”是架构选择，不是机器人控制的自然常数。

## 第四层：训练目标到底在优化什么

把一个时刻的 $D$ 维动作编码为 token 序列：

$$
\mathbf k_t=(k_{t,1},\ldots,k_{t,D}).
$$

若预测 $H$ 步 chunk，序列总长度为 $L_a=HD$。自回归策略把联合概率分解为：

$$
p_\theta(\mathbf k_t\mid\mathbf c_t)
=
\prod_{j=1}^{L_a}
p_\theta(k_{t,j}\mid\mathbf c_t,k_{t,<j}).
$$

对应的 teacher-forced cross-entropy 是：

$$
\mathcal L_{\mathrm{token}}
=
-\sum_{j=1}^{L_a}
\log p_\theta(k^*_{t,j}\mid\mathbf c_t,k^*_{t,<j}),
$$

其中 $k^*$ 是 demonstration 中的 ground-truth token。

这与上一篇 Behavior Cloning 完全接上：action tokenization 改变了 label representation，训练本质仍是在 demonstration distribution 上做 maximum likelihood。

### Teacher forcing 的缝隙

训练第 $j$ 个 token 时，模型看见真实前缀 $k^*_{<j}$；部署时，它看见自己生成的 $\hat k_{<j}$。如果第一个平移 token 就错了，后续旋转和夹爪 token 的条件也会改变。

而且 token 序列中的误差还嵌套在更大的环境闭环里：

~~~text
token error
→ decoded action error
→ robot pose / contact 改变
→ next image 与 state 改变
→ context 离开 demonstration support
→ 后续动作更难
~~~

因此 action-token perplexity 低，并不等于 rollout 稳定。

### 为什么 token 顺序会有影响

若顺序是：

~~~text
dx → dy → dz → roll → pitch → yaw → gripper
~~~

那么 gripper 可以条件化在所有 pose token 上，而 `dx` 不能看见同一步的 `gripper`。也可以并行预测各维，降低 latency，但会弱化显式的 intra-action dependency。没有一种排序对所有控制任务天然最优；需要同时报告准确性、延迟和闭环结果。

## 第五层：Action Chunk 为什么既像加速，也像承诺未来

单步策略每次看一帧、输出一个动作，反馈最及时，但若大模型推理慢于控制周期，机器人会停顿。Action chunk 一次输出未来 $H$ 步：

$$
\hat{\mathbf A}_t
=
(\hat{\mathbf a}_t,\ldots,\hat{\mathbf a}_{t+H-1}).
$$

它有三个直接好处：

- 一次 inference 摊销到多步动作，降低平均推理成本；
- 连续动作在同一预测中联合生成，更容易保持短期平滑与协调；
- 对 bimanual 或接触动作，可表达“先靠近、再闭合、再抬起”的局部结构。

但 chunk 越长，策略对未来的承诺也越长。第 1 步接触结果稍有不同，第 12 步可能已不适合当前真实状态。

因此要区分：

- **prediction horizon $H$**：一次预测多少步；
- **execution horizon $H_e$**：真正执行多少步后重新观察；
- **receding-horizon execution**：通常令 $H_e<H$，执行前缀后用新观测重规划。

这与 Model Predictive Control 的思想相似：保留短期计划的连贯性，但不把模型第一次想象的未来当成已经发生的事实。

Action chunk 还会把 token 长度扩展到 $HD$。若 $H=16,D=7$，朴素标量 tokenization 需要生成 112 个 token。于是控制频率不仅受参数量影响，也受 decoding steps、视觉编码缓存、网络传输和 controller handoff 影响。

## 第六层：三类 VLA 接口，不要被一个名字揉成一团

### RT-1：为真实机器人控制设计的 Transformer Policy

RT-1 把图像与 instruction 融合成紧凑 token，再由 Transformer 输出离散化动作。它的重要贡献不只是“用了 Transformer”，还包括真实多任务 robot data、固定 action specification 和 closed-loop evaluation。

### RT-2：把动作接入 Vision-Language Model 的 Token 空间

RT-2 的关键配方是把 robotic action 表达成 token，并把 web-scale vision-language data 与 robot trajectory co-finetuning。这样预训练语义知识可能帮助理解 novel object、symbol 或语言组合。

但迁移的是可利用的 visual-language representation，不是凭空获得的 contact dynamics。模型知道“石头可当锤子”，不代表它已知道当前夹爪如何稳定抓住这块石头。

### OpenVLA：开放权重与可适配的 VLA

OpenVLA 以 pretrained vision-language backbone 接动作预测，在多 embodiment robot data 上训练，并开放模型、代码与适配路径。它让研究者可以检查 action tokenizer、fine-tuning 和 evaluation，而不只看到演示视频。

这三者共同展示了一条路线：复用视觉—语言预训练，再用 robot trajectories 把表示接到动作。但它们的 encoder、token arrangement、training mixture、action space 与 deployment frequency 不相同，不能只用“都是 VLA”就做不加控制的成绩比较。

## 第七层：Token Accuracy 为什么不能替代 Control Success

设 ground-truth token 为 $k^*$，预测 token 为 $\hat k$。Exact token accuracy 检查 $\hat k=k^*$，但控制价值还依赖至少五层映射：

$$
\text{token}
\rightarrow
\text{continuous action}
\rightarrow
\text{robot motion}
\rightarrow
\text{contact / scene change}
\rightarrow
\text{task outcome}.
$$

### 情况 A：token 错了，动作仍可接受

相邻 bin 的两个 token 不相等，但 decoded action 只差 $0.2\ \mathrm{mm}$，任务可能完全不受影响。

### 情况 B：token 对了，任务仍失败

demonstration 中相同动作在当前物体位置、摩擦或相机延迟下不再合适；token accuracy 无法发现 context shift。

### 情况 C：大部分 token 对了，关键 token 错了

轨迹前 99 个平移动作都正确，最后一个 gripper close 或 terminate 错误，task success 仍为 0。

### 情况 D：平均成功率不错，安全边界仍不可接受

策略可能在常见桌面上成功，却在透明物体、儿童靠近、通信延迟或 force spike 时失败。平均 success 不能替代 safety endpoint 与 worst-group 报告。

所以评估至少分四层：

| 层级 | 典型指标 | 能证明什么 |
|---|---|---|
| 表示层 | token NLL、token accuracy、decoded L1/L2 | 拟合 action label 的程度 |
| 局部控制层 | tracking error、latency、smoothness、constraint violation | controller 能否执行模型输出 |
| 闭环任务层 | success、completion time、intervention、recovery | rollout 是否完成任务 |
| 泛化与安全层 | unseen object/task/scene/embodiment、failure subgroup、collision/force | 主张的适用边界 |

## 第八层：最小可运行代码——量化、解码与误差边界

下面只用 Python 标准库，把三维连续动作映射到 token，再解码并核对误差。

~~~python
from dataclasses import dataclass
from math import floor


@dataclass(frozen=True)
class ActionDim:
    name: str
    low: float
    high: float
    bins: int = 256

    def encode(self, value: float) -> int:
        clipped = min(max(value, self.low), self.high)
        z = (clipped - self.low) / (self.high - self.low)
        return min(self.bins - 1, floor(z * self.bins))

    def decode(self, token: int) -> float:
        if not 0 <= token < self.bins:
            raise ValueError(f"invalid token: {token}")
        return self.low + (token + 0.5) * (self.high - self.low) / self.bins

    @property
    def in_range_error_bound(self) -> float:
        return (self.high - self.low) / (2 * self.bins)


specs = [
    ActionDim("dx_m", -0.05, 0.05),
    ActionDim("dy_m", -0.05, 0.05),
    ActionDim("yaw_rad", -0.25, 0.25),
]
action = [0.013, -0.021, 0.08]

tokens = [spec.encode(value) for spec, value in zip(specs, action)]
decoded = [spec.decode(token) for spec, token in zip(specs, tokens)]

for spec, value, token, recovered in zip(specs, action, tokens, decoded):
    error = abs(value - recovered)
    print(
        f"{spec.name:8s} value={value:+.6f} token={token:3d} "
        f"decoded={recovered:+.6f} error={error:.6f} "
        f"bound={spec.in_range_error_bound:.6f}"
    )
~~~

预期输出类似：

~~~text
dx_m     value=+0.013000 token=161 decoded=+0.013086 error=0.000086 bound=0.000195
dy_m     value=-0.021000 token= 74 decoded=-0.020898 error=0.000102 bound=0.000195
yaw_rad  value=+0.080000 token=168 decoded=+0.079102 error=0.000898 bound=0.000977
~~~

这段代码验证的是 **in-range scalar quantization**，不是策略能力。若动作超过 `[low, high]`，clipping error 可以远大于表中的 bound；若坐标系或单位错了，即使 encode / decode 完全可逆，机器人仍会朝错误方向运动。

## 第九层：常见失败模式

### 1. 用全局 Min/Max 被 Outlier 拉宽范围

少数异常控制值会让大多数正常动作挤进很少的 bin。使用 robust quantile 能改善常见区间分辨率，但也必须报告 tail clipping rate。

### 2. 把所有维度都当作同一种连续量

平移、旋转、夹爪、terminate 和 mode switch 具有不同 topology 与语义。角度还可能有周期性；$-\pi$ 与 $\pi$ 在数值上远，物理方向却相同。

### 3. 忘记控制频率

同样的 $\Delta x=1\ \mathrm{cm}$，10 Hz 与 50 Hz 下对应完全不同的速度和轨迹。跨数据集混合前必须把 action 与 time base 一起对齐。

### 4. 只在 Demonstration Frame 上评估

teacher-forced token accuracy 没有测 learner-induced state、recovery、contact perturbation 与 accumulated latency。

### 5. 把语言预训练迁移说成物理技能迁移

web knowledge 可能改善 object / concept / instruction understanding；physical control 仍依赖 robot data、embodiment calibration、controller 和 closed-loop evidence。

### 6. 让 Safety Filter 掩盖 Policy Failure

safety layer 很必要，但论文应分别报告 raw proposal violation、filter intervention 与最终 outcome。否则“没有碰撞”可能只是外部系统不断拒绝危险动作，并不表示 policy 学会了安全控制。

## 第十层：与你的 CVPR / 偏振三维研究怎么连接

VLA 与偏振三维重建不是直接等价的问题，但它提供了一个很有用的接口观念：**新模态的价值必须从输入合同一直追到闭环结果。**

若把 polarization、normal、depth uncertainty 或 3D Gaussian map 交给 embodied policy，需要逐层回答：

1. **Measurement contract**：偏振角、相机、曝光、时间是否标定与同步？
2. **Representation contract**：输入 raw analyzer images、Stokes、DoLP/AoLP、normal，还是带 uncertainty 的 geometry token？
3. **Fusion contract**：新 token 在哪里进入，是否被 visibility / validity mask 与 reliability weighting 约束？
4. **Action contract**：策略输出在哪个 frame，是否真的依赖更准确的 surface / normal？
5. **Matched control**：RGB-only 与 RGB+polarization 是否冻结 robot data、capacity、action space、训练步与 controller？
6. **Mechanism check**：shuffle polarization、wrong calibration、same-RGB counterfactual 后，优势是否按预期消失？
7. **Independent endpoint**：除了 token loss，还要看 grasp pose error、contact stability、task success、intervention 与 safety subgroup。

即使 RGB+polarization 的 action NLL 更低，也不能直接声称 polarization 改善了三维几何；可能只是它提供了与训练场景相关的 material cue。先独立验证 geometry，再验证它是否改变 action decision，最后才讨论机制。

## 面试角度：高频追问

### Q1：为什么 VLA 要把连续动作离散成 token？

为了复用成熟的 autoregressive Transformer / language-model training interface，让 vision-language context 与 action 在统一序列中建模。代价是 quantization error、序列长度、decoding latency，以及 action topology 被简单词表表示时的结构损失。

### Q2：256 个 bin 越多越好吗？

不是。更多 bin 降低 in-range quantization error，却让每类样本更稀、分类更难，也不能修复 range、frame、latency 或数据覆盖问题。最优粒度取决于 controller tolerance 与数据量。

### Q3：Action chunk 和 autoregressive decoding 的关系是什么？

chunk 定义一次预测多少未来动作；autoregressive 定义这些动作 token 的联合分布如何分解。可以 autoregressively 生成 chunk，也可以用 parallel continuous head 或 generative head 一次生成。

### Q4：为什么 token accuracy 高，机器人仍会失败？

因为 token metric 位于 demonstration distribution 的表示层；部署还经过 de-tokenization、controller、contact dynamics 和 learner-induced observation。相邻 token 误差可能无害，关键 gripper token 的一次错误也可能让整段任务失败。

### Q5：怎样公平比较两个 VLA？

至少冻结或明确报告 robot data、instruction set、camera / state input、action definition、frequency、chunk / execution horizon、controller、latency budget、evaluation initial states 与 safety filter；同时给 open-loop fit 和 closed-loop success / failure subgroup。

## 一张可复用的 VLA 十六问卡

1. Observation 包含哪些相机、历史与 state？
2. 各模态是否时间同步？
3. Language instruction 怎样切分、是否有歧义？
4. Proprioception 在什么 frame / unit？
5. Vision / language / state 在哪里融合？
6. Attention mask 允许哪些 token 互相看见？
7. Action 是 absolute、delta、velocity 还是 torque？
8. 每个维度的 range 与 normalization 来自哪里？
9. 连续量怎样 quantize / dequantize？
10. 角度、gripper、terminate 怎样特殊处理？
11. Prediction horizon 与 execution horizon 各是多少？
12. 推理、通信、controller 的真实 latency 多大？
13. 训练是 teacher forcing 还是包含 learner rollout？
14. Safety layer 拦截了多少 proposal？
15. Open-loop metric 与 closed-loop endpoint 是否分开？
16. Unseen task / scene / object / embodiment 的 scope 是什么？

## 一句话总结

VLA 把 vision、language 与按任务需要加入的 proprioception 编码为 Transformer context，再把机器人连续动作通过归一化、量化、token 序列或 action head 表达出来；自回归 cross-entropy 学到的是 demonstration 上的 action-token likelihood，action chunk 则在推理效率、短期协调和反馈新鲜度之间做权衡。真正的具身能力不能由 token accuracy 代替，而要沿“token → continuous command → controller → contact / scene change → task outcome”逐层验证，并冻结 frame、unit、frequency、horizon、latency 与 safety contract。
