# 2026-11-17 · 地图不能只会“记住”：Continual / Open-world 3D Memory 怎样面对变化、未知与遗忘

> 阶段 M · 开放词汇三维语义、场景图与空间智能 ｜ 标签：continual 3D mapping, open-world memory, change detection, object persistence, unknown rejection, Bayesian filtering, provenance, forgetting, lifelong robotics, embodied AI
> 主线：长期三维记忆不是把每一帧无限追加到硬盘，而是维护一组会随证据更新的世界假设：新 observation 要判断是旧物体、新物体、变化还是感知错误；unknown 要被保留而不是强塞进已知类；旧记录要能衰减、归档和追溯，却不能因为一次漏检就被抹去。

## ⏮ 上篇回顾（30 秒）

M3 把语言拆成 target、anchor、relation、reference frame、goal region、action 与 constraint，再把语言 posterior 接到真实执行。

但它默认地图大体是“现在正确的”。现实中，机器人周一见过的杯子，周二可能被移走；新快递箱没有预定义类别；桌子换了位置；走廊施工后几何改变；模型升级后旧 feature 与新 feature 甚至不在同一个 embedding 版本里。

今天解决的问题是：地图怎样从一次性 reconstruction 变成一份**可更新、可遗忘、可追责的长期记忆**。

## 开篇：一周没进厨房，机器人应该相信谁

假设机器人上周建立了厨房地图：桌上有一个蓝杯，墙边有垃圾桶。今天重新进入时，它只看到桌面的一角，没有看到蓝杯；同时门边多了一个从未见过的纸箱。

四种草率做法都会错：

1. “没看到杯子，所以删除”——可能只是遮挡；
2. “旧地图说有杯子，所以继续相信”——杯子可能真的被拿走；
3. “纸箱最像柜子，所以标成柜子”——closed-set classifier 会强迫 unknown 变成 known；
4. “把今天的点云直接叠上去”——pose drift 会把同一面墙融合成两面墙。

长期记忆必须同时保存两件看似冲突的东西：

- **current belief**：此刻最可能是什么；
- **evidence history**：为什么这样认为，过去又曾是什么。

因此它不是一张静态地图，而是一套带时间、置信度和 provenance 的假设管理系统。

## 第一层：先区分 Observation、World State 与 Memory State

在时刻 $t$，传感器得到 observation

$$
o_t=(I_t,D_t,hat{\mathbf T}_t,\Sigma_t),
$$

其中：

- $I_t$ 是 RGB 或多模态图像；
- $D_t$ 是 depth / point cloud；
- $\hat{\mathbf T}_t$ 是估计的 camera pose；
- $\Sigma_t$ 表示 pose 与 measurement uncertainty。

真实世界状态记为 $x_t$，例如物体的存在、位置、形状和属性；机器人维护的 memory state 记为

$$
M_t=p(x_t\mid o_{1:t},a_{1:t-1}).
$$

这三者不能等同：

- observation 是“这一次看到了什么”；
- world state 是“世界此刻实际是什么”；
- memory state 是“结合历史证据后，系统相信什么”。

一次漏检只改变 belief，不直接改写世界；一次高置信 detection 也可能来自反光、错误 pose 或错误 association。

## 第二层：一个长期 Object Node 至少要存什么

对第 $j$ 个 persistent object，记忆节点可写成

$$
m_j=(I_j,p_j^e,\mathbf x_j,\mathbf P_j,
q_j(c),\mathbf f_j,\tau_j,V_j,\mathcal E_j).
$$

逐项解释：

- $I_j$：跨时间 identity；
- $p_j^e$：当前存在概率；
- $\mathbf x_j,\mathbf P_j$：位置状态与 covariance；
- $q_j(c)$：类别或开放词汇 posterior；
- $\mathbf f_j$：视觉—语言 feature；
- $\tau_j$：最后可靠观测时间；
- $V_j$：状态版本；
- $\mathcal E_j$：支持、反驳和修改该节点的 evidence ledger。

$\mathcal E_j$ 不应只有“最后一张图”。它至少要记录：frame、sensor、pose version、mask / point support、模型版本、时间、操作类型，以及这条证据是 `observed`、`inferred` 还是 `human-corrected`。

于是“杯子在桌上”不再只是一个布尔值，而是：

```text
entity: cup-17
state: probably-present, p=0.71
location: table-3, covariance=...
last-positive: 2026-11-16 18:42, frame-8031
last-missed: 2026-11-17 09:10, likely-occluded
semantic-source: VLM-v4 + human correction
geometry-source: RGB-D fusion, pose-graph-v12
```

这才是可更新也可审计的 memory。

## 第三层：一次“没看到”为什么不能直接删除——Bayesian Persistence

先只考虑一个物体是否仍存在。定义 Bernoulli 变量

$$
E_t\in\{0,1\},
$$

其中 $E_t=1$ 表示物体在时刻 $t$ 仍存在。上一时刻的 belief 为

$$
q_{t-1}=p(E_{t-1}=1\mid o_{1:t-1}).
$$

### 1. 先做时间预测

设物体从上一时刻存活到当前的概率为 $p_s$，暂不考虑原地重新出生，则

$$
q_t^-=p(E_t=1\mid o_{1:t-1})=p_s q_{t-1}.
$$

杯子、垃圾桶和临时快递箱的 $p_s$ 不应相同：固定设备通常 persistence 高，手持物品低。这里的语义先验只能影响 prior，不能替代观察。

### 2. 看到 detection 时更新

令 $z_t=1$ 表示传感器报告检测到该物体，并定义：

- $P_D=p(z_t=1\mid E_t=1)$：detection probability；
- $P_F=p(z_t=1\mid E_t=0)$：false-alarm probability。

由 Bayes rule：

$$
p(E_t=1\mid z_t=1)
=\frac{P_Dq_t^-}
{P_Dq_t^-+P_F(1-q_t^-)}.
$$

分母枚举了 detection 的两种来源：物体真的存在且被检出，或物体不存在但发生 false alarm。

### 3. 没看到时更新

若 $z_t=0$，则

$$
p(E_t=1\mid z_t=0)
=\frac{(1-P_D)q_t^-}
{(1-P_D)q_t^-+(1-P_F)(1-q_t^-)}.
$$

若目标区域被完全遮挡，$P_D$ 本来就低，那么 missed detection 几乎不该惩罚 existence belief；只有视野清楚、距离合适、传感器有效时，连续漏检才构成强反证。

所以正确问题不是“看没看见”，而是：**在本来应该看见的条件下，为什么仍没看见？**

## 最小可运行代码：Positive Evidence 与 Missed Detection 怎样改变记忆

```python
def update_existence(prior, detected, p_detect=0.85, p_false=0.05):
    if detected:
        likelihood_exists = p_detect
        likelihood_absent = p_false
    else:
        likelihood_exists = 1.0 - p_detect
        likelihood_absent = 1.0 - p_false

    numerator = likelihood_exists * prior
    denominator = numerator + likelihood_absent * (1.0 - prior)
    return numerator / denominator


belief = 0.90
survival = 0.98

sequence = [
    (False, 0.20, "missed but heavily occluded"),
    (False, 0.85, "missed in a clear view"),
    (False, 0.85, "missed again in a clear view"),
    (True, 0.85, "positive re-observation"),
]

for detected, p_detect, note in sequence:
    predicted = survival * belief
    belief = update_existence(
        predicted,
        detected=detected,
        p_detect=p_detect,
        p_false=0.05,
    )
    print(note, "->", round(belief, 3))
```

预期输出：

~~~text
missed but heavily occluded -> 0.863
missed in a clear view -> 0.464
missed again in a clear view -> 0.116
positive re-observation -> 0.686
~~~

第一次漏检发生在严重遮挡下，只让高 prior 小幅下降；两次 clear-view 漏检把 belief 明显压低；重新观察到目标后，belief 又恢复。实际系统还要把 data association 与 detection correlation 计入，不能把同一帧的多个相似 proposal 当成独立证据。

## 第四层：Open Vocabulary 不等于 Open World

M1 已经说明，text query 可以任意输入，不代表系统能识别 unknown。若候选类别集合为 $\mathcal C$，closed-set softmax 总满足

$$
\sum_{c\in\mathcal C}p(c\mid o)=1.
$$

即使输入是模型从未见过的物体，概率也必须被分给某个已知类别。于是“完全不认识”会被伪装成“最像其中某类”。

Open-world memory 至少需要四种状态：

1. `known-known`：类别和 instance 都有可靠证据；
2. `known-uncertain`：候选类已知，但 posterior 分散；
3. `unknown-object`：能分割并追踪为一个实体，但暂时没有可靠名称；
4. `outlier / artifact`：可能只是传感器噪声或错误 mask。

因此 unknown rejection 不能只用 top-1 label。可综合：

- 最大 text similarity 是否超过校准阈值；
- top-1 与 top-2 margin；
- embedding 是否远离训练 / memory support；
- 多视角是否稳定形成同一三维实体；
- 几何、运动和上下文是否自洽；
- `none-of-the-above` 是否经过 held-out unknown 校准。

对未知纸箱，系统可以先创建 `unknown-42`，保留多视角 crop、三维 support 和 provenance；以后用户说“这是路由器包装盒”时，再追加 label，而不是重造 identity。**名称可以后补，物理实体的历史不应因此丢失。**

## 第五层：Change Detection 必须先排除 Pose、Visibility 与 Association 错误

同一位置的几何不同，不一定是世界变了。它可能来自：

- camera pose drift；
- depth noise 或反光失效；
- 遮挡边界变化；
- object association 错配；
- map representation / model version 更新。

设旧地图预测 observation 的分布为 $p(o_t\mid H_0,M_{t-1})$，其中 $H_0$ 表示“世界未变”；变化假设为 $H_1$。可以比较 log-likelihood ratio：

$$
\Lambda_t
=\log p(o_t\mid H_1,M_{t-1})
-\log p(o_t\mid H_0,M_{t-1}).
$$

只有当 $\Lambda_t$ 足够大、且 pose / calibration / visibility 检查通过，才把差异升级为 change hypothesis。

变化还要分型：

- **appearance change**：包装换了但实体未换；
- **state change**：门从关到开；
- **pose change**：椅子被移动；
- **birth / removal**：新物体出现或旧物体消失；
- **structural change**：墙体、家具布局改变；
- **temporary occlusion**：世界没变，只是看不到。

若把所有差异都做 overwrite，系统会失去事件历史；若全部 append，又会让 current map 同时存在两把互相重叠的“同一把椅子”。合理接口是 current state + event log + archived state。

## 第六层：地图更新不是神经网络 Continual Learning 的同义词

“Continual”至少包含两层：

### A. Memory-level continual update

模型参数不变，只更新地图里的 node、geometry、feature、relation 和 provenance。这主要处理世界变化。

### B. Model-level continual learning

用新环境数据更新 detector、encoder 或 policy 参数。这会引入 catastrophic forgetting：模型学会新类别后，旧类别性能下降。

二者不能混写。地图更新正确，不代表模型学会了新概念；模型 fine-tune 成功，也不保证旧 map feature 与新 encoder 兼容。

若模型从版本 $v$ 升到 $v+1$，至少要说明：

- 旧 embedding 是否重算；
- 新旧 similarity 是否可比；
- calibration threshold 是否重估；
- replay / rehearsal 是否覆盖旧场景；
- 旧 task 与旧类别性能下降多少；
- provenance 是否记录模型版本。

否则“不断学习”可能只是让 memory silently drift。

## 第七层：遗忘不是 Delete，而是资源受限下的压缩决策

无限保存每帧 RGB-D、feature 和 intermediate result 会让 memory 线性增长。设第 $i$ 条证据的保留 utility 为

$$
U_i
=\alpha R_i
+\beta D_i
+\gamma T_i
+\eta Q_i
-\lambda C_i,
$$

其中：

- $R_i$：reliability；
- $D_i$：对已有视角的 diversity / novelty；
- $T_i$：对当前或未来 task 的价值；
- $Q_i$：对 disputed state 的诊断价值；
- $C_i$：storage、retrieval 与更新成本。

低 utility 不等于立即销毁。可以分层：

1. **active memory**：当前地图与高频对象；
2. **episodic memory**：关键事件、变化前后快照；
3. **consolidated memory**：从多帧压缩出的 object / place summary；
4. **archive**：低频原始证据，可慢速检索；
5. **tombstone**：对象已不在 current map，但保留 ID、删除理由和证据指针。

真正危险的是两种极端：从不忘记，导致陈旧信息压过新世界；无痕删除，导致系统无法解释自己为什么改口。

## 第八层：Loop Closure 与 Long-term Memory 要一起版本化

SLAM loop closure 可能把过去所有 pose 重新优化。若 object node 只存一份已经写死的 world coordinate，pose graph 更新后，几何、关系和 provenance 会互相错位。

因此长期地图要保留：

- observation 在 local sensor frame 的原始支持；
- 它依赖的 pose-graph version；
- object fusion 使用的 transformation；
- 关系边是在何种 frame 下计算；
- re-optimization 后哪些 derived quantity 需要重算。

这与数据库 migration 很像：更新坐标系统不是把一个数字改掉，而是要让所有下游派生状态知道上游版本发生了变化。

## 第九层：怎样评价 Lifelong 3D Memory，不让“最终地图好看”遮住历史错误

至少拆成六张成绩单。

### 1. Current-state accuracy

- 当前物体 existence、pose、geometry、relation；
- stale object rate 与 ghost map；
- 被移走物体多久才被正确降权；
- 暂时遮挡后能否恢复同一 identity。

### 2. Change detection

- change precision / recall 与 detection delay；
- appearance / pose / birth / removal / structural change 分组；
- pose drift、照明、遮挡造成的 false change；
- reversible 与 irreversible change 分开。

### 3. Open-world recognition

- known-class accuracy；
- unknown rejection AUROC / risk-coverage；
- unknown cluster purity；
- 新名称加入后能否 retroactive relabel；
- head / tail / novel domain / novel material 分组。

### 4. Identity 与历史连续性

- identity switch、fragmentation、duplicate；
- removed → reappeared 后是否恢复旧 ID；
- split / merge 的准确率和可撤销性；
- event chronology 是否与 GT 一致。

### 5. Forgetting 与资源

- memory size、update latency、query latency、energy；
- 压缩前后 retrieval / task performance；
- model continual learning 的 backward transfer / forgetting；
- archive 恢复是否可用。

### 6. Task 与可审计性

- object search、relocalization、navigation、manipulation；
- query 需要“现在在哪里”还是“昨天在哪里”；
- confidence 是否校准；
- 错误答案能否追到 observation、pose 和 model version。

测试必须按时间切分，而不是把同一时段随机拆成 train / test。最终帧准确，也不能证明系统在变化发生后的数小时里没有持续给出过期答案。

## 🔗 与我 CVPR / 偏振三维工作的连接

### 1. 偏振观测的 Validity 本身会随时间和视角变化

DoLP / AoLP 受 view、illumination、material、exposure 与 reflection mode 影响。长期 memory 不能把一次高 DoLP 写成永恒属性；应连同采集条件、sensor calibration 和 uncertainty 保存。

### 2. 几何改善应减少哪一种长期错误，要先命名

偏振若改善高光 / 低纹理表面的 normal 与 boundary，可能减少 object fragmentation、false change 或 data-association error。实验要冻结 pose、detector、memory policy 与 observation budget，分别测这三条路径，不能只展示更清楚的最终 map。

### 3. 新旧模型版本必须做 Feature Compatibility

若后续替换 polarization encoder，旧 node embedding 与新 observation 直接做 cosine similarity 可能失去意义。应重编码 anchor memory、学习 version adapter，或至少分版本检索并重新校准 threshold。

### 4. Independent Evidence 仍然不能缺席

长期 novel-view consistency 只能证明 appearance memory 可重放；物体存在、位置变化与 surface geometry 仍要靠时间标注 GT、独立 depth / scan、人工事件日志或真实 task endpoint 验证。

## 🔧 配菜 · 面试考点

### Q1：Open-vocabulary mapping 和 open-world mapping 有什么区别？

Open vocabulary 允许任意文本 query；open world 还要求识别 unknown、创建新实体、处理分布外输入、随时间更新类别和状态，并保留拒答与纠错接口。

### Q2：为什么一次 missed detection 不能删除物体？

漏检的证据强度依赖 visibility、distance、sensor validity 与 detector recall。Bayesian update 应用 $p(z=0\mid E=1)$ 与 $p(z=0\mid E=0)$ 比较，而不是把 `not detected` 等同于 `not present`。

### Q3：长期地图怎样避免 ghost object？

对 existence 做时间预测和基于 clear-view negative evidence 的更新；把 dormant、removed 与 occluded 分开；连续主动复查高风险位置，并报告 stale-object detection delay。

### Q4：Catastrophic forgetting 是地图删除吗？

不是。它通常指模型参数学习新任务后旧任务性能下降；地图层面的证据压缩 / 状态淘汰是 memory management。二者可能相互作用，但指标和修复方法不同。

### Q5：为什么 provenance 是长期 memory 的核心，而不是附加日志？

因为世界、pose graph、模型和标签都会变。没有来源与版本，就无法撤销错误融合、重算派生量、区分观察与推断，也无法解释系统为什么改变答案。

## 一张可复用的“Lifelong 3D Memory 二十问卡”

1. **Clock**：observation time、world time、update time 是否区分？
2. **Frame**：状态在哪个坐标系与 pose-graph version？
3. **Entity**：observation ID 与 persistent ID 是否分开？
4. **Existence**：物体存在概率怎样预测与更新？
5. **Visibility**：没看到时，本来是否应该看见？
6. **Association**：新观测是旧物体、新物体还是错误匹配？
7. **Unknown**：能否明确说 `unknown` / `none-of-the-above`？
8. **Novelty**：新类别与 sensor artifact 怎样区分？
9. **Change**：appearance、state、pose、birth、removal 是否分型？
10. **Drift**：pose / calibration / feature drift 是否先排除？
11. **Version**：model、embedding、map schema 是否记录版本？
12. **Update**：哪些字段 overwrite，哪些 append，哪些重新推导？
13. **Provenance**：每个结论能否追到原始 frame 和操作？
14. **Conflict**：新旧证据冲突时谁获得多大权重？
15. **Forgetting**：压缩依据是 recency、reliability、diversity 还是 task value？
16. **Archive**：删除后是否有 tombstone 与恢复路径？
17. **Calibration**：existence、unknown、change confidence 是否校准？
18. **Temporal split**：测试是否真正跨时间与跨变化？
19. **Resource**：memory、latency、energy 随时间怎样增长？
20. **Evidence**：当前状态、历史事件、模型学习与真实任务是否分开验收？

- [A Scene Language Model for Open-Vocabulary Scene Mapping — 2026](https://arxiv.org/abs/2609.21400)：探索用结构化文本作为 persistent scene state、通过 add / edit / remove 迭代维护地图，并以检索、定位和 memory footprint 检查压缩后的场景记忆。

## 一句话总结

Continual / Open-world 3D Memory 是对世界假设做时间化 Bayesian 管理：把 observation、world state 与 memory belief 分开，用 visibility-aware positive / negative evidence 更新 existence，用 unknown buffer 保留未命名实体，用 change hypothesis 区分真实变化与 pose / sensor drift，用版本和 provenance 保证可撤销与可重算，再在 active、episodic、consolidated 与 archive memory 间受控遗忘。它的目标不是“永远记得最多”，而是**在世界变化后仍知道现在该信什么，并能说明为什么**。
