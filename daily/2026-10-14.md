## ⏮ 上篇回顾（30 秒）

H2 把 Method 写成一条可失败的推导链：

~~~text
design gap → task constraint → mechanism → observable prediction → matched evidence
~~~

今天接最后一箭：证据已经做出来以后，怎样放进 Results，才不会让审稿人自己在十几张表和几十幅图里拼结论？

核心原则只有一句：

> **每个 display item 都应服务于一条明确主张；每条重要主张都应能在一次扫描中找到协议、比较、结果与边界。**

## 🧠 开篇：Results 不是实验仓库，而是论证界面

想象审稿人先不读正文，只按顺序看：

1. abstract 里的三条 claim；
2. Table 1 的粗体数字；
3. Figure 3 的可视化；
4. ablation table；
5. failure cases；
6. 各自 caption。

如果这条“扫描路径”已经能回答下面六问，论文的证据组织通常是清楚的：

- 比谁？
- 在什么数据、mask、split 与 protocol 下比？
- 比什么 outcome，方向是越大越好还是越小越好？
- 提升有多大，是否稳定？
- 改善发生在哪些区域，代价是什么？
- 哪些条件下不成立？

反过来，最常见的问题不是“实验太少”，而是证据散落：

- 主表混用不同输入、训练数据或 evaluator；
- 消融一次改了多个因素；
- qualitative 只展示最漂亮的样例；
- caption 只写“visual comparison”，不说颜色、裁剪、误差或选择规则；
- failure case 藏在 supplement，正文却声称普遍有效。

## 第一层：先把 claim 变成 evidence slot

对一条经验性主张，先写成

$$
C=(P,T,K,O,\Pi,S),
$$

其中：

- $P$：population，例如 HAMMER validation 中的真实偏振场景；
- $T$：treatment，即本文方法；
- $K$：comparison，例如相同 backbone、训练数据和预算下的 baseline；
- $O$：outcome，例如 angular error、PSNR、harm rate 或 latency；
- $\Pi$：protocol，包括 split、mask、对齐、聚合和 checkpoint selection；
- $S$：scope，结论允许覆盖到哪里。

然后为它分配一个 evidence slot：

| Claim 类型 | 首要 display | 必须补充的信息 | 不能单独证明 |
|---|---|---|---|
| Overall superiority | main table | matched protocol、effect、uncertainty、cost | 机制为何成立 |
| Module contribution | matched ablation | 单变量变化、容量/预算控制 | 真实因果机制 |
| Mechanism claim | intervention + subgroup figure | 可失败预测、cue 被破坏后的变化 | 超出干预范围的泛化 |
| Visual quality | qualitative figure | 同输入、同 crop、同色标、选择规则 | 总体统计优势 |
| Robustness / safety | subgroup + failure table | worst group、harm、coverage | 未观测环境中的绝对安全 |

这一步的价值是阻止“一张表负责所有故事”。Table 1 可以证明某协议下平均指标占优，但它不能同时证明模块使用了偏振物理、每个物体都改善、几何更准确且部署更安全。

## 第二层：主表先锁协议，再决定粗体

一个可信主表可以拆成四块：

~~~text
身份列：method / year / training data
能力列：input modality / extra supervision / pretraining
结果列：dataset × metric
代价列：parameters / FLOPs / latency / memory
~~~

比较公平性的最低检查是：被放在同一个视觉分组里的方法，是否真的共享关键协议。若方法 A 使用 real RGB，方法 B 使用 GT-derived simulation；或一个允许 scale alignment，另一个要求 metric prediction，就不应仅靠同一行数字制造“直接排名”。

主表中的粗体也不是装饰。先定义每个 cell 的 estimand。例如误差越小越好时：

$$
\mu_m=\mathbb E_{u\sim P}[e_m(u)],
$$

其中：

- $m$ 表示方法；
- $u$ 是独立 evaluation unit，例如 scene 或 object，而不一定是 pixel；
- $e_m(u)$ 是方法 $m$ 在单位 $u$ 上、按固定 mask 与 evaluator 算出的误差；
- $P$ 是论文声称覆盖的目标总体。

只有当不同方法的 $u$、mask、alignment 和 aggregation 一致时，$\mu_m$ 才能进入同一排名。否则“最佳”可能只是协议差异。

### 为什么 scene average 与 pixel average 不是一回事

假设第 $j$ 个 scene 有 $n_j$ 个有效像素，像素误差为 $e_{jk}$。

pixel-weighted mean 是

$$
\bar e_{\text{pixel}}
=\frac{\sum_{j=1}^{J}\sum_{k=1}^{n_j}e_{jk}}
{\sum_{j=1}^{J}n_j}.
$$

先定义每个 scene 的均值

$$
\bar e_j=\frac{1}{n_j}\sum_{k=1}^{n_j}e_{jk},
$$

把它代回前式：

$$
\bar e_{\text{pixel}}
=\sum_{j=1}^{J}
\frac{n_j}{\sum_{\ell=1}^{J}n_\ell}\bar e_j.
$$

所以 pixel average 实际给大 mask scene 更高权重。若 claim 是“对一个随机 scene 平均有效”，更匹配的是

$$
\bar e_{\text{scene}}
=\frac{1}{J}\sum_{j=1}^{J}\bar e_j.
$$

两者都可以合法，但回答的是不同问题。表头或 caption 必须说清 aggregation unit。

## 第三层：比较提升时，优先展示 paired effect

设同一 evaluation unit $i$ 上，本文方法误差为 $e_i^{(T)}$，baseline 误差为 $e_i^{(B)}$。对“越小越好”的指标，定义

$$
d_i=e_i^{(T)}-e_i^{(B)}.
$$

- $d_i<0$：本文方法改善；
- $d_i>0$：本文方法伤害；
- $d_i=0$：无变化。

平均配对差是

$$
\bar d=\frac{1}{N}\sum_{i=1}^{N}d_i.
$$

为什么不只分别报告两个 mean？因为 paired difference 消除了同一个 scene 对两种方法共同造成的难度波动。若某个透明物体对所有方法都很难，它会同时抬高 $e_i^{(T)}$ 与 $e_i^{(B)}$；先做差，可以更直接地估计“换方法”带来的变化。

样本方差为

$$
s_d^2=\frac{1}{N-1}\sum_{i=1}^{N}(d_i-\bar d)^2,
$$

平均差的标准误差为

$$
\operatorname{SE}(\bar d)=\frac{s_d}{\sqrt N}
=\sqrt{\frac{1}{N(N-1)}
\sum_{i=1}^{N}(d_i-\bar d)^2}.
$$

第二个等式只是把 $s_d^2$ 代入并开方。若 evaluation unit 近似独立、样本量足够，可用

$$
\bar d\pm1.96\,\operatorname{SE}(\bar d)
$$

给出近似 95% confidence interval。若 scene 数少、分布偏斜或层级复杂，更稳妥的是按真正独立的 scene / object 做 paired bootstrap，而不是把相关像素当成百万个独立样本。

主表不一定塞下所有区间，但至少应在正文、caption 或 supplement 清楚绑定：

~~~text
point estimate + uncertainty + unit + direction + protocol
~~~

只有 “+0.3” 而没有这些信息，读者不知道它是稳定收益、偶然波动，还是聚合方式制造的差异。

## 第四层：消融表不是“拆零件”，而是检验 Method 的可失败预测

matched ablation 要尽量只改变一个解释变量。以 reliability gate 为例：

| Arm | 容量 | 输入 | 训练预算 | 唯一变化 | 能回答什么 |
|---|---:|---|---:|---|---|
| Base | matched | RGB + pol | matched | 无 gate | 起点 |
| Generic | matched | RGB + pol | matched | 同容量 concat block | 增加容量是否足够 |
| Ours | matched | RGB + pol | matched | reliability gate | 结构是否比 generic replacement 更好 |
| Shuffled | matched | RGB + shuffled pol | matched | 打乱 cue 对应 | 优势是否依赖正确 cue |

最弱的消融是从 Base 一步跳到 Ours，因为结构、参数量、优化路径和信息流都变了。更有解释力的顺序是：

1. Base → Generic：控制额外容量；
2. Generic → Ours：比较特定 inductive bias；
3. Ours → Shuffled：破坏声称依赖的信息；
4. 按 cue quality 分层：检查 observable prediction。

如果 Method 声称“低可靠度区域会被抑制”，Results 就应展示 gate 与 held-out error 的关系、corruption intervention，以及低 DoLP / saturation 等预定义 subgroup。只报总体均值，仍然无法区分“机制正确”与“模型只是更大”。

## 第五层：qualitative figure 要把“好看”变成可核验观察

一张定性图至少要固定五件事：

1. **同输入**：每列来自同一 scene、view 与 frame；
2. **同显示**：相同 crop、分辨率、color map 和 value range；
3. **有参照**：GT、input cue 或 error map 至少提供一个可定位基准；
4. **有规则**：说明样例是随机、典型、按预定义 subgroup，还是 failure-driven selection；
5. **有边界**：图中现象只支持局部结构判断，不替代全数据统计。

对 normal / depth / polarization 任务，一个实用布局是：

~~~text
Input | Baseline | Ours | GT | Base error | Ours error
~~~

每一行再只讲一个现象，例如：

- row 1：物体边界；
- row 2：高光区域；
- row 3：低 DoLP；
- row 4：纹理弱但几何连续区域；
- row 5：失败案例。

不要把不同 crop 放到一起，却让读者误以为像素对应；也不要为每种方法自动归一化色条，否则视觉对比会失去共同尺度。

### 样例选择为什么也属于 protocol

如果从 1000 个场景中挑 4 个最漂亮的结果，figure 证明的是“存在成功案例”，不是“典型改善”。更稳妥的组合是：

- 1–2 个按固定 seed 随机抽样；
- 2–3 个预注册 subgroup 的代表；
- 1–2 个最大伤害或已知 failure mode。

把选择规则写进 caption 或 Methods，能显著降低 cherry-picking 的嫌疑。

## 第六层：failure case 不是自损，而是在标定 claim 的边界

失败图应回答三个不同问题：

1. **发生了什么**：哪些像素、scene 或材料退化？
2. **为什么可能发生**：输入缺信息、分布外、表示错误，还是 gate 决策失败？
3. **论文怎样收缩结论**：是平均有效但存在 harm，还是只在某个 observable condition 下有效？

可定义 harm rate：

$$
\operatorname{HR}_{\tau}
=\frac{1}{N}\sum_{i=1}^{N}
\mathbf 1[d_i>\tau],
$$

其中：

- $\mathbf 1[\cdot]$ 是条件成立时取 1、否则取 0 的 indicator；
- $d_i$ 仍是本文方法减 baseline 的误差差值；
- $\tau\ge0$ 是预先定义的 practically meaningful harm threshold。

当 $\tau=0$ 时，它统计任何退化；当 $\tau>0$ 时，它统计超过实际容忍度的伤害。平均 $\bar d<0$ 与 $\operatorname{HR}_\tau>0$ 可以同时成立：总体改善不代表每个单位都改善。

因此 Results 的完整安全叙事应同时放：

~~~text
mean benefit + uncertainty + harm rate + worst subgroup + representative failures
~~~

## 第七层：caption 是最小可执行说明，不是标题复述

好的 caption 至少包含六槽：

$$
K=(W,D,E,M,U,B),
$$

- $W$（what）：展示什么对象与比较；
- $D$（data）：dataset、split、sample selection；
- $E$（encoding）：颜色、线型、误差图、箭头分别表示什么；
- $M$（metric）：指标定义、方向与 aggregation；
- $U$（uncertainty）：error bar 或区间怎样计算、单位是什么；
- $B$（boundary）：图表允许得到的结论与不能外推的范围。

例如，不要只写：

> Figure 4. Qualitative comparison with prior methods.

可以写成：

> Figure 4. HAMMER VAL 上按固定 seed 随机选取的两个 scene，以及预定义 low-DoLP subgroup 中的两个 scene。各方法使用相同输入、crop 与 normal color encoding；右两列为相对同一 GT 和 valid mask 计算的 angular-error map，色条固定为 $0^\circ$–$30^\circ$。Ours 在物体边界与高光区域减少误差，但第二行透明区域仍失败；该图用于定位误差结构，不替代 Table 1 的总体统计。

这段 caption 即使脱离正文，也能被正确阅读。

## 第八层：按“结论依赖关系”排版，而不是按实验完成时间排版

推荐的 Results 扫描顺序是：

~~~text
R1 Evaluation contract
  ↓
R2 Main comparison: 是否总体占优
  ↓
R3 Matched ablation: 哪个设计贡献了什么
  ↓
R4 Mechanism / subgroup: 是否按推导的条件工作
  ↓
R5 Qualitative + failure: 改善和失败发生在哪里
  ↓
R6 Efficiency / limitations: 代价与边界
~~~

每节开头先给一句 claim，随后立即指向 display：

> Under the matched real-input protocol, Ours reduces scene-level angular error relative to the strongest baseline (Table 1).

接着再解释 effect、uncertainty、subgroup 和 exception。不要先逐行朗读数字，再把结论埋在段尾。

CVPR 2026 正文上限为八页且 figures / tables 计入页数，因此每个 display 都要承担清晰任务；supplement 可以放更多分析，但不能用来修补正文中缺失的核心协议或主结论证据。

## 🧪 最小可运行代码：从 paired results 生成证据摘要，并审计 display

下面只使用 Python 标准库。它计算 paired effect、近似 95% confidence interval、harm rate，并检查每个 display 是否覆盖必要槽位。

~~~python
import math

baseline = [12.4, 8.7, 15.1, 10.3, 9.5, 13.0]
ours =     [11.8, 8.5, 14.0, 10.6, 9.0, 12.1]

# 对“越小越好”的误差，负差值表示 Ours 更好
diff = [o - b for o, b in zip(ours, baseline)]
n = len(diff)
mean_diff = sum(diff) / n
sample_var = sum((d - mean_diff) ** 2 for d in diff) / (n - 1)
se = math.sqrt(sample_var / n)
ci95 = (mean_diff - 1.96 * se, mean_diff + 1.96 * se)

harm_threshold = 0.2
harm_rate = sum(d > harm_threshold for d in diff) / n

print("paired effect:", round(mean_diff, 3), "deg")
print("approx. 95% CI:", tuple(round(x, 3) for x in ci95))
print("harm rate:", round(harm_rate, 3))

displays = {
    "table_1": {
        "claim": "overall matched comparison",
        "population": "VAL scenes",
        "protocol": "same mask and evaluator",
        "effect": "paired scene-level difference",
        "uncertainty": "95% CI",
        "boundary": "real-input VAL only",
    },
    "figure_3": {
        "claim": "boundary improvement",
        "population": "predefined boundary subgroup",
        "protocol": "same crop and color scale",
        "effect": "error-map localization",
        "uncertainty": "",  # 故意留空，审计器应报错
        "boundary": "qualitative evidence only",
    },
}

required = {
    "claim", "population", "protocol",
    "effect", "uncertainty", "boundary",
}
for name, card in displays.items():
    missing = sorted(k for k in required if not card.get(k))
    print(name, "READY" if not missing else f"MISSING {missing}")
~~~

这组数据的平均 paired effect 为负，表示总体改善；但其中仍有一个单位超过 $0.2^\circ$ 的 harm threshold。代码刻意让 Figure 3 缺少 uncertainty 槽位，提醒你：定性现象可以定位错误，却不能冒充总体稳定性证据。

## 🔗 与你的 CVPR / 偏振工作怎样连起来

对 polarization generation、PA estimation、SfP 和下游 geometry，建议把 display 明确分工：

1. **Main table**：冻结 real / simulated 输入边界、split、mask、checkpoint selection 和 evaluator；不同证据来源不要合成一个不存在的“best model”。
2. **Matched ablation**：一次只改 representation、cue、fusion 或 refinement 中一个因素；参数量、训练预算和数据保持可比。
3. **Mechanism figure**：按 DoLP、饱和、高光、边界、材质等 observable condition 分层，检查收益是否符合 Method 的可失败预测。
4. **Qualitative panel**：真实 RGB、GT-derived simulation 与纯合成证据必须显式标注，不能靠相似视觉外观混为同一证据等级。
5. **Failure / harm panel**：展示 candidate 相对 base 的退化，尤其关注 base-correct subset、透明/高光材料和 worst scene。
6. **Geometry table**：PSNR 只能支持图像保真主张；法向或深度几何需要独立 GT、尺度、配准、mask 与 observable-area protocol。

最重要的是让 caption 带出 provenance：哪一个 checkpoint、哪份 prediction、哪版 mask 和 evaluator 生成该 display。图表是论文中的证据入口，不应与原始 artifact 失去连接。

## 🎤 面试角度

**Q：为什么只报 Ours 与 baseline 的两个均值不够？** 因为它隐藏了逐单位的配对结构、波动和 harm。paired difference 更直接估计替换方法的效果，并允许报告 uncertainty 与退化比例。

**Q：ablation 与 mechanism experiment 有什么区别？** ablation 说明组件与最终性能相关；mechanism experiment 还要破坏或操纵该组件声称使用的信息，并观察预先推导的行为变化。

**Q：qualitative figure 怎样避免 cherry-picking？** 预先写明选择规则，混合固定随机样例、预定义 subgroup 与最大伤害案例，并保持输入、crop、色标和 GT 一致。

**Q：为什么 caption 要写得近乎独立？** 因为审稿人与读者常先扫描 display；caption 若缺 protocol、encoding、metric direction 或边界，图表很容易被过度解释。

**Q：平均提升了，为什么还要放 failure case？** 因为平均效应与个体伤害可同时存在。failure case 帮助定位 scope、提出可检验原因，并防止论文把局部优势写成普遍保证。

## 一句话总结

Results 的任务不是把做过的实验全部陈列出来，而是把 claim 排成可扫描的证据路径：主表锁定 matched overall effect，消融隔离设计贡献，intervention 与 subgroup 检查机制，定性图定位现象，failure case 标定边界，caption 则把 protocol、encoding、uncertainty 与 scope 一起封装。
