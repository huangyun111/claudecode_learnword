# 2026-11-19 · 阶段 M 复盘：从“能贴标签”到“能回答、能行动、能改口”的空间智能

> 阶段 M · 开放词汇三维语义、场景图与空间智能 ｜ 标签：open-vocabulary 3D, object-centric mapping, 3D scene graph, language grounding, embodied instruction, open-world memory, provenance, uncertainty, spatial intelligence, independent evidence
> 主线：可查询空间智能不是在几何地图上再贴一层文本标签，而是让 geometry、semantic feature、persistent object、relation、language query 与 versioned memory 共享同一套坐标、时间、不确定性和证据来源；系统不仅要给答案，还要知道答案对应哪个实体、哪个时刻、哪份证据，以及何时应拒答、澄清或用新观测改口。

---

## 开篇：机器人昨天说“杯子在红椅子旁”，今天为什么不能照抄旧答案

想象机器人已经扫描过办公室。用户问：

> “把红椅子旁边那只杯子拿来。”

地图里确实存着一把红椅子和一只杯子，视觉—语言相似度也很高。可真实场景里可能同时发生：

- 杯子昨天被移动到会议室；
- 椅子仍在，但 pose graph 更新后坐标整体发生了修正；
- 地图里还有另一只同色杯子；
- `near` 在旧版本中成立，在当前版本中已经失效；
- 机器人能定位目标，却没有无碰撞、可抓取的路径；
- 用户说的“旁边”按其视角与机器人视角会指向不同区域。

若系统只做一次 text–feature similarity，它会自信地复述旧标签。真正的空间智能必须回答一串更难的问题：

1. 这条语言描述绑定的是哪个 **physical instance**？
2. 这个实体现在还存在吗，位置是什么，证据有多新？
3. `near` 在哪个 frame、尺度与时间区间成立？
4. 当前答案来自 observation、model inference，还是语言常识补全？
5. 若信息不足，应选目标、主动观察，还是先澄清？
6. 执行后，新的观测怎样反过来更新地图？

M1–M4 的关系就在这里：M1 让地图可被任意词查询，M2 让查询落到持续存在的 object 与 relation，M3 把语言结果变成可执行 region / action，M4 让这些状态在开放世界中随时间更新并保留 provenance。

## 第一层：先把“地图”从单一数组改写成有状态的 Belief

传统 occupancy map 可以近似写成每个位置是否被占据。阶段 M 需要更丰富的状态：

$$
\mathcal M_t=(\mathcal G_t,\mathcal F_t,\mathcal V_t,\mathcal E_t,\mathcal H_t),
$$

其中：

- $t$ 是当前时间；
- $\mathcal G_t$ 是 metric geometry，例如 point、mesh、Gaussian、free space 与相机 frame；
- $\mathcal F_t$ 是与三维 support 对齐的 open-vocabulary feature；
- $\mathcal V_t$ 是 persistent object node 集合；
- $\mathcal E_t$ 是 object relation 与层级结构；
- $\mathcal H_t$ 是 history / version / evidence ledger。

但 $\mathcal M_t$ 不是确定真值。给定截至时刻 $t$ 的观测

$$
\mathbf y_{1:t}=(\mathbf y_1,\ldots,\mathbf y_t),
$$

更准确的对象是 posterior belief：

$$
b_t(\mathcal M)=p(\mathcal M_t=\mathcal M\mid \mathbf y_{1:t}).
$$

这一步看似只是多写一个概率，实际改变了接口：

- geometry 有 pose / depth uncertainty；
- semantic feature 有 view、occlusion 与 prompt sensitivity；
- object identity 有 association uncertainty；
- relation 有 frame、尺度和有效时间；
- existence 有 survival、detection 与 missed-detection probability；
- history 记录“为什么相信”，而不只保存最后结果。

所以一张高级地图不是“世界数据库”，而是 **关于世界的、可更新的带证据 belief**。

## 第二层：M1 把二维语义放回三维，但 Feature 不是 Object

设相机内参为 $\mathbf K$，像素齐次坐标为 $\tilde{\mathbf p}=(u,v,1)^\top$，该像素深度为 $z$。在 camera frame 中：

$$
\mathbf X_c=z\mathbf K^{-1}\tilde{\mathbf p}.
$$

若 $\mathbf R_{cw}$、$\mathbf t_{cw}$ 把 camera coordinate 转到 world coordinate，则

$$
\mathbf X_w=\mathbf R_{cw}\mathbf X_c+\mathbf t_{cw}.
$$

这一步把 pixel feature $\mathbf z_i$ 附着到三维位置。对同一三维 support 的多次观测，用可靠性 $w_i\ge 0$ 融合：

$$
\mathbf f
=\arg\min_{\mathbf h}\sum_i w_i\|\mathbf h-\mathbf z_i\|_2^2.
$$

对 $\mathbf h$ 求导并令其为零：

$$
2\sum_i w_i(\mathbf h-\mathbf z_i)=0,
$$

因此

$$
\mathbf f=\frac{\sum_i w_i\mathbf z_i}{\sum_i w_i}.
$$

给定文本 embedding $\mathbf e_q$，可用 cosine similarity 查询：

$$
s(\mathbf f,\mathbf e_q)
=\frac{\mathbf f^\top\mathbf e_q}
{\|\mathbf f\|_2\|\mathbf e_q\|_2}.
$$

这让地图能响应训练时未固定的词，但仍只回答“哪片 support 与文本相似”。它没有自动解决：

- 多片 support 是否属于同一个物体；
- 两把相同椅子谁是昨天见到的那一把；
- feature bleeding 是否跨越几何边界；
- 新词是有效开放类别，还是不应强配的 unknown；
- 高 similarity 是否意味着几何位置正确。

因此 M1 的输出是 queryable feature field，不是完整世界模型。

## 第三层：M2 把 Support 组织成 Persistent Object 与 Probabilistic Relation

在第 $t$ 帧中检测到 observation instance $o_i^t$，地图中已有 object node $v_j$。二者是否同一实体，可写成 association cost：

$$
C_{ij}
=\lambda_g C_{ij}^{\text{geom}}
+\lambda_p C_{ij}^{\text{pos}}
+\lambda_f C_{ij}^{\text{feat}}
+\lambda_s C_{ij}^{\text{sem}}
+\lambda_\tau C_{ij}^{\text{time}}.
$$

各项分别检查 support overlap、位置及 covariance、feature distance、semantic compatibility 与时间连续性。接着求一对一 global assignment：

$$
\min_{x_{ij}\in\{0,1\}}
\sum_{i,j}C_{ij}x_{ij},
$$

满足

$$
\sum_jx_{ij}\le 1,\qquad
\sum_ix_{ij}\le 1.
$$

$x_{ij}=1$ 表示 observation $i$ 与 node $j$ 匹配。约束避免多个 observation 同时贪心占用同一 node，但它不会修复错误的 pose、mask 或 feature。

Object node 至少应保存：

~~~text
node_id
geometry support + covariance
open-vocabulary feature + uncertainty
existence probability
last observed time
version
evidence / provenance
~~~

Relation edge 也不应只是 `left_of=true`。更完整的 edge 是：

~~~text
(source, relation, target, frame, parameters,
 confidence, valid_time, provenance)
~~~

这样 `near` 可以带尺度，`left_of` 可以带 reference frame，`on` 可以带 support geometry，旧关系也能在场景变化后失效而不是永久残留。

## 第四层：M3 把自然语言拆成 Joint Grounding，而不是只检索一个词

把指令 $u$ 解析成：

$$
q=(z_t,z_a,r,F,G,A,C),
$$

其中：

- $z_t$ 是 target；
- $z_a$ 是 anchor；
- $r$ 是 relation；
- $F$ 是 reference frame；
- $G$ 是 goal region；
- $A$ 是 action sequence；
- $C$ 是 reachability、collision、safety 等 constraint。

候选 target $j$ 与 anchor $k$ 的 posterior 可以分解为：

$$
p(j,k\mid u,\mathcal M_t)
\propto
\phi_t(j)\phi_a(k)\phi_r(j,k;F)\phi_c(j,k).
$$

这里 $\phi_t$ 与 $\phi_a$ 是 target / anchor 语义证据，$\phi_r$ 是关系证据，$\phi_c$ 是 context、visibility、reachability 等证据。

取 log 后：

$$
S_{jk}=\log\phi_t(j)+\log\phi_a(k)
+\log\phi_r(j,k;F)+\log\phi_c(j,k).
$$

再归一化：

$$
p_{jk}=\frac{\exp(S_{jk}/\tau)}
{\sum_{m,n}\exp(S_{mn}/\tau)}.
$$

关键不是 softmax 本身，而是每个 factor 对应不同可诊断接口：semantic 错、anchor 错、frame 错、geometry 错与 path 不可达，不应都被压缩成“模型没听懂”。

Grounding 后还必须把 object 转成可执行区域：

$$
G=G_{\text{free}}
\cap G_{\text{visible}}
\cap G_{\text{reachable}}
\cap G_{\text{safe}}.
$$

找到桌子中心不等于导航目标有效；文本回答正确也不等于真实任务完成。

## 第五层：M4 给 Query 加上 Time、Existence 与 Provenance

设 object 在上一时刻存在的概率为

$$
r_{t-1}=P(E_{t-1}=1\mid \mathbf y_{1:t-1}).
$$

若存活概率为 $P_S$，新生概率为 $P_B$，prediction 为：

$$
r_t^-
=P_Sr_{t-1}+P_B(1-r_{t-1}).
$$

若当前检测到该 object，且 detection probability 为 $P_D$、false positive probability 为 $P_F$，Bayes update 为：

$$
r_t^+
=\frac{P_Dr_t^-}
{P_Dr_t^-+P_F(1-r_t^-)}.
$$

若没有检测到：

$$
r_t^+
=\frac{(1-P_D)r_t^-}
{(1-P_D)r_t^-+(1-P_F)(1-r_t^-)}.
$$

但这里的 $P_D$ 必须依赖 visibility。物体被墙挡住时，missed detection 几乎不是“物体消失”的证据；相机正对原位置、照明正常、传感器工作时，miss 才更有意义。

于是一次当前查询不只看 semantic 与 relation，还应加入：

$$
S_{jk}^{\text{current}}
=S_{jk}
+\log r_j
+\log r_k
+\log \psi_{\text{fresh}}(j,k)
+\log \psi_{\text{prov}}(j,k),
$$

其中：

- $r_j,r_k$ 是 target / anchor existence probability；
- $\psi_{\text{fresh}}$ 衡量证据时效；
- $\psi_{\text{prov}}$ 衡量 evidence source 与 query 所需证据是否匹配。

这解释了为什么“昨天高置信看见”不能直接等于“今天仍在那里”。

## 第六层：把 M1–M4 接成一条可回写的空间智能闭环

完整链条可以写成：

~~~text
RGB / depth / polarization / pose / time
                  ↓
geometry + visibility + calibrated frame
                  ↓
pixel feature → 3D feature fusion
                  ↓
observation instance → persistent object identity
                  ↓
object node + probabilistic relation + provenance
                  ↓
language parse → joint grounding posterior
                  ↓
current existence + freshness + feasibility
                  ↓
answer / clarify / active observe / act / reject
                  ↓
new observation + execution outcome
                  ↓
versioned map update, relation repair, memory audit
~~~

注意最后一条回边：如果执行到旧位置却没有发现杯子，这不是单纯 controller failure。它可能触发：

- 重新检查 visibility 与 sensor health；
- 降低旧 object 的 existence probability；
- 搜索 unknown / moved-object hypothesis；
- 让旧 relation 进入 `stale`；
- 主动选择能最大区分“移动 / 遮挡 / 漏检”的新视角；
- 更新 query answer，并保留为什么改口的证据链。

“能改口”不是不可靠，而是开放世界系统诚实更新 belief 的表现。

## 最小可运行代码：为什么最高语义分不能直接成为当前答案

下面用 standard library 模拟三只候选杯子。最终 score 同时考虑 semantic、与红椅子的 relation、existence、freshness 与 reachability。

```python
import math

candidates = [
    # name, semantic, relation, existence, age_hours, reachable
    ("old_cup", 0.97, 0.95, 0.35, 48.0, 1.00),
    ("current_cup", 0.90, 0.88, 0.92, 1.0, 0.95),
    ("blocked_cup", 0.94, 0.91, 0.90, 0.5, 0.00),
]

semantic_only = max(candidates, key=lambda item: item[1])[0]
print("semantic-only:", semantic_only)

feasible = []
for name, semantic, relation, existence, age, reachable in candidates:
    if reachable <= 0.0:
        continue
    freshness = math.exp(-age / 24.0)
    score = sum(math.log(value + 1e-12) for value in (
        semantic, relation, existence, freshness, reachable
    ))
    feasible.append((name, score))

normalizer = sum(math.exp(score) for _, score in feasible)
for name, score in sorted(feasible, key=lambda item: item[1], reverse=True):
    posterior = math.exp(score) / normalizer
    print(name, "posterior=", round(posterior, 3))
```

预期输出：

~~~text
semantic-only: old_cup
current_cup posterior= 0.938
old_cup posterior= 0.062
~~~

`old_cup` 的语义和旧 relation 都最好，但 evidence 太旧、当前 existence 低；`blocked_cup` 看似匹配，却没有可执行 goal。这个 toy posterior 不是通用公式，却清楚说明：**query score 必须匹配问题本身**。问“地图里曾看见过什么”与问“现在去哪里拿”需要不同的 time / feasibility evidence。

## 第七层：Evaluation 必须沿接口拆开，不能只报一个问答 Accuracy

### 1. Geometry / Frame

- pose、depth、surface accuracy 与 completeness；
- visibility、free space、boundary 与 calibration；
- frozen global alignment，避免每个结果单独对齐掩盖漂移。

### 2. Semantic / Open Vocabulary

- seen / unseen / tail query；
- prompt stability、synonym 与 paraphrase；
- unknown / none-of-the-above rejection；
- feature bleeding 与 geometry boundary subgroup。

### 3. Object / Graph

- instance association、identity switch；
- split / merge / duplicate；
- node existence calibration；
- relation accuracy、frame / time validity 与 edge calibration。

### 4. Language / Interaction

- target / anchor / relation / frame accuracy；
- same-class distractor 与 ambiguous expression；
- clarification efficiency；
- answer calibration 与 selective prediction。

### 5. Memory / Change

- current-state accuracy；
- change detection delay 与 false alarm；
- moved / occluded / disappeared / newly appeared 分组；
- forgetting、memory footprint、version / provenance completeness。

### 6. Embodied Task

- goal-region validity、path / grasp / place success；
- intervention、time、energy 与 safety；
- real-world execution，不由 planner 自报完成；
- failure attribution 与 recovery success。

一个 QA 数字可能被语言常识拉高，即使 geometry 错；一个 task success 也可能靠碰巧探索成功，即使 grounding 错。只有分层成绩单才能证明改进发生在哪个接口。

## 🔗 与我 CVPR / 偏振三维工作的连接

### 1. 偏振更可能先改善 Geometry Host，而不是直接创造“空间智能”

偏振 cue 若改善高光、弱纹理或边界处的 normal / surface support，可能进一步减少 feature bleeding、instance merge 和 relation error。但完整因果链应是：

~~~text
polarization observation
→ geometry / boundary / visibility improvement
→ object support / relation improvement
→ grounding / task endpoint improvement
~~~

任何一条箭头都要单独验证，不能由最终漂亮案例倒推。

### 2. 冻结下游模块，才能定位收益

比较 RGB 与 RGB+polarization 时，应尽量冻结 text encoder、query set、object association rule、planner、action budget 与 evaluation split。先看 independent geometry，再看 object / relation，最后看 grounding / task；否则 capacity 和 exposure 变化会混入结论。

### 3. 物理属性要带 Measurement Condition

DoLP、AoLP、specular cue 可以帮助区分材质或 reflection mode，但会随视角、照明和表面法向变化。它们应作为带 view / light / calibration / time 的 observation，而不是永久写入 object node 的无条件属性。

### 4. Language Completion 与 Physical Evidence 必须分账

LLM 可以推断“杯子通常在桌上”，却不能把这个 prior 伪装成已观测 relation。Map 中至少区分 `observed`、`estimated`、`inferred` 与 `predicted`，论文中也应分别报告。

## 🔧 配菜 · 面试考点

### Q1：Open-vocabulary 3D map 与 open-world 3D map 有什么区别？

Open vocabulary 强调推理时可用未固定的文本词查询；open world 还要求处理 unknown、新增 / 消失实体、domain shift、持续更新与遗忘。前者不自动包含后者。

### Q2：为什么 dense feature map 不能替代 object-centric map？

Dense feature 适合局部检索，却缺少 persistent identity、object-level state、relation、version 与事件历史。长期任务需要知道“是不是同一个实体”，不只是“这里像不像某个词”。

### Q3：Scene graph 为什么不能只存确定 label？

Relation 依赖 geometry、frame、尺度、时间和 evidence；场景还会变化。确定 label 会隐藏 uncertainty，并让旧关系永久污染当前答案。

### Q4：系统什么时候应主动观察，什么时候应询问用户？

若不确定性来自 visibility / existence，新视角可能有效；若来自语言 reference frame 或候选描述歧义，询问更有效。应比较两种行动的 expected decision benefit、cost 与 risk。

### Q5：怎样证明一个 embodied agent 真在使用三维地图？

使用 same-class distractor、relation swap、anchor removal、pose perturbation、stale-memory、moved-object、shuffled graph 与 absent-target controls；检查答案和行动是否按空间证据变化，并分开评 geometry、grounding 与 execution。

## 一张可复用的“空间智能二十四问卡”

1. **Frame**：所有 observation 是否在明确坐标系中？
2. **Time**：状态对应哪个时刻和有效区间？
3. **Geometry**：surface / free space / boundary 是否独立验证？
4. **Visibility**：没看见是消失、遮挡还是 sensor failure？
5. **Feature**：二维 feature 如何放回三维？
6. **Weight**：融合权重反映了哪些可靠性？
7. **Vocabulary**：query 真开放，还是预设类别换了名字？
8. **Unknown**：none-of-the-above 能否拒绝？
9. **Instance**：support 怎样成为 object？
10. **Identity**：跨帧怎样避免 switch / merge / split？
11. **Relation**：edge 是否带 frame、scale、time 与 uncertainty？
12. **Provenance**：结论来自哪次 observation 或哪条 inference？
13. **Parse**：target、anchor、attribute、relation、action 是否分开？
14. **Grounding**：semantic、relation、context 怎样联合？
15. **Region**：object 怎样转成 free / visible / reachable / safe goal？
16. **Existence**：当前存在概率怎样更新？
17. **Freshness**：旧证据如何衰减或失效？
18. **Change**：object change 与 pose / feature / sensor drift 怎样区分？
19. **Clarify**：语言歧义何时值得询问？
20. **Observe**：状态歧义何时值得主动采集？
21. **Act**：动作成功由什么物理 observation 验证？
22. **Repair**：失败怎样回写 node、edge 与 memory？
23. **Evidence**：geometry、semantics、memory 与 task 是否分层验收？
24. **Claim**：最终措辞是否没有超过最弱证据接口？

## 可靠来源

- [OpenScene: 3D Scene Understanding with Open Vocabularies](https://arxiv.org/abs/2211.15654)：展示如何把多视角二维 feature 融合到三维点，并支持任意文本对 category、material、affordance 与 room type 的查询。
- [ConceptFusion: Open-set Multimodal 3D Mapping](https://concept-fusion.github.io/)：把 pixel-aligned open-set feature 与 SLAM / multi-view fusion 结合，说明 queryable feature map 的能力与几何依赖。
- [3D Scene Graph: A Structure for Unified Semantics, 3D Space, and Camera — ICCV 2019](https://openaccess.thecvf.com/content_ICCV_2019/html/Armeni_3D_Scene_Graph_A_Structure_for_Unified_Semantics_3D_Space_ICCV_2019_paper.html)：把 object、room、camera、attribute 与 relation 放入统一层级三维表示。
- [ConceptGraphs: Open-Vocabulary 3D Scene Graphs for Perception and Planning](https://arxiv.org/abs/2309.16650)：以 object instance、multi-view association、caption 与 relation 构建开放词汇 object graph，并展示 perception / planning 接口。
- [ReferIt3D — ECCV 2020](https://referit3d.github.io/)：以同类多实例中的 referential language 为核心，适合检查 target、anchor 与视角相关空间表达。
- [Visual Language Maps for Robot Navigation — ICRA 2023](https://vlmaps.github.io/)：把开放词汇 feature map 与 spatial-language navigation goal 对接，同时提示 localization 与真实 obstacle-aware execution 的区别。
- [3D-Mem: 3D Scene Memory for Embodied Exploration and Reasoning — CVPR 2025](https://openaccess.thecvf.com/content/CVPR2025/html/Yang_3D-Mem_3D_Scene_Memory_for_Embodied_Exploration_and_Reasoning_CVPR_2025_paper.html)：用 object-centered memory snapshot 支持长期探索、检索与 embodied reasoning，并评价 memory efficiency。
- [OVI-MAP: Open-Vocabulary Instance-Semantic Mapping — CVPR 2026](https://openaccess.thecvf.com/content/CVPR2026/html/Deng_OVI-MAP_Open-Vocabulary_Instance-Semantic_Mapping_CVPR_2026_paper.html)：把 incremental instance map 与按需开放词汇语义提取分开，展示 identity、online update 与 memory efficiency 的接口。

## 一句话总结

阶段 M 把空间智能组织成一条可回写的 belief chain：先在明确 frame / time 中恢复 geometry，把视觉—语言 feature 可靠地放回三维，再通过 data association 建立 persistent object 与 probabilistic relation，用 joint grounding 将语言绑定到实体、区域和行动，并以 existence、freshness、version 与 provenance 面对开放世界变化；只有 geometry、semantics、identity、relation、memory、interaction 与真实任务分别通过独立验证，地图才从“能贴标签”升级为“能回答、能行动、能拒绝，也能依据新证据改口”。
