## 🧠 开篇：0.3° 提升为什么可能是四种完全不同的结论

假设新模块把 normal MAngE 从 12.1° 降到 11.8°。你可能立刻写：“我们的方法提升了 0.3°。”但同一个数字至少可能对应四种情况：

1. 同一批图像逐对比较，绝大多数样本略有改善；
2. 两个方法用了不同 mask，0.3° 来自评估协议变化；
3. 总均值改善，但低 DoLP 场景大量受损；
4. checkpoint 是看过 test set 后挑的，0.3° 已包含 selection bias。

所以研究不是“训练 → 抄一个最好数字”，而是一条首尾相接的证据链：

```text
问题与主张
  → estimand（究竟想估计什么）
  → matched design（只改变被研究因素）
  → split / protocol（结果能推广到谁）
  → per-unit evidence（保留逐单位差异）
  → uncertainty（有限样本下有多稳）
  → decision rule（多大才值得采用）
  → provenance / artifacts（别人怎样重算）
```

前一环没有定义清楚，后一环算得再精确也可能只是在精确回答错误的问题。

## 第一层：先把自然语言主张翻译成 estimand

研究问题可以先写成五元组：

$$
Q=(P,T,C,O,\Pi).
$$

- $P$（population）：希望结论覆盖的对象，例如“corrected HAMMER 中未见过的 scene”；
- $T$（treatment）：引入的新模块或训练策略；
- $C$（control）：除被研究因素外尽量匹配的对照；
- $O$（outcome）：固定 evaluator 下的 per-image MAngE；
- $\Pi$（protocol）：split、mask、alignment、checkpoint selection 与 aggregation 规则。

设第 $i$ 个评估单位在 treatment 下的误差为 $Y_i(T)$，在 control 下的误差为 $Y_i(C)$。真正关心的总体平均效应是

$$
\Delta
=\mathbb E_{i\sim P}\left[Y_i(T)-Y_i(C)\right].
$$

这里约定误差越小越好，因此 $\Delta<0$ 表示 treatment 改善。这个式子不只是数学装饰：它逼你回答“评估单位是什么”“对哪个总体取期望”“两个结果是否能逐对对应”。

如果一张物体被拍了 20 帧，而你声称泛化到“新物体”，那么独立单位就不应偷换成 frame。否则同一物体的 20 帧会被当成 20 份独立证据，区间看起来虚假地变窄。

## 第二层：matched control 负责隔离变化来源

实际观测到的差异可以直觉地拆成

$$
\widehat\Delta_{\text{obs}}
=\Delta_{\text{target}}
+B_{\text{nuisance}}
+B_{\text{selection}}
+B_{\text{measurement}}.
$$

- $\Delta_{\text{target}}$：目标模块真正带来的变化；
- $B_{\text{nuisance}}$：capacity、训练预算、seed、预处理等共同变化造成的偏差；
- $B_{\text{selection}}$：反复看 validation/test 后挑配置造成的偏差；
- $B_{\text{measurement}}$：mask、resize、单位、alignment 或 evaluator 变化造成的偏差。

matched control 的目的不是让实验“看起来公平”，而是让后三项尽可能接近零。若新模型多了参数，就增加 matched-capacity control；若怀疑网络根本没有使用 polarization cue，就增加 shuffled-cue negative control；若选择过 checkpoint，就把选择规则冻结在 validation set，再只评一次 held-out test。

因此 baseline、ablation 和 negative control 回答的问题不同：

| 证据 | 回答什么 | 不能单独证明什么 |
|---|---|---|
| baseline comparison | 完整系统是否优于参照 | 改善由哪个部件造成 |
| ablation | 去掉部件后性能怎样变化 | 部件为何有效、是否有混杂 |
| matched control | 目标因素之外尽量相同后是否仍改善 | 所有真实部署条件都成立 |
| negative control | 无关或破坏后的信息是否也产生“提升” | treatment 已有正向机制 |

## 第三层：从逐单位差异推到总体效应

对 $n$ 个成对单位，先计算

$$
d_i=Y_i(T)-Y_i(C),
$$

再取 paired mean：

$$
\widehat\Delta=\bar d=\frac1n\sum_{i=1}^{n}d_i.
$$

为什么不只比较两个独立均值？把 $d_i$ 展开后，两个方法在同一 scene 上共同承受的难度会相减掉。设

$$
Y_i(T)=\mu_T+s_i+\epsilon_{i,T},\qquad
Y_i(C)=\mu_C+s_i+\epsilon_{i,C},
$$

$s_i$ 是第 $i$ 个 scene 的共同难度。相减得到

$$
d_i=(\mu_T-\mu_C)+(\epsilon_{i,T}-\epsilon_{i,C}),
$$

共同项 $s_i$ 消失，因此 paired estimator 通常比不配对比较更稳定。

样本差异的方差为

$$
s_d^2=\frac1{n-1}\sum_{i=1}^{n}(d_i-\bar d)^2,
$$

若单位近似独立，均值标准误约为

$$
\operatorname{SE}(\bar d)=\frac{s_d}{\sqrt n}.
$$

但如果 frame 嵌套在 scene 内，就应按 scene 重采样或先求 scene-level effect；不能把相关 frame 当成独立样本。bootstrap 也必须在 claim 对应的 split unit 上抽样。

## 第四层：区间不替你做决策

设 $[L,U]$ 是 $\Delta$ 的置信区间，$\tau>0$ 是采用新方法所需的最小实际改善。由于误差越低越好，可以写出三档规则：

$$
\text{decision}=
\begin{cases}
\text{practically supported}, & U<-\tau,\\
\text{direction supported only}, & U<0\ \text{且}\ U\ge-\tau,\\
\text{improvement uncertain}, & U\ge0.
\end{cases}
$$

第一档意味着即使取区间中最不乐观的一端，改善仍超过实际门槛。第二档说明方向较稳定，但还不足以改变工程决策。第三档表示现有数据仍允许“没有改善甚至变差”。

$\tau$ 不能在看到结果后临时设置。它应来自测量噪声、标注误差、部署收益、额外算力、延迟和维护成本。若多出 40% 推理时间只换来 0.03°，即使样本足够多使 $p$-value 很小，也未必值得采用。

均值之外还要报告 harm：

$$
h=\frac1n\sum_{i=1}^{n}\mathbb 1(d_i>0).
$$

$h$ 是 treatment 变差的单位比例。总体改善与 harm rate 可以同时很高，因此还要按 scene、材质、DoLP、sensor 等预定义 subgroup 检查 effect 和 worst case。

## 第五层：把论文表格变成可遍历的 provenance graph

一项结果的身份可以写成

$$
R=(C,D,S,H,E),
$$

其中 $C$ 是 code revision，$D$ 是 data revision，$S$ 是 split，$H$ 是 hyperparameters，$E$ 是 evaluator revision。若任一项改变，结果身份就发生变化。

但只有 run identity 还不够。真正可审计的 artifact 应建立如下映射：

```text
paper claim
  ↕ claim map
table cell / figure panel
  ↕ generation command
machine-readable result + per-unit errors
  ↕ evaluator config/hash
prediction + checkpoint
  ↕ inference/train config
code revision + data manifest + split
```

这张图允许你从论文的一格数字向下追到原始证据，也允许数据或 evaluator 修正后向上找到所有受影响的主张。可复现不是“文件很多”，而是这条路径不断裂。

## 🧪 最小可运行代码：按 scene 汇总、bootstrap，再输出决策记录

下面只用 Python 标准库。每个 scene 有若干 frame，代码先计算 scene-level paired effect，再在 scene 层 bootstrap，最后把决策规则和输入摘要写进可追溯记录。

```python
import hashlib
import json
import random
import statistics

rows = [
    # scene, control MAngE, treatment MAngE
    ("A", 12.4, 11.8), ("A", 12.0, 11.7),
    ("B", 10.8, 10.5), ("B", 11.1, 10.9),
    ("C", 14.1, 13.6), ("C", 13.7, 13.9),
    ("D", 9.7, 9.3),  ("D", 10.0, 9.6),
]

by_scene = {}
for scene, control, treatment in rows:
    by_scene.setdefault(scene, []).append(treatment - control)

scene_effect = {
    scene: statistics.fmean(values)
    for scene, values in by_scene.items()
}
effects = list(scene_effect.values())
point = statistics.fmean(effects)
harm_rate = statistics.fmean(x > 0 for x in effects)

rng = random.Random(7)
boot = []
for _ in range(10000):
    sample = [effects[rng.randrange(len(effects))] for _ in effects]
    boot.append(statistics.fmean(sample))
boot.sort()
interval = [boot[int(0.025 * len(boot))],
            boot[int(0.975 * len(boot))]]

tau = 0.20  # pre-registered minimum practical improvement, degrees
if interval[1] < -tau:
    decision = "practically_supported"
elif interval[1] < 0:
    decision = "direction_supported_only"
else:
    decision = "improvement_uncertain"

protocol = (
    "unit=scene|metric=MAngE_deg|lower_is_better|"
    "mask=valid_gt|aggregation=scene_then_macro"
)
record = {
    "estimand": "mean scene-level paired MAngE difference",
    "scene_effect_deg": scene_effect,
    "point_estimate_deg": point,
    "bootstrap_95_deg": interval,
    "scene_harm_rate": harm_rate,
    "minimum_practical_improvement_deg": tau,
    "decision": decision,
    "protocol_sha256": hashlib.sha256(
        protocol.encode("utf-8")
    ).hexdigest(),
}
print(json.dumps(record, ensure_ascii=False, indent=2))
```

这段示例故意不输出神奇的“显著 / 不显著”二元结论。它保留 point estimate、interval、harm、practical threshold 与 protocol identity，让读者能看见结论怎样形成。

## 🔗 与你的 CVPR / 偏振工作怎样连起来

可以把一项偏振方法的证据包按下面顺序检查：

1. **Claim**：是生成质量更好、PA 估计更准，还是 downstream normal 更准？三者不能互换。
2. **Population**：corrected HAMMER、自建真实数据与 GT-derived simulation 分开定义，不能把不同总体混成一个“综合提升”。
3. **Matched design**：新增 PA/R fusion 时，保留相同 backbone、预算、输入与 evaluator，并做 component swap、shuffled cue 或 matched-capacity control。
4. **Unit**：若声称跨 scene 泛化，就按 scene split，并在 scene 层计算 paired effect 与 bootstrap。
5. **Decision**：同时看 MAngE effect、harm/worst group、推理成本和预先定义的 practical threshold。
6. **Traceability**：每个表格单元格绑定 checkpoint、config、label layout、mask、evaluator hash、per-image errors 与生成命令；未运行的格子明确写 pending。

这能阻止两类常见越界：模拟结果不能冒充真实 RGB 证据；训练或推理“已经启动”也不能冒充最终指标已经 verified。

## 🎤 面试角度

**Q：为什么 paired evaluation 往往比比较两个均值更有力？** 因为同一评估单位的共同难度在差值中抵消，估计直接对准方法间变化；前提是配对关系正确，且不把相关子样本当成独立单位。

**Q：置信区间完全小于 0，为什么仍可能不上线？** 因为它只支持改善方向，不保证改善超过工程门槛。还要比较 practical threshold、harm、延迟、算力与维护成本。

**Q：ablation 能证明模块的因果作用吗？** 只能在对照足够匹配、选择规则冻结且不存在其他共同变化时提供更强的机制证据；若去掉模块同时改变 capacity 或训练稳定性，还需要 matched control 和 negative control。

**Q：reproducibility 的核心是什么？** 不是压缩包大小，而是 claim、结果、命令、evaluator、模型、代码与数据之间存在可执行、可校验的双向映射。

## 一句话总结

一条完整研究证据链，要先用 estimand 说明“想知道什么”，再用 matched design 和正确 split 说明“差异来自哪里、能推广给谁”，用 paired effect、uncertainty、harm 与 practical threshold 说明“结果有多稳、是否值得行动”，最后用 provenance graph 说明“这句话怎样被重新计算和推翻”。
