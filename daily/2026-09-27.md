> 你看到的提升，究竟来自论文声称的机制，还是来自更多参数、更长训练、不同数据、挑过的 checkpoint，甚至测试集被反复用于决策？

## 🧭 开篇：实验不是“把能跑的组合都跑一遍”

设你提出一个 reliability-guided refinement module。完整模型比原系统的 mean angular error 低了 $0.8^\circ$。至少存在六种解释：

1. 新模块真的利用 reliability signal 选择了值得修正的位置；
2. 新模型只是参数更多；
3. 新模型训练步数更多，或获得了额外监督；
4. 结果来自某个幸运 seed；
5. checkpoint、阈值或数据清洗规则看过测试集后才决定；
6. 平均指标改善，但困难材质、边界或低 DoLP 子组受损。

所以一个数字只是一条 **observation**。只有比较对象、控制变量和评估协议共同成立，它才进入证据链。

```text
research question
      ↓
hypothesis + mechanism
      ↓
estimand：到底想估计哪个差值
      ↓
matched experiment + controls
      ↓
held-out measurement + uncertainty
      ↓
claim：只说证据真正支持的那一层
```

## 第一层：先把 research question 写成可被实验回答的句子

### 🪜 台阶 1：主题不是 research question

“研究偏振法向估计”只是主题；“加入 PA 表征是否有效”仍然太宽。一个可检验的问题至少要固定五件事：

$$
Q=(P, T, C, O, \Pi).
$$

其中：

- $P$（population）表示希望结论覆盖的样本总体，例如真实室内物体，而不是模拟方向场；
- $T$（treatment）表示引入的改变，例如用 PA feature 替换原 feature；
- $C$（control）表示对照系统；
- $O$（outcome）表示预先指定的指标；
- $\Pi$（protocol）表示数据划分、训练预算、选择规则和 evaluator。

于是问题可以写成：

> 在冻结的真实 HAMMER test split、相同 backbone / loss / training budget / evaluator 下，仅把 baseline feature 替换为 PA feature，是否降低 per-image normal MAngE，并且不提高困难子组的 harm rate？

这句话已经提前排除了“换数据、换损失、换评估器之后也更好”这种不可解释比较。

### 🪜 台阶 2：hypothesis 要说方向，也要说机制

一个弱 hypothesis 是：

> PA 会提高性能。

一个更可检验的 hypothesis 是：

> PA 编码显式保留 doubled-angle orientation，因此在 AoLP ambiguity 明显、RGB 纹理不足的像素上，应比同容量的普通 feature 降低 angular error；如果收益确实来自该信息，则打乱 PA 与 RGB 的配对关系后，收益应消失。

它包含三部分：

1. **intervention**：引入 PA；
2. **mechanism**：提供与方向相关的信息；
3. **falsifier**：shuffle 后若仍同样有效，原机制解释就受损。

好的 hypothesis 不只是预测“会上升”，还告诉你什么结果会让自己难堪。

## 第二层：estimand 是“你真正想估计的差”

### 🪜 台阶 3：从两个 potential outcomes 开始

对第 $i$ 个 evaluation unit，定义：

- $Y_i(1)$：使用 proposed treatment 时的结果；
- $Y_i(0)$：不使用 proposed treatment、其余保持匹配时的结果。

若 outcome 是 error，个体处理效应可写为

$$
\tau_i=Y_i(1)-Y_i(0).
$$

$\tau_i<0$ 表示 treatment 降低 error。总体平均效应是

$$
\tau=\mathbb E_{i\sim P}[Y_i(1)-Y_i(0)].
$$

这就是一个 estimand：**在明确总体上，处理与对照的平均差。**

Hernán 与 Robins 的开放教材 [Causal Inference: What If](https://miguelhernan.org/whatifbook) 用 potential outcomes 系统说明了这种思路。深度学习实验不等同于医学随机试验，但“先定义想估计什么，再讨论怎样识别它”的顺序同样重要。

### 🪜 台阶 4：为什么不能直接看到 $\tau_i$

同一个训练过程不可能同时既加入模块又不加入模块；同一随机 seed 运行一次后，也不会自动告诉你“另一个世界”会怎样。我们实际观察到的是

$$
Y_i^{\text{obs}}
=A_iY_i(1)+(1-A_i)Y_i(0),
$$

其中 $A_i\in\{0,1\}$ 表示该 unit 接受 treatment 还是 control。

实验设计的任务，就是让 observed comparison 尽可能接近想要的 counterfactual comparison。对神经网络而言，最常见办法是：

- 同一 data split；
- 同一 preprocessing 与 valid mask；
- 同一 backbone、optimizer、steps 与 augmentation；
- 相同 seed 列表；
- 相同 checkpoint-selection rule；
- 同一 evaluator；
- 只改变待检验因素。

这就是 matched control 的核心。

## 第三层：baseline、matched control 与 ablation 不是同义词

### 🪜 台阶 5：baseline 回答“有没有一个合理参照物”

Baseline 可以有不同角色：

- **uninformed baseline**：常数、随机、copy-input，检查任务是否被轻易取巧；
- **classical baseline**：不依赖复杂学习的传统方法；
- **strong published baseline**：社区认可的方法；
- **internal base model**：你在其上增加模块的系统。

它们回答的是“你的完整系统相对哪些已有选择更好”。但若 proposed method 与 published baseline 使用不同训练数据、输入模态、分辨率或调参预算，差值是整个 system bundle 的差，而不是单个模块的效应。

### 🪜 台阶 6：matched control 回答“只改变这一件事会怎样”

假设完整模型多了一个 $1.8$M 参数的 fusion block。公平 control 不只是把 block 删除，因为性能变化可能来自容量。更强的设计可以包含：

| 组别 | 信号 | 参数量 / FLOPs | 训练预算 | 能回答什么 |
|---|---:|---:|---:|---|
| Base | 无 PA | 原始 | 相同 | 系统起点 |
| Capacity control | 无 PA，加入同容量 generic block | 匹配 | 相同 | 收益是否只是容量 |
| Proposed | PA + fusion | 匹配 | 相同 | 完整处理效应 |
| Shuffled PA | 错配 PA + fusion | 匹配 | 相同 | 是否真依赖正确配对信息 |

若 Proposed 胜过 Base，却没有胜过 Capacity control，只能说“更大模型更好”，不能把收益归因于 PA 信息。

### 🪜 台阶 7：ablation 回答“完整系统的哪部分对结果必要”

设完整方法包含模块 $A$、$B$ 与 loss $C$。常见 remove-one ablation 为：

$$
\Delta_A=M(A+B+C)-M(B+C).
$$

但它不是独立的“$A$ 的固有效果”，因为模块可能交互。若存在 synergy：

$$
M(A+B)-M(\varnothing)
\neq
[M(A)-M(\varnothing)]+[M(B)-M(\varnothing)].
$$

因此最好至少报告小型 factorial table：Base、A only、B only、A+B。这样可区分单独贡献与 interaction。Ablation 支持“组件对当前系统是否重要”，却不自动证明设计动机或物理机制为真。

## 第四层：negative control 专门寻找“本不该有效却有效”的信号

### 🪜 台阶 8：为什么 positive improvement 不够

如果数据 pipeline 中存在 scene ID 泄漏，一个完全不含物理信息的输入也可能提高 test score。Negative control 的思想是：构造按理论不应产生目标效应的处理或结果。

CV 里常用的 negative controls 包括：

- **condition shuffle**：保留边缘分布与张量尺寸，破坏样本对应关系；
- **random feature**：匹配 channel 数与统计尺度，但不含语义；
- **zero / constant feature**：检查网络是否仅从新增结构获益；
- **irrelevant outcome**：如果方法声称只改善 normal orientation，不应同时“神奇”预测无关的随机标签；
- **frozen wrong transform**：故意使用已知错误的几何对应，检查 evaluator 或 split 是否泄漏。

Negative control 不负责证明方法有效；它负责发现“即使机制不存在，也能跑出提升”的替代解释。

一个容易犯的错是只做 zero ablation。把 feature 置零可能制造训练从未见过的 out-of-distribution activation，因此性能骤降既可能说明 feature 内容重要，也可能只说明 zero 是异常输入。更稳妥的是同时比较 zero、mean、noise 与 cross-sample shuffle。

## 第五层：held-out evaluation 保护的是结论，不只是一份数据

### 🪜 台阶 9：validation 与 test 为什么必须分工

设你尝试了 $K$ 个配置，并选择 validation 最优者：

$$
k^*=\arg\min_{k\in\{1,\ldots,K\}}\hat R_{\text{val}}(k).
$$

这时 validation score 已参与 selection，往往对该配置乐观。若再根据 test score 修改 loss、挑 epoch、调 threshold 或决定数据过滤规则，test 也变成了 development set。

正确分工是：

```text
train：拟合参数
validation：选 architecture / hyperparameter / checkpoint
test：方案冻结后，只估计最终 generalization
```

“只看 test、不反向传播”并不等于 held-out。只要 test 结果影响下一轮选择，信息就进入了开发过程。

### 🪜 台阶 10：模型选择规则也属于方法

比较两个系统时，不能给 Proposed 选 best-of-50 checkpoint，却给 Baseline 用 last checkpoint。应预先固定：

- metric 与优化方向；
- checkpoint frequency；
- early-stopping patience；
- tie-breaking rule；
- seed aggregation；
- 是否允许 target-set tuning。

这也是为什么实验记录不能只保存最终权重，还要保存 config、commit、environment、split hash、selected epoch 与 selection metric。ACM 的 [Artifact Review and Badging](https://www.acm.org/publications/policies/artifact-review-and-badging-current) 把 artifacts 是否完整、可运行、可审计与结果是否被独立验证分开；“代码能启动”与“论文主张可复现”不是一回事。

## 第六层：随机性与 uncertainty——不要让单个 seed 扮演总体规律

### 🪜 台阶 11：用 paired difference 消掉共同波动

假设使用相同的 $S$ 个 seeds，记 Proposed 与 Control 的 test error 为 $Y_s(1)$ 与 $Y_s(0)$。定义 paired difference：

$$
d_s=Y_s(1)-Y_s(0).
$$

估计平均差：

$$
\bar d=\frac1S\sum_{s=1}^{S}d_s.
$$

样本标准差为

$$
s_d=\sqrt{\frac1{S-1}\sum_{s=1}^{S}(d_s-\bar d)^2},
$$

标准误差为

$$
\mathrm{SE}(\bar d)=\frac{s_d}{\sqrt S}.
$$

若 seeds 可近似视为独立重复，粗略的 95% interval 可写为

$$
\bar d\pm t_{0.975,S-1}\frac{s_d}{\sqrt S}.
$$

这里 interval 衡量的是你所定义重复过程下的估计不确定性，不是“模型对所有现实场景有效”的概率证明。三个 seeds 也不会覆盖 dataset shift、label error 或 evaluator bias。

### 🪜 台阶 12：evaluation unit 决定统计结论

像素通常高度相关，不能把一百万像素当成一百万独立样本来制造极小 p-value。根据 claim 选择 unit：

- 若结论针对图像，按 image 聚合；
- 若同一物体有多帧，可能应按 object / sequence bootstrap；
- 若要声称跨数据集有效，dataset 才是更高层 unit；
- seed variation 与 sample variation 是两类 uncertainty，应分别报告。

统计方法不能补救错误的实验单位。

## 第七层：从结果到 causal claim 有一架梯子

可以把论文表述分成五层：

1. **Descriptive**：在协议 $\Pi$ 下，模型 A 的指标为 12.3；
2. **Comparative**：A 在同一 test set 上优于 B；
3. **Robust comparative**：差异跨 seeds / subsets 稳定，并有 uncertainty；
4. **Mechanistic**：matched control、ablation 与 negative control 共同支持某机制；
5. **Causal / general claim**：在清楚假设与覆盖范围下，该 intervention 导致目标总体上的改善。

常见越级是从第 2 层直接写到第 5 层：

> “Ours 比 Baseline 高 1.2，所以所提 physical prior 有效且提升了泛化。”

更诚实的写法是：

> “在冻结协议与匹配容量下，正确配对的 PA condition 相对 capacity control 降低了 held-out error；shuffle control 未出现同类收益。这支持收益依赖 paired PA information，但跨传感器与跨域泛化仍需独立数据验证。”

边界不是示弱，而是让 claim 精确落在证据上。

## 🧪 最小可运行代码：confounded comparison 与 matched estimate 差多少

下面构造两个 scene groups。困难组基础 error 更高，而且 Proposed 恰好多评估了容易组。直接比较总体均值会把 composition difference 错算成方法收益；在每个 group 内配对后再按共同权重聚合，才接近真实 treatment effect。

```python
import numpy as np

rng = np.random.default_rng(27)

# Easy / hard groups have different baseline error.
n_easy, n_hard = 80, 20
base_easy = rng.normal(10.0, 1.0, n_easy)
base_hard = rng.normal(20.0, 1.5, n_hard)

# True intervention lowers error by about 1 degree in both groups.
prop_easy = base_easy - 1.0 + rng.normal(0, 0.25, n_easy)
prop_hard = base_hard - 1.0 + rng.normal(0, 0.25, n_hard)

# Bad comparison: proposed uses mostly easy cases, control mostly hard cases.
bad_proposed = np.r_[prop_easy[:70], prop_hard[:10]]
bad_control = np.r_[base_easy[:20], base_hard]
naive_delta = bad_proposed.mean() - bad_control.mean()

# Matched comparison: same samples, paired difference.
paired_delta = np.r_[prop_easy - base_easy, prop_hard - base_hard]
mean_delta = paired_delta.mean()
se = paired_delta.std(ddof=1) / np.sqrt(paired_delta.size)

# Negative control: same extra branch, but feed an irrelevant condition.
# It keeps compute/noise comparable and should not create the target benefit.
negative_easy = base_easy + rng.normal(0, 0.25, n_easy)
negative_delta = (negative_easy - base_easy).mean()

print(f"naive unmatched delta: {naive_delta:.3f} deg")
print(f"matched paired delta: {mean_delta:.3f} ± {1.96*se:.3f} deg")
print(f"irrelevant-condition control: {negative_delta:.3f} deg")
```

重点不是记住 `1.96`，而是看到：**先定义共同样本与比较协议，再谈统计汇总。** 如果 treatment/control 连 evaluation population 都不同，后面的显著性检验只会精确地回答错误问题。

## 🔬 与你的 CVPR / 偏振工作有什么连接

### 1. 把“系统比较”与“组件归因”分成两张表

- SOTA table 可以允许不同方法保留其原始推理流程，但必须标注输入、监督、训练数据与 evaluator 差异；
- mechanism table 必须用同一代码基、相同预算和同一 evaluator，只交换 PA、R 或 fusion component。

第一张表回答“完整系统处于什么位置”；第二张表回答“你的设计为什么有效”。

### 2. 模拟、GT-derived input 与真实 RGB 不属于同一 population

在 GT-derived noisy direction field 上的提升，只估计模拟 input population 中的效应；它不能直接成为真实 RGB pipeline 的 causal evidence。模拟实验适合验证上限、机制与 failure mode，真实 held-out 数据负责外部有效性。

### 3. 固定 SfP 替换是 downstream measurement，不是 generation metric

若用固定 SfP evaluator 比较生成的偏振图，normal MAngE 衡量的是“生成输出经过该固定下游系统后的 utility”。它不能替代 generation fidelity，也不能自动分离生成器与 SfP evaluator 的交互。

### 4. Negative result 也在收紧证据边界

若 PA expansion、某个 gate 或 extra supervision 没有改善，保留它有两个价值：

- 排除“更多 PA 通道 / 更多监督自然更好”的简单解释；
- 为下一轮设计指出缺口在 representation、optimization 还是 data support。

删掉 adverse result 会让论文故事更顺，却让研究判断更差。

## 🎤 面试角度：七个高频追问

### Q1：baseline 与 control 有什么区别？

Baseline 是性能参照物；control 是为了隔离某个解释而设计的对照。一个强 published baseline 未必与 proposed method 匹配，不能单独用于组件归因。

### Q2：什么是 estimand？

Estimand 是希望从实验中估计的目标量，例如“在固定协议与真实 test population 上，仅替换 feature 后的平均 per-image MAngE 差”。它先于 estimator 与代码。

### Q3：ablation 能证明模块机制吗？

Remove-one ablation 说明组件对当前组合是否重要；若容量、优化与交互没有控制，它不能独自证明收益来自声称的机制。

### Q4：negative control 的价值是什么？

它构造理论上不该产生目标效应的条件，用来暴露泄漏、容量、错误匹配或 evaluator artifact。若 negative control 也提高，原因果解释就不可信。

### Q5：为什么 test set 只看不训练仍可能泄漏？

因为只要 test 结果影响 architecture、threshold、checkpoint 或数据清洗，test information 就参与了 selection，最终数字会对这套反复决策乐观。

### Q6：为什么报告 mean ± std 仍可能不够？

必须说明 variation 来自 seeds、images、objects 还是 datasets；不同 unit 回答不同 uncertainty。还要配合 paired design、effect size、subgroup 与 harm analysis。

### Q7：怎样把 claim 写得既强又不越界？

明确 population、intervention、control、outcome 与 protocol；先报告 observed effect，再说明 controls 排除了哪些替代解释，最后列出尚未覆盖的 domain。

## 🧾 一页实验设计模板

```text
Research question:
  在 [population] 上，[intervention] 相对 [control]
  是否改善 [primary outcome]，且不恶化 [safety/subgroup outcome]？

Hypothesis + mechanism:
  因为 [mechanism]，预期 [directional result]；
  若 [negative control] 仍有效，则该解释受损。

Estimand:
  E[Y(1) - Y(0)]，evaluation unit = [...]

Frozen protocol:
  data split / mask / evaluator / seeds / budget / selection rule

Evidence table:
  uninformed baseline / strong baseline / matched capacity control /
  component ablations / negative control / held-out result

Uncertainty:
  paired effect + interval；另报 seed / sample / subgroup variation

Claim boundary:
  已支持什么；未支持跨哪些 dataset / sensor / supervision setting
```

CVPR 2026 的官方作者指南新增了 experimental compute reporting initiative，也鼓励随 supplementary 提交代码以帮助审查。[CVPR 2026 Author Guidelines](https://cvpr.thecvf.com/Conferences/2026/AuthorGuidelines) 这类要求背后的共同方向是：结果不仅要高，还要让训练代价、协议与证据能够被审计。

## 一句话总结

实验设计的核心不是把表格填满，而是让每个比较只承担它能承担的证明责任：research question 固定对象，hypothesis 给出机制与可证伪预测，estimand 定义真正要估计的差，matched control 隔离变量，ablation 分解系统，negative control 搜索伪解释，held-out evaluation 阻断选择泄漏，uncertainty 则说明结果有多稳定。只有这些环节连起来，指标提升才从 observation 变成可辩护的 evidence。
