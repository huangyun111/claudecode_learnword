## 🧭 开篇：排行榜高了 0.1°，为什么还不能按下“部署”按钮

假设一个 surface-normal 模型的平均角误差从 $12.0^\circ$ 降到 $11.9^\circ$。这个数字可能对应完全不同的现实：

- 大多数图都稳定改善一点；
- 容易图改善很多，关键困难场景反而恶化；
- 只在某个 checkpoint、mask 或后处理下出现；
- 改善真实但推理时间翻倍；
- 差值小于标注噪声、跨 seed 波动或业务容忍区间。

所以要分开四个问题：

```text
metric：怎样把误差压成数字？
effect：新方法相对 control 改了多少？
decision：这个变化是否足以改变行动？
record：别人怎样追溯、重算并质疑这个结论？
```

## 第一层：metric 是测量规则，不是研究目标本身

### 🪜 台阶 1：从单样本误差到汇总指标

设测试集有 $N$ 个独立 evaluation units。第 $i$ 个 unit 上，control 的误差为 $c_i$，proposed 的误差为 $p_i$。若误差越低越好，常见平均指标是

$$
\bar c=\frac1N\sum_{i=1}^{N}c_i,
\qquad
\bar p=\frac1N\sum_{i=1}^{N}p_i.
$$

定义 paired effect：

$$
d_i=p_i-c_i,
\qquad
\bar d=\frac1N\sum_{i=1}^{N}d_i=\bar p-\bar c.
$$

这里 $d_i<0$ 表示改善，$\bar d$ 是 **effect size 的原始单位表达**。例如 $\bar d=-0.4^\circ$ 比“提升 3.2%”更容易解释，因为它保留了任务单位。

相对改善率可以辅助阅读：

$$
r=-\frac{\bar d}{\bar c}\times100\%.
$$

但当 baseline 接近 0、不同数据集量纲不同，或分母很小时，百分比会显得夸张。最好同时报告 control、proposed、绝对差值和相对差值。

### 🪜 台阶 2：统计可分辨不等于现实上重要

样本很多时，极小差异也可能得到很窄的 confidence interval；样本很少时，现实上重要的改善也可能暂时不精确。于是要在看结果前定义 **minimum practically important difference**，记为 $\Delta_{\min}>0$。

若误差越低越好，则“值得采用”的目标不是仅仅 $\bar d<0$，而是

$$
\bar d\le -\Delta_{\min}.
$$

$\Delta_{\min}$ 不能由作者看完结果后随手选。它应来自任务代价、传感器精度、标注一致性、下游敏感度、算力预算或用户容忍度。例如：normal error 降低多少才会让 downstream reconstruction 真正变化？延迟增加 30 ms 是否会破坏实时要求？

### 🪜 台阶 3：把 interval 变成决策，而不是装饰

设 paired effect 的 95% interval 为 $[L,U]$，仍以负数为改善：

```text
U < -Δ_min          → 整个区间都达到实用门槛，证据支持采用
L < -Δ_min ≤ U < 0  → 大概率有改善，但是否“够用”仍不确定
L < 0 < U           → 连改善方向都不稳定，需要更多证据
0 ≤ L               → 当前证据不支持优于 control
```

这不是把决策机械交给一个区间。它迫使我们预先写清：什么变化能改变行动，以及不确定性跨过了哪些行动边界。

## 第二层：一个决策通常有多项代价

模型选择不是只最小化 accuracy error。设一次部署决策的总损失为

$$
J = w_eE + w_hH + w_tT + w_mM.
$$

各符号含义如下：

- $E$：主要预测误差；
- $H$：harm，例如严重恶化比例或 worst-group 风险；
- $T$：时间与算力成本；
- $M$：维护成本，例如额外模型、依赖和数据管线；
- $w_e,w_h,w_t,w_m$：由使用情境确定的权重。

这个式子不是要求所有论文都发明一个加权总分，而是提醒：**若最终决策依赖四项，就不能只展示第一项。** 在高风险任务中，某些约束甚至应写成 hard constraint，例如 harm rate 不得超过阈值、P95 latency 必须小于预算，而不是用平均精度抵消。

## 第三层：error taxonomy 让“失败案例”变成可检验问题

### 🪜 台阶 4：不要只收藏最难看的图片

一张 bad case 只能证明“存在失败”，不能说明失败来自哪里。更有用的 error taxonomy 至少包含四层：

| 层级 | 典型问题 | 可记录变量 | 下一步检验 |
|---|---|---|---|
| 数据 | domain shift、低信噪比、标签错 | scene、sensor、DoLP、材质、标注版本 | 分组评估、复核标签 |
| 表征 | 输入缺少可辨识信息、几何有多解 | 遮挡、反射类型、边界、ambiguity | oracle cue、额外视角 |
| 模型 | capacity、optimization、shortcut | seed、loss、gate、激活、梯度 | matched-capacity、shuffle control |
| 评估 | mask、alignment、单位或后处理不一致 | evaluator hash、mask version、resize | 锁定 evaluator 后重算 |
| 系统 | 内存、吞吐、依赖和数值漂移 | device、precision、latency、commit | 环境复现、端到端 profiling |

taxonomy 的目标不是给每次失败贴一个永远正确的标签，而是生成可反驳的假设。比如“低 DoLP 导致 AoLP cue 不稳定”应进一步预测：错误随 DoLP 降低而上升；若换成 shuffled cue 结果不变，则当前模型可能根本没用到该 cue。

### 🪜 台阶 5：failure analysis 要保留分母

若只展示 10 个失败例，读者不知道它们来自 20 张还是 2000 张。对第 $k$ 类失败，至少记录

$$
n_k,\qquad
\text{rate}_k=\frac{n_k}{N},\qquad
\bar d_k,\qquad
h_k=\frac1{n_k}\sum_{i\in G_k}\mathbb 1(d_i>0).
$$

$n_k$ 是数量，$\text{rate}_k$ 是占比，$\bar d_k$ 是该类平均变化，$h_k$ 是 proposed 在该类上受损的比例。这样 failure gallery 才能与总体结果接起来。

## 第四层：一次实验必须有稳定身份

“我记得这个文件夹是最终版”不是实验记录。一个 run 最少要绑定以下六层：

```text
claim      这次运行试图检验什么
code       git commit / dirty diff / entry command
data       dataset version / split / label provenance / hashes
config     model / loss / seed / precision / training budget
selection  checkpoint 与 threshold 怎样选择
evaluation evaluator / mask / alignment / metric aggregation
```

可以把 run identity 写成

$$
R=(C,D,S,H,E),
$$

其中 $C$ 是 code revision，$D$ 是 data revision，$S$ 是 split，$H$ 是 hyperparameters，$E$ 是 evaluator revision。任一项改变，就不应悄悄沿用同一个结果身份。

训练日志还应区分三种状态：

- **planned**：准备运行，尚无结果；
- **running / partial**：已有中间产物，但不能冒充完成；
- **verified**：目标产物、评估输出和 provenance 已检查。

“作业启动成功”只属于第二类，不等于实验结论完成。

## 🧪 最小可运行代码：从 paired effect 到可追溯 manifest

下面只用 Python 标准库。它计算 paired effect、harm rate、bootstrap interval，并把输入数字、决策门槛与 evaluator 指纹写入 JSON；同一记录以后可以重新检查，而不是只剩一行手抄均值。

```python
import hashlib
import json
import random
import statistics

control = [12.4, 10.8, 14.1, 9.7, 13.0, 11.6, 15.2, 10.1]
proposed = [11.8, 10.5, 13.6, 9.9, 12.4, 11.0, 15.4, 9.8]
assert len(control) == len(proposed)

d = [p - c for p, c in zip(proposed, control)]  # negative is better
effect = statistics.fmean(d)
harm_rate = statistics.fmean(x > 0 for x in d)

rng = random.Random(7)
boot = []
for _ in range(5000):
    sample = [d[rng.randrange(len(d))] for _ in d]
    boot.append(statistics.fmean(sample))
boot.sort()
interval = [boot[int(0.025 * len(boot))],
            boot[int(0.975 * len(boot))]]

evaluator_text = "normal_mange_v3|mask=valid_gt|per_image_mean"
record = {
    "metric": "mean angular error (deg; lower is better)",
    "control": control,
    "proposed": proposed,
    "paired_effect_deg": effect,
    "bootstrap_95_deg": interval,
    "harm_rate": harm_rate,
    "minimum_practical_improvement_deg": 0.3,
    "decision": (
        "practically_supported" if interval[1] < -0.3
        else "direction_supported_but_practical_uncertain"
        if interval[1] < 0
        else "improvement_direction_uncertain"
    ),
    "evaluator_sha256": hashlib.sha256(
        evaluator_text.encode("utf-8")
    ).hexdigest(),
}

print(json.dumps(record, ensure_ascii=False, indent=2))
```

注意：示例中的 hash 只演示“给 evaluator 身份”；正式实验应对真实脚本、配置、manifest 或归档文件计算 hash，并记录文件路径与生成方式。

## 第五层：artifact package 不是“上传一个 checkpoint”

一套能支持论文主张的 artifact，最好从外到内分层：

1. **README / claim map**：每个表格、图和主张由哪条命令产生；
2. **environment**：依赖、CUDA/driver、硬件与容器或 lock file；
3. **data card / manifest**：数据来源、许可、split、排除规则、hash；
4. **train / infer configs**：seed、预算、checkpoint-selection rule；
5. **evaluation**：固定 evaluator、mask、alignment 和 aggregation；
6. **outputs**：machine-readable metrics、per-unit errors、日志与必要 checkpoint；
7. **limitations**：未运行的格子、已知失败和不可公开资产的替代审计方式。

“Artifacts Available”“Artifacts Evaluated”“Results Reproduced”也不是同义词：文件可下载，不代表能运行；能运行，不代表复得主要结论。artifact 的强度应与主张需要的复查深度匹配。

## 🔗 与你的 CVPR / 偏振工作有什么连接

1. **指标身份**：MAngE、生成 fidelity 与 fixed-SfP downstream normal metric 回答不同问题，不能互相代替。
2. **数据身份**：corrected HAMMER、self-built data、GT-derived simulation 要分表、分 manifest，避免把不同 population 汇成一个数字。
3. **协议身份**：固定 label layout、mask、evaluator、resize/alignment 与 checkpoint selection；仅改模块时保留 matched control。
4. **失败分类**：按低 DoLP、反射类型、边界、材质、scene 与 sensor 记录 per-image delta 和 harm，而不只挑视觉上最明显的样例。
5. **交付闭环**：训练、推理、评估、表格和图都指向 commit、config、日志与结果 JSON；未测项明确写 pending，不用占位数字填满表格。

## 🎤 面试角度

**Q：统计显著与 practical significance 有什么区别？** 统计显著主要问观察到的差异是否容易由既定随机机制解释；practical significance 问差异是否大到足以改变使用决策。大样本可以让微小差异很精确，但不自动让它有价值。

**Q：为什么失败案例不能只放几张图？** 因为选图没有分母，也不能估计失败频率。应先定义 error taxonomy，报告每类样本量、effect 与 harm rate，再用代表性样例解释机制假设。

**Q：可复现 artifact 最关键的是什么？** 不是文件越多越好，而是主张到数据、代码、配置、选择规则、evaluator 和输出之间存在可执行、可校验的映射。

## 一句话总结

一项结果真正可用，需要四次过关：metric 明确测量什么；paired effect 说明相对 control 改了多少；practical threshold、harm 与成本决定是否值得行动；最后由稳定的 run identity、error taxonomy 和 artifact package 保证结论能够被追溯、重算和推翻。数字不只要更好，还要足够重要，并且说得清它从哪里来。
