## ⏮ 上篇回顾（30 秒）

上一篇把 Bayesian prediction 写成对参数 posterior 的积分：

$$
p(y^\star\mid x^\star,\mathcal D)
=
\int p(y^\star\mid x^\star,\theta)
p(\theta\mid\mathcal D)\,d\theta.
$$

MC Dropout 与 Deep Ensembles 都在近似“多组合理参数的预测”。若它们彼此分歧，就得到 epistemic uncertainty 的一个估计。

今天到期复习只问一句：

> 多个模型意见一致，是否就证明它们是对的？

不一定。它们可能共享同一数据偏差、架构偏差或伪相关，因此会“整齐地犯错”。所以：

```text
uncertainty：模型产生的风险信号
reliability：这个信号与真实错误之间的经验对应关系
calibration：把信号刻度调整到可解释的概率或风险尺度
```

## 🎯 主菜：从“有一个 confidence 数”到“这个数能负责”

先看 1000 个分类预测。模型对每个样本都给出 `confidence = 0.9`。

- 如果大约 900 个预测正确，它在这一档上是 calibrated；
- 如果只有 650 个正确，它是 overconfident；
- 如果有 980 个正确，它是 underconfident。

关键不是某一个样本的 `0.9` 必须“90% 正确”——单次事件没有 90% 次——而是把许多相似置信度的样本放在一起后，长期频率能否对上。

### 台阶 1：先把 accuracy、confidence 与 calibration 分开

对第 $i$ 个分类样本，设：

- $x_i$：输入；
- $y_i$：真实类别；
- $\hat y_i$：模型预测类别；
- $c_i\in[0,1]$：模型对 $\hat y_i$ 的 confidence；
- $a_i=\mathbf 1(\hat y_i=y_i)$：预测正确时为 1，否则为 0。

accuracy 是：

$$
\mathrm{Accuracy}
=
\frac{1}{N}\sum_{i=1}^{N}a_i.
$$

它只回答总体上对了多少，却不检查 confidence 的刻度。

理想 calibration 要求：

$$
\mathbb P(\hat Y=Y\mid C=c)=c.
$$

意思是：在所有 confidence 接近 $c$ 的预测里，正确比例也应接近 $c$。

因此两个模型可以 accuracy 相同，却可靠度不同。模型 A 的 0.9 约对应 90% 正确；模型 B 不论对错都报 0.99。它们可能答对同样多，但 B 的 confidence 不能直接用于安全决策。

### 台阶 2：分类 confidence 是怎样从 logits 得到的

设网络对 $K$ 个类别输出 logits：

$$
z(x)=[z_1(x),z_2(x),\ldots,z_K(x)].
$$

logit 是 softmax 前的任意实数分数。softmax 把它转成概率：

$$
p_k(x)
=
\frac{\exp(z_k(x))}
{\sum_{j=1}^{K}\exp(z_j(x))}.
$$

预测类别与常用 confidence 分别为：

$$
\hat y=\arg\max_k p_k(x),
\qquad
c=\max_k p_k(x).
$$

问题在于：softmax 归一化只保证 $\sum_k p_k=1$，不保证这些数已经匹配现实中的正确频率。只要 logits 的相对差距很大，softmax 就会给出接近 1 的最大概率，即使网络面对的是分布外输入。

> softmax probability 是模型内部的归一化分数，不会自动成为经过验证的真实正确概率。

### 台阶 3：用 reliability diagram 与 ECE 检查刻度

把 $[0,1]$ 分成 $M$ 个 confidence 区间。第 $m$ 个 bin 的样本集合记为：

$$
B_m=\{i:c_i\in I_m\}.
$$

在这个 bin 内，平均 confidence 是：

$$
\mathrm{conf}(B_m)
=
\frac{1}{|B_m|}
\sum_{i\in B_m}c_i,
$$

真实 accuracy 是：

$$
\mathrm{acc}(B_m)
=
\frac{1}{|B_m|}
\sum_{i\in B_m}a_i.
$$

reliability diagram 把横轴设为 $\mathrm{conf}(B_m)$，纵轴设为 $\mathrm{acc}(B_m)$。点越接近对角线 $y=x$，这一档越 calibrated。

常见汇总指标 Expected Calibration Error（ECE）为：

$$
\mathrm{ECE}
=
\sum_{m=1}^{M}
\frac{|B_m|}{N}
\left|
\mathrm{acc}(B_m)-\mathrm{conf}(B_m)
\right|.
$$

每个 bin 的偏差按样本比例加权，再求和。

但 ECE 不是绝对真理：

- bin 数和边界改变，数值会改变；
- 小样本 bin 的估计噪声很大；
- ECE 只看分箱后的平均差，可能掩盖类间或空间差异；
- calibration 好不等于 accuracy 高——一个很差的模型也可以诚实地报告低 confidence。

所以至少要同时报告 task metric、NLL 或 Brier score、reliability diagram 与 ECE，而不是只挑一个漂亮数字。

### 台阶 4：Temperature Scaling 为什么能校准而不改变分类结果

Temperature Scaling 在冻结模型后，用一个正数 $T$ 缩放 logits：

$$
p_k^{(T)}(x)
=
\frac{\exp(z_k(x)/T)}
{\sum_{j=1}^{K}\exp(z_j(x)/T)}.
$$

- $T>1$：logits 差距被压小，softmax 更平缓，confidence 降低；
- $0<T<1$：logits 差距被放大，softmax 更尖锐，confidence 升高；
- $T=1$：保持原模型。

因为所有 logits 都除以同一个正数，类别排序不变：

$$
\arg\max_k z_k
=
\arg\max_k \frac{z_k}{T}.
$$

所以 Temperature Scaling 通常不改变 accuracy，只调整概率刻度。

在独立 calibration set

$$
\mathcal D_{\mathrm{cal}}
=
\{(x_i,y_i)\}_{i=1}^{N_{\mathrm{cal}}}
$$

上选择 $T$，最小化 negative log-likelihood：

$$
T^\star
=
\arg\min_{T>0}
\left[
-\sum_{i=1}^{N_{\mathrm{cal}}}
\log p_{y_i}^{(T)}(x_i)
\right].
$$

为什么不能在 test set 上选 $T$？因为 test labels 一旦参与调参，最后的测试就不再是独立评估。正确顺序是：

```text
train set：学习模型参数
validation / calibration set：学习 T 或 reliability mapping
test set：只做一次最终评估
```

Temperature Scaling 很稳健，但表达能力有限：一个全局 $T$ 只能修正整体过尖或过平，不能自动解决不同类别、材质、空间区域或 OOD 条件下的局部失准。

### 台阶 5：dense regression 没有 softmax，reliability 应怎样定义

在深度、法向、恢复或偏振表征任务中，模型常输出连续预测 $\hat y_i$ 与 uncertainty score $u_i$。此时没有天然的“预测正确概率”，必须先明确事件或损失。

一种做法是定义容差事件：

$$
a_i(\tau)
=
\mathbf 1\bigl(\ell(\hat y_i,y_i)\le\tau\bigr),
$$

其中：

- $\ell(\hat y_i,y_i)$ 是单样本或单像素误差；
- $\tau$ 是任务允许的误差阈值；
- $a_i(\tau)=1$ 表示预测在容差内。

再训练或校准一个 reliability：

$$
r_i
\approx
\mathbb P\bigl(\ell(\hat y_i,y_i)\le\tau\mid x_i\bigr).
$$

另一种做法不强求概率解释，只要求 uncertainty 能正确排序风险：$u_i$ 越大，预期误差越大。它适合 selective prediction——模型只处理最可信的一部分样本。

设保留集合为：

$$
S_q=\{i:u_i\le q\},
$$

其中阈值 $q$ 保留低 uncertainty 的预测。coverage 与 risk 分别为：

$$
\mathrm{Coverage}(q)
=
\frac{|S_q|}{N},
$$

$$
\mathrm{Risk}(q)
=
\frac{1}{|S_q|}
\sum_{i\in S_q}\ell(\hat y_i,y_i).
$$

若 uncertainty 有用，从 100% coverage 逐步拒绝最不可靠样本时，risk 应稳定下降。把不同 coverage 下的 risk 画出来，就得到 risk-coverage curve；曲线下面积 AURC 越小通常越好。

这里有一个容易忽略的区别：

```text
calibration：0.8 是否真的对应约 80% 的成功频率
ranking：模型能否把更危险的样本排到前面
```

一个分数可能排序很好，但数值没概率意义；也可能总体 ECE 不错，却无法有效筛出最危险区域。两者都要测。

### 台阶 6：reliability head 应该学什么，怎样避免走捷径

假设 base model 输出预测 $\hat y$，我们还能构造特征：

$$
g(x)=
[\text{ensemble variance},\text{DoLP},\text{intensity},
\text{physics residual},\text{feature statistics}].
$$

reliability head 输出：

$$
r_\phi(x)=\sigma(h_\phi(g(x)))\in(0,1),
$$

其中 $\sigma$ 是 sigmoid，$h_\phi$ 是待学习网络。

若目标是预测误差是否小于阈值 $\tau$，标签可写为：

$$
t_i=\mathbf 1(\ell(\hat y_i,y_i)\le\tau),
$$

再用 binary cross-entropy：

$$
\mathcal L_{\mathrm{rel}}
=
-t_i\log r_i
-(1-t_i)\log(1-r_i).
$$

但必须防止三种捷径：

1. **数据泄漏**：用生成标签时见过的 test 信息训练 reliability head；
2. **只学场景频率**：把“暗区通常难”记成规律，却忽略某些暗区其实预测正确；
3. **共同错误**：base model 与 reliability head 共享偏差，导致错误区域仍然高置信。

因此要做按材质、亮度、DoLP、场景与 OOD 条件分层的 calibration / risk-coverage 检查，而不能只看全部像素混在一起的均值。

## 实现：最小 ECE、Temperature Scaling 与 Risk-Coverage

下面代码只依赖 NumPy。它先计算原始 confidence 的 ECE，再用 calibration split 网格搜索 temperature，最后演示 uncertainty 排序的 risk-coverage curve。

```python
import numpy as np


def softmax(logits):
    logits = logits - logits.max(axis=1, keepdims=True)
    exp_logits = np.exp(logits)
    return exp_logits / exp_logits.sum(axis=1, keepdims=True)


def nll(logits, labels, temperature=1.0):
    probs = softmax(logits / temperature)
    return -np.log(probs[np.arange(len(labels)), labels] + 1e-12).mean()


def ece(logits, labels, temperature=1.0, n_bins=10):
    probs = softmax(logits / temperature)
    pred = probs.argmax(axis=1)
    conf = probs.max(axis=1)
    correct = (pred == labels).astype(float)
    edges = np.linspace(0.0, 1.0, n_bins + 1)
    value = 0.0
    for left, right in zip(edges[:-1], edges[1:]):
        # Include confidence == 1.0 in the last bin.
        in_bin = (conf >= left) & (
            (conf < right) | ((right == 1.0) & (conf <= right))
        )
        if in_bin.any():
            value += in_bin.mean() * abs(
                correct[in_bin].mean() - conf[in_bin].mean()
            )
    return value


def risk_coverage(errors, uncertainty):
    # Keep low-uncertainty samples first.
    order = np.argsort(uncertainty)
    sorted_errors = errors[order]
    coverage = np.arange(1, len(errors) + 1) / len(errors)
    risk = np.cumsum(sorted_errors) / np.arange(1, len(errors) + 1)
    return coverage, risk


rng = np.random.default_rng(7)
n = 1000
labels = rng.integers(0, 3, size=n)

# Synthetic overconfident logits: correct signal plus excessive scale.
logits = rng.normal(size=(n, 3))
logits[np.arange(n), labels] += 1.2
logits *= 3.0

cal_logits, test_logits = logits[:500], logits[500:]
cal_labels, test_labels = labels[:500], labels[500:]

temperatures = np.linspace(0.5, 5.0, 181)
best_t = min(temperatures, key=lambda t: nll(cal_logits, cal_labels, t))

print("best temperature:", round(float(best_t), 3))
print("test ECE before:", round(ece(test_logits, test_labels), 4))
print("test ECE after :", round(ece(test_logits, test_labels, best_t), 4))

# Regression example: uncertainty should rank large absolute errors later.
errors = np.abs(rng.normal(size=200))
uncertainty = errors + 0.4 * rng.normal(size=200)
coverage, risk = risk_coverage(errors, uncertainty)
for target in (0.25, 0.50, 0.75, 1.00):
    idx = np.searchsorted(coverage, target)
    print(f"coverage={coverage[idx]:.2f}, risk={risk[idx]:.3f}")
```

这段代码是概念演示。真实项目应固定 calibration protocol，报告随机种子与置信区间，并避免用 test split 反复选择 temperature、阈值或 reliability 特征。

## 🔗 与我 CVPR 工作的连接

reliability-guided refinement 不是“多输出一张热力图”，而是一条可检验的控制链：

```text
输入与物理信号
-> base prediction
-> uncertainty / reliability estimation
-> 选择是否修、在哪里修、修多大
-> 检查 refinement 后是否真的降低风险
```

### 1. reliability 的监督目标要贴最终用途

如果 reliability 用于控制 refiner，就不应只预测 base error 大小，还应关心 refinement 的收益：

$$
\Delta\ell_i
=
\ell(\hat y_i^{\mathrm{base}},y_i)
-
\ell(\hat y_i^{\mathrm{refined}},y_i).
$$

$\Delta\ell_i>0$ 表示 refinement 改善，$\Delta\ell_i<0$ 表示反而伤害。gate 真正需要回答的可能是：

$$
\mathbb P(\Delta\ell_i>0\mid g_i),
$$

而不只是“这里 base error 大不大”。难区域不等于可修区域。

### 2. 用 reliability 控制残差幅度

可写成：

$$
\hat y_{\mathrm{final}}
=
\hat y_{\mathrm{base}}
+
r_i\,\Delta y_i,
\qquad 0\le r_i\le1.
$$

这里 $r_i$ 越大，越允许 refiner 修改。但必须与三个基线比较：

- 不使用 gate，所有位置都修；
- oracle gate，用真实 error / improvement 决定是否修；
- learned gate，只用推理时可获得的信号。

oracle 与 learned 之间的差距能告诉我们：瓶颈到底在 refiner 能力，还是 reliability 估计。

### 3. no-harm 不能只看全图平均

全图指标变好，仍可能掩盖“容易区域被破坏、困难区域略改善”。建议同时报告：

- base-correct 区域的退化率；
- 按 reliability 分位数的误差；
- risk-coverage / error-retention curve；
- in-distribution 与 OOD 材质、低 DoLP、暗区、饱和区的分层结果；
- reliability 与真实 error、真实 improvement 的相关和校准。

对角度量还要用周期正确的误差，例如 AoLP 的 $\pi$ 周期不能直接套普通绝对差。

## 一句话总结

> uncertainty 只是模型给出的风险信号，reliability 要求这个信号在独立数据上真的对应错误或成功频率。分类中可用 reliability diagram、ECE 与 Temperature Scaling 检查和修正概率刻度；密集回归中应先定义误差事件或风险，再用 risk-coverage 检查排序能力。用于 refinement 时，最重要的目标甚至不是“哪里错得大”，而是“哪里值得修、修后是否 no-harm”。

## 🔧 配菜·面试考点

1. **accuracy 高是否代表 calibration 好？** 不代表。accuracy 衡量答对比例，calibration 衡量 confidence 与真实正确频率是否一致。
2. **为什么 Temperature Scaling 通常不改变 accuracy？** 所有 logits 除以同一个正数不会改变类别排序，只会改变 softmax 的尖锐程度。
3. **ECE 有什么局限？** 它依赖分箱方案，可能掩盖类间和局部失准，也不能替代 accuracy、NLL 与 reliability diagram。
4. **selective prediction 中怎样判断 uncertainty 有用？** 按 uncertainty 从低到高保留样本；若 coverage 下降时 risk 明显下降，说明它能把危险预测排到后面。
5. **reliability-guided refiner 最容易犯什么概念错误？** 把“base error 大”直接当成“refinement 一定有益”。正确目标应验证可修性与 no-harm。
